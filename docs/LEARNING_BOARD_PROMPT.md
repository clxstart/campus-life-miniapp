## 一、你的角色和任务

你是一位有产品感的全栈工程师。这个项目里有一个校园生活小程序，现在要新增**学习专区**。

- 数据库：`campus_life`，账号 `root`，密码见项目里的 `backend/src/main/resources/application.yml`（打包版已脱敏为占位符，本地跑的时候填你自己的）
- 当前已注册 26 个页面，`app.json` 里**没有 tabBar**
- 项目里已经有一套成熟的页面、接口、样式约定。**动手前先浏览几个同类页面**（比如 `pages/activities/`、`pages/community/`、`pages/market-list/`），了解这个项目的代码风格后再写。

## 三、现状

现在首页有一张「学习专区」卡片，但它只是个入口，点进去只是论坛里按 `tag='学习'` 过滤的帖子列表——**没有独立页面，也没有分类**。

首页那张卡片的标题是「学习专区」，副标题「作业答疑 · 论文指导 · 学习好物」，下面三个小入口。点整张卡片应该进入学习专区。

## 四、我要什么（产品需求）

### 4.1 一个独立的学习专区页面

像「季节活动」那样，是**一整个独立页面**（有自己的导航栏、自己的内容区），不是某个页面里的一个标签。

页面里分 **5 个板块**：

| 板块 | 说明 |
|---|---|
| 代课互助 | 课程相关的互助信息 |
| 论文指导 | 选题、结构、格式、查重 |
| 就业实习 | 实习、校招、简历、面试 |
| 考研 | 院校、资料、经验、时间安排 |
| 考公 | 岗位、行测、申论 |

用户能在这 5 个板块之间切换，看各自的内容。

### 4.2 内容形态

学习专区里的内容是**用户发的帖子**。这一点很重要：它需要能**点赞、评论、点进详情页、看到作者和发布时间**。

项目里已经有完整的帖子能力（发布、点赞、评论、详情、浏览数）。希望学习专区能复用这套能力，而不是再实现一遍——具体怎么做到由你决定。

### 4.3 核心交互

- **浏览**：切换板块看列表，下拉刷新，上拉加载更多
- **发布**：页面里能发新帖，发的时候要能选发到哪个板块
- **进详情**：点任意一条进帖子详情
- **按校**：默认只看本校内容（项目是多学校架构，用户有「当前选中学校」的概念）

### 4.4 离线可用

项目有一个贯穿全局的设计：**后端挂了小程序也要能打开、能看到东西**，不能白屏。学习专区也要遵守。

## 五、硬约束（这些破坏了会出问题）

以下不是风格偏好，是项目既有的事实，违反了会破坏其它功能或现有测试：

1. **微信原生小程序**：每个页面必须有 `.js` `.wxml` `.wxss` `.json` 四件套，并在 `app.json` 的 `pages` 里注册
2. **后端统一返回格式**：`{code, msg, data}`，成功时 `code=0`
3. **读接口要兜底、写接口不能兜底**：读失败时前端回落本地数据（保证离线可用）；写失败必须把错误抛给用户，不能假装成功
4. **多学校隔离**：内容要按学校过滤。用户当前选中哪所学校由项目里已有的机制提供，别自己造一套
5. **小程序端零 npm 依赖**
6. **不要破坏现有功能**：论坛、季节活动、圈子、外卖、二手这些页面不能被改坏

## 六、验收标准（我怎么判断做完了）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 后端能编译 | Maven 编译成功 |
| 2 | 页面能打开 | 从首页「学习专区」卡片点进去，能看到独立页面 |
| 3 | 五个板块能切换 | 每个板块显示各自的内容 |
| 4 | 能看到内容 | 库里没有数据时也要能发帖，发完能看到 |
| 5 | 发帖能选板块 | 发的内容出现在对应板块里 |
| 6 | 能进详情 | 点一条内容能进详情页 |
| 7 | 按校生效 | 切到别的学校看不到本校内容 |
| 8 | 离线不白屏 | 后端停掉，页面仍能打开并有提示 |
| 9 | 分页正确 | 上拉加载不重复、不丢失 |
| 10 | 静态校验通过 | 项目自带 `python tests/validate_project.py` 输出 PASS |
| 11 | 现有功能没坏 | 论坛、季节活动等页面照常可用 |

## 七、边界（不要做的事）

- 不要重构论坛页 `pages/community`、季节活动页 `pages/activities` 等已有页面
- 不要改 `utils/api.js` 里已有函数的签名（有页面在调用）
- 不要改数据库连接配置
- 不要引入 npm 依赖
- 不要给学习专区另造一套点赞/评论体系——项目里已经有了
- 不要动首页那张学习专区卡片的事件绑定方式（卡片本身和里面三个小入口用的是不同事件类型，改了会重复触发）

## 八、你可以自由决定的

以下这些我不限制，你按自己的判断来，只要满足上面的需求：

- 数据怎么建模（新表还是复用现有结构）
- 接口怎么设计、字段怎么命名
- 页面内部怎么组织、组件怎么拆
- 样式细节（但请和项目现有视觉风格保持一致——浅色卡片、圆角、克制阴影）
- 板块的编码/枚举怎么定（只要前后端一致）
- 是否需要 tab 上显示数量、是否需要本校/全部切换等附加能力
