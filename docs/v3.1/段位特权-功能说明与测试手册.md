## 一、这个功能解决什么问题

**现状（读码核实）**

- 段位（第 4 份文档）只是标签，不给任何实际好处。用户冲段的唯一收益是"好看一点"。
- 圈子只能由管理端创建：`CircleController` 没有创建端点，用户侧没有任何入口；`circle` 表也没有 `creator_id`。
- 发帖一律走内容审核：`AuditService.initialStatus()` 返回 `passed` / `pending`（带图）/ `reviewing`（命中疑似），带图内容先进 `pending` 不可见。

**不做会怎样**

大表 B 的三条铁律第一条就是"特权 = 排序权重 / 系统额度 / 时间窗口"。特权缺席时，段位是纯装饰，用户没有持续做任务的理由；而这三项特权**平台成本≈0**（权重、白名单、一个入口），是性价比最高的一档。

## 二、前端页面与操作（小程序端 + Web 端）

> 通用规范见 `docs/v3.1/前端设计-双端总览.md`。三项特权落在三个已有页面 + 一个新页，Web 端只有圈子审核一处。

### 2.1 快速应答（白银）· `pages/jobs/jobs`（改造）

**结构**：列表第 1 页顶部插入最多 2 张岗位卡，卡片右上角 `.cp-tag` 徽标「优先推荐」；之后一条分隔文案 `—— 以下为其他岗位 ——`。

**操作步骤**

1. 白银及以上用户进入兼职列表 → 服务端在第 1 页返回 `priority=true` 的 2 条（同 `school_id` 优先）。
2. 用户点卡片 → 与普通岗位完全相同的详情页，**不做特殊处理**（避免"优先"变成"特权通道"）。
3. 翻到第 2 页 → 不再注入，顺序与原逻辑一致。

**状态与边界**

| 情况 | 表现 |
|---|---|
| 青铜 | 不注入，无徽标、无分隔文案 |
| 开关关闭 | 恢复原顺序 |
| 同校岗位不足 2 条 | 有几条插几条，不凑数 |
| 岗位总数 ≤2 | 不显示分隔文案 |

### 2.2 发帖免审（黄金）· `pages/publish/publish` 与 `pages/circle-publish`（改造）

**结构**：黄金用户发帖页标题下方多一行 `.cp-hint`：`你已享受发帖免审，发布后立即可见`。非黄金用户**不显示任何提示**（不制造落差）。

**操作步骤**

1. 填标题/正文/图片 → 点发布。
2. 黄金用户：接口返回即 `status=1`，跳回列表能立刻看到自己的帖子（带图同样立即显示）。
3. 若异步审核命中违规 → 帖子下架，站内通知：`你的帖子因违反社区规范已被下架`。

**状态与边界**

| 情况 | 表现 |
|---|---|
| 非黄金 | 走原审核流程（带图进 `pending`），页面无额外提示 |
| 开关关闭 | `post.fastlane.enabled=0` → 提示消失，黄金用户也走普通审核 |
| 审核命中 | 列表里帖子消失 + 站内通知（不弹窗打断） |

### 2.3 圈子创建权（黄金）· `pages/circles` 改造 + `pages/circle-create`（新页）

**入口**：圈子页右上角「+ 创建圈子」按钮。

| 用户状态 | 点击后 |
|---|---|
| 白银及以下 | `popup.toast('创建圈子需要黄金段位（成长值 200）', { tone: 'info' })`，不跳转 |
| 黄金，未建过 | 跳 `circle-create` |
| 黄金，已建 1 个 | 按钮变灰，文案 `你已创建 1 个圈子（上限 1）` |
| 开关关闭 | 按钮保留，点击提示 `圈子创建暂未开放` |

**`pages/circle-create` 页面结构**

| 区域 | 控件 | 校验 |
|---|---|---|
| 圈子名称 | 输入框 | 1–16 字，必填 |
| 分类 | `picker`（取 `/api/circles/categories`） | 必选 |
| 简介 | 多行输入 | ≤64 字，实时字数 |
| 封面 | 可选上传（复用现有图片上传） | jpg/png，≤2MB |
| 底部 | 主按钮「提交审核」 | 提交中 `disabled` |

**操作步骤**

1. 填写 → 提交 → `POST /api/circles`。
2. 成功 → `navigateBack` 回圈子页，toast `已提交，等待审核`；「我的圈子」里该圈显示灰色「审核中」角标。
3. 审核通过 → 角标变正常，用户成为圈主（可发圈内帖）。
4. 驳回 → 站内通知带原因，可修改后重新提交（仍占 1 个名额）。

### 2.4 Web 端 · `views/Circles.vue`（改造）

- 筛选区加「待审核」选项（`status=0`）。
- 表格加列：创建者、创建时间、状态。
- 操作：通过 / 驳回。驳回弹 `NoModal` 填原因（必填，≤100 字），提交后写通知给创建者。

### 2.5 文案清单

| 场景 | 文案 |
|---|---|
| 优先推荐徽标 | `优先推荐` |
| 分隔 | `—— 以下为其他岗位 ——` |
| 免审提示 | `你已享受发帖免审，发布后立即可见` |
| 段位不足 | `创建圈子需要黄金段位（成长值 200）` |
| 已达上限 | `你已创建 1 个圈子（上限 1）` |
| 提交成功 | `已提交，等待审核` |
| 被下架 | `你的帖子因违反社区规范已被下架` |

段位不够时按钮**不隐藏**，点击才提示——隐藏会让用户永远不知道有这条路径。

## 三、设计取舍

| 决策 | 选了 | 没选 | 为什么 |
|---|---|---|---|
| 快速应答作用面 | **只作用于兼职列表第 1 页**，注入最多 2 条 | 全站所有列表统一加权 | 多列表加权会让每个人看到的顺序都不同，翻页会"跳条"；只动第 1 页既有效果又不破坏分页稳定 |
| 快速应答排序依据 | 同 `school_id` 优先 + 原发布时间倒序 | 纯随机 | 同校岗位对用户才有意义；随机会让"优先"变成噪音 |
| 发帖免审范围 | **先发后审**：立即可见，仍异步过文本/图片审核 | 真正跳过审核 | 跳过审核违反 UGC 平台要求，且微信侧 `msg_sec_check` 是硬要求；先发后审既给了体验又守住底线 |
| 免审失败处理 | 审核命中即下架并把 `status` 改 0，写 `audit_log` | 只警告不隐藏 | 违规内容留在线上就是事故 |
| 建圈是否有审核 | 有，`status=0` 待审 | 直接上线 | 圈子是群聊入口，失控成本最高；已有管理端建圈审核页可复用 |
| 建圈上限 | 统一 1 个/人 | 按段位 1→2 | 大表写"上限 1→2"，但第二档要等铂金开放（本期未开放），先统一 1 |
| 特权判定依据 | 成长值 G | 当季活跃值 S | S 属 V3.3；本期没有"躺平惩罚"，这是已知缺口，写在第 7 节 |

## 四、数据表与字段

```sql
-- 体验段位与特权缓存（体验段位由第 6 份文档的新人礼包写入）
CREATE TABLE user_privilege (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id      BIGINT      NOT NULL,
  priv_key     VARCHAR(32) NOT NULL COMMENT '如 tier_trial_silver / priority_reply / post_fastlane / circle_create',
  active       TINYINT     NOT NULL DEFAULT 1,
  activated_at DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  expires_at   DATETIME    NULL COMMENT 'NULL=永久，按段位实时判定',
  UNIQUE KEY uk_priv (user_id, priv_key)
) COMMENT='限时特权；永久特权不入表，由段位实时判定';

-- 圈子：补创建者与审核字段（status 已存在，0=待审 1=展示）
ALTER TABLE circle ADD COLUMN creator_id BIGINT NULL COMMENT '用户创建时记录，管理端建的为 NULL';
ALTER TABLE circle ADD KEY idx_circle_creator (creator_id);
```

**特权判定（唯一入口 `TierService.effectiveTier(userId)`）**

```
1. G 推导段位（第 4 份文档）
2. 查 user_privilege 中 active=1 且 (expires_at IS NULL OR expires_at > now) 的 tier_trial_* 
3. 取两者中较高段位作为"生效段位"
4. 对照下表判定三项特权
```

| priv_key | 生效段位 | 判定 |
|---|---|---|
| `priority_reply` | ≥ 白银 | 生效段位 rank ≥ silver |
| `post_fastlane` | ≥ 黄金 | 生效段位 rank ≥ gold，且开关 `post.fastlane.enabled=1` |
| `circle_create` | ≥ 黄金 | 生效段位 rank ≥ gold，且开关 `circle.create.enabled=1` |

## 五、接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/points/me` | 本人 | 增加 `privileges: {priorityReply, postFastlane, circleCreate}` |
| POST | `/api/circles` | 登录 + 黄金 | 用户建圈；body `{name, category, description, cover}` |
| POST | `/api/admin/circles/{id}/status` | 管理员 | 圈子上/下架（补在现有管理端建圈接口旁） |
| GET | `/api/jobs?page=1` | 登录 | 首屏注入 `priority=true` 条目（仅 page=1） |

**`POST /api/circles` 校验顺序**

1. 开关 `circle.create.enabled=1`，否则 403「圈子创建暂未开放」。
2. 生效段位 ≥ 黄金，否则 403「创建圈子需要黄金段位（成长值 200）」。
3. 已创建数（`circle.creator_id=我`）< 1，否则 403「最多创建 1 个圈子」。
4. 参数：`name` 1–16 字、`category` 在白名单、`description` ≤64 字；过 `AuditService.checkText`，命中直接拒绝。
5. 落库：`circle(status=0, creator_id=我, member_count=1)` + `circle_member(role='owner')`，同一事务。
6. 返回 `{circleId, status:"pending"}`，页面提示「已提交，等待审核」。

**发帖免审改造点**（`ForumService.create` 第 149 行附近）

```
原: status = "passed".equals(auditStatus) ? 1 : 0
新: boolean fastlane = tierService.hasPrivilege(userId, "post_fastlane");
    status = (fastlane || "passed".equals(auditStatus)) ? 1 : 0;
    若 fastlane 命中: audit_log 记 source='fastlane'，仍调 scheduleImagesAfterCommit 与异步 checkText
    异步审核命中 → status=0 并写一条 audit_log(source='fastlane_revoked') + 站内通知作者
```

## 七、已知限制与本期不做

- **没有当季活跃值 S**：特权只看成长值，**躺着不掉段**。大表「想保住特权就得持续活跃」的效果本期不成立，属 V3.3。
- **快速应答不作用于**：考试、评奖、助学金、助学金类资源（大表合规第 10 条）。当前系统也没有这类功能，属"事先声明"。
- **免审仍要审核**：`msg_sec_check` 与图片审核照跑，只是"先发后审"，不是"不审"。
- **置顶曝光 ×2、抢单提前 10 秒、1对1急送、专属客服**：铂金及以上特权，本期不开放。
- **圈子创建后不能改名/换封面**：第二版再说。
- **建圈审核没有独立工作台**：复用管理端现有 `Circles.vue`，加一个"待审"筛选即可。

## 九、风险与被砍代价

| 风险 | 说明 | 处理 |
|---|---|---|
| 免审内容风险 | 黄金用户量少时可控，量大后违规内容扩散更快 | 先发后审 + 异步审核 + 立即下架 + 举报入口；开关 `post.fastlane.enabled` 可一键关停 |
| 建圈失控 | 用户建圈后拉人进群聊，群聊内容审核目前**未覆盖**（`docs/扩展功能规划.md` P0-4 已指出） | 建圈必须审核；群聊审核补齐前不放开更多名额 |
| 排序公平性 | 白银用户的岗位优先展示，低段位用户觉得被压 | 只影响 2 条，且是"同校优先"的合理排序，不是屏蔽他人 |
| 体验段位结束后的落差 | 第 8 天突然失去快速应答 | 第 5 天起在积分页提示「白银体验还剩 2 天」，减少突兀感 |

**砍掉代价**：段位退化为纯装饰，用户冲段没有实际收获；「发帖免审」这个几乎零成本的体验提升和「快速应答」这个零成本的稀缺感都拿不到。
