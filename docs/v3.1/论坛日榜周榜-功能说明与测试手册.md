## 一、这个功能解决什么问题

**现状（读码核实）**

- 论坛有完整的互动数据：`post.like_count`、`comment_count`、`view_count`、`post_like`（唯一键防重复）、`comment_like`（同）。
- 但**没有任何排行**：内容怎么排序只有「发帖时间倒序」和热度（`like*3 + comment*5 + view*1`，见 `项目文档清单` 提到的热度算法）。
- 用户发了好帖，只有点赞数一个模糊反馈，没有"我上榜了"的确定性回报。

**为什么值得做**

论坛是所有 UGC 平台的引擎。大表把榜单放在 A-9，并给"上榜"单独一档奖励，就是因为榜单是**一次性写好、长期自动运转**的激励：不需要运营天天找内容，规则自动把优质作者推到前面。你这次也明确要了日榜前 10、周榜前 20 送积分。

### 2.2 小程序端 · `pages/forum-rank`（新页）

**页面结构（自上而下）**

| 区域 | 内容 |
|---|---|
| 顶部切换 | 两段胶囊：`日榜` / `周榜`；右侧小字标注周期，如 `11-08` / `第 45 周` |
| 结算说明 | 一行 `.cp-hint`：`本榜已于 00:10 结算` 或 `今日尚未结算，展示昨日榜` |
| 前三名区 | 三张并排卡片（2-1-3 视觉排序），显示头像、昵称、得分、奖励标签 |
| 第 4–N 名列表 | 每行：名次、头像、昵称、得分、右侧 `+10 积分` 或灰色 `已发放` |
| 底部吸底条 | `我的排名：第 27 名 · 得分 18`；未上榜显示「你还没上榜，发个帖子试试」+ 按钮跳论坛 |

**操作步骤**

1. 进入默认日榜 → `GET /api/forum/rank?type=daily`。
2. 切「周榜」→ 重新拉取，列表回到顶部。
3. 下拉刷新 → 重拉当前榜。
4. 点任一行 → 跳 `pages/user-home`（现有用户主页）。
5. 底部「发个帖子试试」→ 跳 `pages/publish`。

**状态与边界**

| 情况 | 表现 |
|---|---|
| 榜单为空 | `empty-state`：「今天还没有人上榜」+ 按钮「去发帖」 |
| 当天未结算 | 展示最近已结算周期，顶部注明「今日尚未结算」 |
| 未登录 | 榜单可看，底部不显示「我的排名」，改为「登录后看我的排名」 |
| 加载中 | 前三名骨架 + 5 行列表骨架 |

### 2.3 上榜通知（复用 `notification`）

- 标题：`你登上论坛日榜第 3 名`
- 正文：`+10 积分已到账`
- 点击 → 跳 `pages/forum-rank?type=daily`
- 仅上榜者收到，未上榜不发

### 2.4 Web 端 · `web/src/views/PointsRank.vue`（新页）

**页面结构**

- 标题区：`论坛榜单` + 说明「快照一旦生成不会变；重结算幂等，已发放的不会重复发」。
- 筛选：类型（日榜/周榜）、周期（日期选择器 / 周选择器）。
- 表格列：名次、用户 ID、昵称、得分、奖励、发放状态、结算时间。
- 操作：「重新结算本周期」按钮。

**操作步骤**

1. 选类型与周期 → `GET /api/admin/forum-rank?type=&period=`。
2. 点「重新结算」→ `NoModal` 确认：「将重算该周期排名；已发放奖励不会重复发放」→ `POST /api/admin/forum-rank/resettle`。
3. 成功 → 绿条「重算完成，发放 N 人」。

**状态与边界**：未结算周期显示「该周期还没有快照」+ 「立即结算」按钮；发放失败的行标红，可再次重算。

## 三、设计取舍

| 决策 | 选了 | 没选 | 为什么 |
|---|---|---|---|
| 算分口径 | 发帖×3 + 评论×2 + 被赞×1 | 只看点赞数 | 你已选定综合分；纯点赞对新用户不友好（没人认识你就没赞），综合分让新人靠"发帖+评论"也能上榜 |
| 被赞权重 | 1 | 3 | 与发帖同权会让"互赞群"主导榜单；1 分权重下刷赞收益低于刷帖，且刷帖要过内容审核 |
| 评论计入条件 | 字数 ≥5 且非纯表情 | 全算 | 防止"顶""1"刷分；5 个字是能表达意思的最低门槛 |
| 结算方式 | 落 `forum_rank` 快照后发分 | 实时查排名+实时发分 | 实时排名会随互动抖动，用户看到第 3 名转眼变第 4 名会投诉；快照=当日最终结果，可复核 |
| 结算时间 | 日榜次日 00:10，周榜周一 00:10 | 23:59 | 给最后一分钟的互动留出写入与事务提交时间 |
| 周期边界 | `Asia/Shanghai` 自然日/自然周 | 滚动 24 小时 | 滚动窗口无法"每日一结"，也不符合用户理解的"今天/这周" |
| 重跑 | 幂等，可手动补跑 | 只跑一次，漏了就算 | 定时任务可能因重启错过；必须有后台补跑入口 |
| 日榜与周榜是否互斥 | 不互斥，可同时拿 | 只能拿一个 | 两者周期不同、奖励不同，同时拿是合理的 |

## 四、数据表与字段

```sql
CREATE TABLE forum_rank (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  board      VARCHAR(8)  NOT NULL COMMENT 'daily|weekly',
  period_key VARCHAR(16) NOT NULL COMMENT '2026-11-08 / 2026-W45',
  user_id    BIGINT      NOT NULL,
  score      INT         NOT NULL,
  rank_no    INT         NOT NULL,
  awarded    TINYINT     NOT NULL DEFAULT 0,
  created_at DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_rank (board, period_key, user_id),
  KEY idx_rank_period (board, period_key, rank_no)
) COMMENT='榜单快照；结算后不再变动，作为发奖依据与用户可见的最终结果';
```

**算分 SQL（单周期，示例日榜 `2026-11-08`）**

```sql
SELECT uid, SUM(pts) AS score FROM (
  SELECT user_id AS uid, 3 AS pts FROM post
   WHERE status = 1 AND created_at >= :start AND created_at < :end
  UNION ALL
  SELECT user_id, 2 FROM comment
   WHERE CHAR_LENGTH(TRIM(content)) >= 5 AND created_at >= :start AND created_at < :end
  UNION ALL
  SELECT p.user_id, 1 FROM post_like l JOIN post p ON p.id = l.post_id
   WHERE l.created_at >= :start AND l.created_at < :end
  UNION ALL
  SELECT c.user_id, 1 FROM comment_like l JOIN comment c ON c.id = l.comment_id
   WHERE l.created_at >= :start AND l.created_at < :end
) t GROUP BY uid ORDER BY score DESC, uid ASC LIMIT :n;
```

- 并列按 `user_id` 升序，保证结果稳定可复现。
- `post.status=1`：未过审/已下架的帖子不计分。
- 时间窗：日榜 `[当日 00:00, 次日 00:00)`；周榜 `[周一 00:00, 下周一 00:00)`。

## 五、接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/forum/rank?type=daily\|weekly` | 登录（我的排名需登录） | 榜单 + 我的排名 |
| GET | `/api/admin/forum-rank?type=&period=` | 管理员 | 查看任意周期快照与发放状态 |
| POST | `/api/admin/forum-rank/resettle` | 管理员 | 手动补跑 `{type, periodKey}`，幂等 |

**返回**

```json
{
  "code": 0,
  "data": {
    "type": "daily",
    "periodKey": "2026-11-08",
    "settled": true,
    "rows": [
      { "rankNo": 1, "userId": 3, "nickname": "陈一川", "avatar": null, "score": 86, "awarded": 10 },
      { "rankNo": 2, "userId": 1, "nickname": "林知夏", "avatar": "/assets/...", "score": 71, "awarded": 10 }
    ],
    "me": { "rankNo": 27, "score": 18, "awarded": 0 }
  }
}
```

**结算流程（`ForumRankScheduler`）**

1. 计算 `periodKey` 与时间窗（`Asia/Shanghai`）。
2. 跑算分 SQL，取前 `N`（日 10 / 周 20）。
3. `INSERT forum_rank ... ON DUPLICATE KEY UPDATE score=VALUES(score), rank_no=VALUES(rank_no)`（补跑时覆盖分数，但 `awarded=1` 的不重复发）。
4. 对 `awarded=0` 的行逐个 `PointsService.award(userId, 'rank_daily'|'rank_weekly', periodKey, 10|15, 15|25)`；成功后置 `awarded=1`。
5. 写站内通知。
6. 任一行失败不影响其他行（逐行事务），失败行留 `awarded=0`，下次补跑继续。

> 注意：`task_catalog` 需要两行 —— `rank_daily`(10P/15G)、`rank_weekly`(15P/25G)，`daily_cap=1`，`biz_key = periodKey`（跨周期不冲突）。

## 七、已知限制与本期不做

- **不做赛季榜**：大表的"赛季前十"属 V3.3，需要赛季表与活跃值 S。
- **不做校区间榜**：本期榜单是全校维度（`school_id` 隔离在数据侧已具备，但榜单只算本校）。
- **不做"发帖免审"与榜单的联动**：黄金用户免审帖照常计分（因为过审状态为 1），不额外加权。
- **不做作弊检测系统**：只有"评论 ≥5 字""帖子需过审"两道门槛；专业反作弊（同 IP、设备指纹）不在本期。
- **不做榜单冠名/赞助位**：大表提到"榜单冠名（赞助）"，需商务合作，代码侧只预留标题文案字段，不实现。
- **不发实物奖**：只有积分与成长值。

## 九、风险与被砍代价

| 风险 | 说明 | 处理 |
|---|---|---|
| 互赞刷分 | 小群互赞把榜单占满 | 被赞权重仅 1、评论需 ≥5 字、帖子需过审；后续可按"同一对用户互赞只计 1 次"加强 |
| 灌水评论 | 大量 5 字评论刷分 | 评论本身有 5P/条 + 日限 3 条任务上限，且内容要过 `AuditService`；榜单加分与任务发分是两条独立线，前者不设日限但被审核兜底 |
| 定时任务漏跑 | 服务重启错过 00:10 | 后台提供 `resettle` 手动补跑，幂等可重复执行 |
| 时区错位 | UTC 服务器把周榜算错一天 | 统一 `Asia/Shanghai`，`CircleStreakService.BEIJING` 是既有先例 |
| 榜单无内容可上 | 冷启动期一天只有 3 个帖子 | 榜单照常展示（第 3 名就是第 3 名），不做假数据填充 |

**砍掉代价**：你这次的核心诉求之一落空；UGC 作者失去唯一的确定性回报，论坛只能靠"发帖时间倒序"自然生长。
