## 五、口径与前提

- 人日 = 熟悉本仓库的 1 名开发者，不含联调等待、资质审批、UI 设计。
- 积分 100P = 1 元，**仅价值公示，不可提现**。
- `job.paid.enabled` 仍为 0：学生认证做完也不能接有偿单。
- 小程序微信认证 + 备案未完成（见 `docs/小程序上线进度.md`），代码可以做、后端接口全通，但真机拉新仍跑不起来 —— 这是上线前置，不是代码缺口。
- 所有功能均基于《全功能积分任务与段位特权大总表_V3.md》的 V3.1 范围设计。
- **验收口径**：每份文档的测试计划里，可自动化用例全部落成 JUnit 或可复现脚本并通过；只有「真机像素级交互」与「`school` 角色 403 的真实 HTTP 状态码」两类仍标未自动验证（见交付报告第二节）。合计 `mvn -o test` **360 个测试通过**（4 个跳过为无 Redis 集群时的集成测试，属设计内跳过）。
- **原「只能手工」项已批量自动化**：未登录 401（`config/V31AuthGateTest` 8 例）、SQL 幂等（`config/SqlMigrationIdempotencyTest` 连跑两遍 44 个脚本）、交易发分「提交后才发/回滚不发/并发幂等」（`MerchantPointsAwardIntegrationTest`、`JobSettleAwardIntegrationTest`）、券结算三件套（`CouponOrderSettlementIntegrationTest`）、争议裁定账务重算、30 秒配置 TTL 与签到跨天边界（注入 `Clock`）、宠物回归（`PetPointsRegressionIntegrationTest`）、页面契约（`tools/check-v31-page-contracts.js`、`check-v31-newbie-gift.js`、`check-v31-coupon-select.js`）。
- **SQL 幂等由测试兜底**：`config/SqlMigrationIdempotencyTest` 在临时 schema 里把 `schema.sql` + 全部 `module-*.sql` 连续执行两遍，任一遍报错即失败（已用「故意注入裸 `ALTER TABLE ADD COLUMN`」验证过它确实会红）。这条以前只有人工声明，现在是回归门禁。
