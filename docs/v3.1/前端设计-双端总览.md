## 三、小程序端规范（沿用现有，不要另起一套）

### 3.1 配色与尺寸：只引用变量

`styles/theme.wxss` 已定义，页面里**不许写死色值**：

| 变量 | 值 | 用途 |
|---|---|---|
| `--c-bg` | `#F7F3EA` | 页面底色（奶油色） |
| `--c-card` | `#FFFCF5` | 卡片底 |
| `--c-primary` | `#2F6555` | 主按钮、选中态（森林绿） |
| `--c-text` / `--c-text-sub` | `#203D34` / `#586A60` | 正文 / 次要文字 |
| `--c-accent` | `#BD5134` | 重要点缀（陶土橙），如「+10 积分」 |
| `--c-soft` / `--c-line` | `#E0EADC` / `#DEDCCD` | 浅底标签 / 分割线 |
| `--sp-page` / `--sp-card` / `--sp-gap` | 32 / 28 / 24 rpx | 页面留白 / 卡片内距 / 卡片间距 |
| `--radius-card` / `--radius-pill` | 28rpx / 999rpx | 卡片 / 胶囊 |
| `--h-button` | 88rpx | 主按钮高度 |
| `--fs-page-title` / `--fs-card-title` / `--fs-body` / `--fs-hint` | 40 / 32 / 28 / 24 rpx | 四级字号 |

页面 `wxss` 第一行固定写：`@import "../../styles/theme.wxss"; @import "../../styles/common.wxss";`

### 3.2 能直接用的类（`styles/common.wxss`）

`.cp-page`（页面容器）· `.cp-page-title` · `.cp-card`（卡片）· `.cp-card-title` · `.cp-body` · `.cp-hint` · `.cp-btn-primary` / `.cp-btn-primary--disabled` · `.cp-btn-ghost` · `.cp-divider` · `.cp-empty`（空态）· `.cp-grid-2` / `.cp-grid-3`（等分栅格）· `.cp-tag` · `.cp-selected`

**V3.1 的积分页、榜单页、宿舍页、认证明细，一律用 `.cp-card` 叠放，不新造卡片样式。**

### 3.3 组件

| 组件 | 用在哪 | 说明 |
|---|---|---|
| `ui-popup` | 全站弹层 | 三形态：`toast` / `modal` / `sheet` |
| `empty-state` | 积分明细、榜单空、宿舍未加入 | 传 `title`/`desc`/可选按钮 |
| `skeleton-list` | 榜单、明细首屏 | 首屏加载态，别用白屏 |
| `offline-banner` | 所有新页顶部 | 断网提示 |
| `nav-bar` | 新页自定义导航 | 与现有页面一致 |

### 3.4 弹窗只能走 `ui-popup-helper`

```js
const popup = require('../../utils/ui-popup-helper')
popup.toast(this, '签到成功 +1 积分', { tone: 'success' })
popup.modal(this, { title: '确认兑换', message: '将扣除 10 积分，兑换后不可退', confirmText: '兑换', confirm(res) {} })
popup.sheet(this, { actions: [{ text: '复制邀请码' }, { text: '取消', type: 'cancel' }], action(res) {} })
```

**禁止**直接用 `wx.showToast` / `wx.showModal`：它们绕过了统一主题与 tone，视觉会和现有页面不一致；`tools/check-popup-api.js` 会查这个。

### 3.5 点击反馈三档

| 场景 | `hover-class` |
|---|---|
| 文字 / 图标按钮 | `tap` |
| 卡片 / 列表项 | `tap-card` |
| 主按钮 | `tap-btn` |

统一配 `hover-stay-time="80"`。**不加反馈的后果是用户以为没点上而反复点，进而重复提交**——积分/兑换/签到这类写操作尤其要加。

### 3.6 导航与安全区

所有新页沿用 `navigationStyle: custom` + `utils/navigation.getNavigationMetrics()`，把 `statusBarHeight` / `navBarHeight` / `capsuleReservedRight` 写进 `data`，顶部留白按现有页面写法处理，**不要硬编码 px**。

### 3.7 数据层

- 新域按 `utils/api/<domain>.js` 拆分（参照 `utils/api/pet.js`、`utils/api/circle.js`），再在 `utils/api.js` 里 `Object.assign(module.exports, ...)` 汇总。
- **写接口不兜底**（签到、兑换、认证提交、建圈、成交确认），失败就如实报错；**读接口可 `fallback`**（榜单、商品池）。
- 新增导出必须跑 `node tools/check-api-exports.js`，否则页面调不到方法。

### 3.8 状态四件套（每页都要有）

| 状态 | 做法 |
|---|---|
| 加载中 | 首屏 `skeleton-list`；翻页用底部「加载中…」 |
| 空 | `empty-state`，文案具体（「今天还没有人上榜」而不是「暂无数据」） |
| 失败 | 页面级错误块 + 「重试」按钮；写操作失败用 `popup.toast(..., { tone: 'error' })` |
| 断网 | `offline-banner` + 读接口回落缓存 |

## 四、Web 管理端规范（沿用现有）

### 4.1 布局

`AdminLayout`（侧栏 + 内容区，移动端折叠），页面根节点固定：

```vue
<section class="space-y-5">
  <div>
    <h2 class="text-base font-semibold text-stone-800">页面标题</h2>
    <p class="mt-1 text-sm text-stone-600">一句话说明这页能干什么、有什么限制</p>
  </div>
  <!-- 提示区 / 筛选区 / 表格区 / 弹窗 -->
</section>
```

### 4.2 能直接用的类（`web/src/style.css`）

`.no-btn` · `.no-btn-primary` · `.no-btn-ghost` · `.no-btn-sm` · `.no-card-plain` · `.no-input` · `.no-badge`

**不要**直接用 Tailwind 手搓一套新按钮，颜色会和现有后台不一致。

### 4.3 弹窗

统一用 `NoModal`（现有 `Verification.vue`、`Circles.vue` 在用）：`open` / `title` / `hint` / `submitting` / `confirm-text` / `@close` / `@confirm`。

### 4.4 表格

```html
<div class="no-card-plain !p-0 overflow-x-auto">
  <table class="w-full min-w-[760px] text-left text-sm">
```

宽表必须 `overflow-x-auto` + `min-w-[…]`，否则手机上横向溢出（现有 26 个视图只有 6 个做了，新页不要重犯）。

### 4.5 路由与菜单

在 `web/src/router/index.js` 后台 children 里加一条，`meta` 必须带 `title` 与 `icon`：

```js
{ path: 'points-tasks', name: 'points-tasks', component: () => import('../views/PointsTasks.vue'),
  meta: { title: '积分任务', icon: '★' } }
```

涉及全校数据的加 `superOnly: true`；校管能用的不放 `superOnly`。

### 4.6 权限

前端只负责**隐藏入口**，后端必须再校验一次（`AdminInterceptor` + `scopeSchool`）。参照 `AdminVerificationController.scopeSchool()`：`super` 不限校，`school` 强制本校。

### 4.7 提示区

沿用现有两块色带：

```html
<p v-if="error" class="rounded-md border border-[#e3cbbf] bg-[#f6e7e0] px-4 py-3 text-sm text-[#a4553f]">{{ error }}</p>
<p v-if="notice" class="rounded-md border border-[#cfdcc4] bg-[#eef4e8] px-4 py-3 text-sm text-[#4d6b3c]">{{ notice }}</p>
```

## 五、通用状态与文案口径

| 状态 | 小程序端 | Web 端 | 文案示例 |
|---|---|---|---|
| 加载中 | 骨架屏 / 底部加载 | 表格「正在加载…」 | — |
| 空 | `empty-state` | 表格「没有符合条件的记录」 | 「今天还没有人上榜」 |
| 失败 | 错误块 + 重试 | 顶部红色提示块 | 「加载失败，下拉重试」 |
| 未登录 | 401 → 跳登录 | 401 → 跳 `/login` | 「请先登录」 |
| 无权限 | 按钮保留，点击提示 | 入口隐藏 + 直链 403 | 「创建圈子需要黄金段位（成长值 200）」 |
| 开关关闭 | 入口保留，点击提示 | 页面顶部说明「该功能已关闭」 | 「认证申请暂未开放」 |
| 频控 | toast | 顶部提示 | 「今天提交次数过多，请明天再试」 |
| 段位不足 | 见「无权限」 | — | 同上 |

**文案三条铁律**
1. 说**下一步**，不说「操作失败」（例：「积分不足，去发帖赚积分吧」）。
2. 不出现「系统繁忙」「未知错误」这类无信息量的词。
3. 涉及钱/积分的操作必须写清**不可逆**（「兑换后不可退」）。
