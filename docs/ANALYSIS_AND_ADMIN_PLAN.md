### 2.3 关于「外部教务对接」——必须说明

**各高校教务系统没有公开 API，各校字段还不统一**。在没有目标学校接口文档的前提下，
"完成对接"只能是**编造数据源**，那是假的。

因此改为：`POST /api/admin/timetable/import` —— 管理员把教务系统导出的课表整理成 CSV 批量导入。
- 支持列：`课程名,教室,星期,节次,起始周,结束周[,配色]`
- 星期支持「周一」或数字 1-7
- **错误行处理：全有或全无** —— 任一行有问题则整批拒绝，返回带行号的错误清单，不写入半截数据
- 将来拿到真实接口，只需替换数据来源，接口形状不变

## 三、还缺什么（按价值排序）

### P0 · 影响可用性

| # | 缺失 | 说明 | 预估 |
|---|---|---|---|
| 1 | **Web 管理端** | 见第四节。目前所有管理动作（建圈、导入课表、运营 banner）都要直连数据库 | 大 |
| 2 | **内容审核** | 用户发帖/评论无审核、无举报、无删除入口。生产环境必需 | 中 |
| 3 | **登录后的用户体系** | 现在登录能拿到 token，但前端没有「登录页/退出登录/切换账号」入口 | 小 |

### P1 · 体验与完整性

| # | 缺失 | 说明 |
|---|---|---|
| 4 | **圈子推荐/搜索圈子** | 「搜索圈子」目前跳到帖子搜索页，没有圈子搜索 |
| 5 | **圈子内消息通知** | 加入圈子、圈内被回复没有通知（通知表已支持，未埋点） |
| 6 | **聊天图片消息前端** | 表结构支持 `type='image'`，chat 页还没加发送图片入口 |
| 7 | **二手/外卖的订单流转** | 下单即完成，没有「已接单/配送中/已完成」状态机 |
| 8 | **分页一致性** | 部分列表用 `size=50` 一次拉完，数据量大后会有性能问题 |

### P2 · 工程质量

| # | 缺失 | 说明 |
|---|---|---|
| 9 | **接口鉴权收紧** | 现在是「轻量鉴权」——伪造 token 不报错只是降级。生产需按接口分级授权 |
| 10 | **写接口的幂等性** | 发帖/下单没有幂等键，重复提交会产生重复数据 |
| 11 | **后端单测** | 只有前端行为测试，后端 58 个端点没有单元测试 |
| 12 | **日志与监控** | 没有请求日志、慢查询日志、错误聚合 |
| 13 | **上传文件清理** | 上传的图片没有清理机制，会无限累积 |
| 14 | **敏感词过滤** | 发帖/评论无敏感词拦截 |

### P3 · 数据

| # | 缺失 | 说明 |
|---|---|---|
| 15 | **分页总数不准** | `GET /posts` 的 total 用的是全表数，翻到尾部会拿到空页 |
| 16 | **无索引优化** | 推荐排序用了 `EXP/TIMESTAMPDIFF` 表达式排序，无法走索引，数据量大时慢 |

## 四、Web 管理端方案

### 4.1 为什么需要它

目前**所有管理动作都要直连数据库**：

```sql
-- 运营要上活动 → 手工 INSERT banner
INSERT INTO banner(slot,title,...) VALUES('discover','校园歌手大赛',...);
-- 管理员要建圈子 → 手工 INSERT circle
INSERT INTO circle(name,slug,...) VALUES('王者荣耀','wzry',...);
-- 要导课表 → 手工跑 SQL 或调接口
```

这对非技术人员**不可用**。

### 4.2 技术选型建议

| 方案 | 说明 | 适合 |
|---|---|---|
| **A. 独立 Vue3 + Element Plus 前端** | 与后端完全分离，调 `/api/admin/**` | ✅ 推荐 |
| B. 后端内嵌 Thymeleaf 页面 | 不分离部署，改动小 | 快速原型 |
| C. 低代码平台（如 amis） | 配置即页面 | 只想快速看数据 |

推荐 **A**：后端已经是 REST 风格，加管理接口即可，前端独立部署不影响小程序。

### 4.5 安全要求（管理端必须做，不能照搬小程序的轻量鉴权）

| 要求 | 说明 |
|---|---|
| **独立的角色表** | `admin_user`，与 `user` 分离，避免普通用户提权 |
| **强制鉴权** | 管理接口**必须**校验，不能用「解析失败就降级」那套 |
| **RBAC** | 至少区分：超管 / 运营 / 内容审核 |
| **操作日志** | 所有写操作记录 admin_id + IP + 时间 + 变更内容 |
| **登录风控** | 失败次数限制、验证码 |
| **审计** | 删除类操作软删除 + 可恢复 |
