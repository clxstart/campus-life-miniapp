## 关于数字口径（避免答辩被追问对不上）

同一套代码，按不同口径数出来的数字不同，都是对的：

| 口径 | 数字 | 怎么数的 |
|---|---|---|
| **本文档采用** | **211** | 一个 `@XxxMapping` 算一个端点，多路径别名只记第一个 |
| 方法级映射 | 218 | 把 `@GetMapping({"/shops","/food/shops"})` 这种别名按 2 个算 |
| 唯一路径 | 213 | 别名展开后去重 |

差异来源：`BizController` 里有 2 个方法用了双路径别名（`/shops` 与 `/food/shops` 指向同一个方法）。

**对外建议统一说「26 个控制器、210+ 个接口」**，不要报精确数字，省得被追问口径。

数据表同理：`information_schema` 里是 53 张，其中 `sensitive_word_backup_22` 是备份表，业务表 52 张；`schema.sql` 与 `module-*.sql` 有重复定义，按脚本数会更多。**对外说「50 余张表」**即可。

## 一、通用约定

### 1.1 基础信息

| 项 | 值 |
|---|---|
| 本地地址 | `http://127.0.0.1:8080/api` |
| 统一响应体 | `{ "code": 0, "msg": "ok", "data": ... }` |
| `code = 0` | 成功 |
| 非 0 | 失败，`msg` 为可直接展示的中文提示 |
| 字符集 | UTF-8 |
| 请求体格式 | `application/json` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（日期字段用 `yyyy-MM-dd`） |

### 1.2 HTTP 状态码约定

| 状态码 | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | `code=0` |
| 400 | 参数错误 / 业务拒绝 | 校验失败、内容含违规词（`code=4001`） |
| 401 | 未登录 / token 失效 | 写操作或「我的数据」接口缺 token |
| 403 | 已登录但无权 | 校管查别校数据、商家账号访问管理端 |
| 409 | 状态冲突 | 重复报名、订单状态不允许 |
| 429 | 请求过于频繁 | 上传限流 |
| 500 | 服务端异常 | 兜底 |

### 1.3 鉴权规则（重要）

系统里有**三套独立身份**，token 互不通用：

| 身份 | 登录接口 | token 用途 | 拦截器 |
|---|---|---|---|
| 小程序用户 | `POST /api/auth/login`（微信 code）或 `POST /api/auth/dev-login`（开发） | 访问 `/api/**` 的用户侧接口 | `AuthInterceptor` |
| 管理员 | `POST /api/admin/login` | 访问 `/api/admin/**` | `AdminInterceptor` |
| 商家 | 同一登录接口（role=merchant） | 访问 `/api/merchant/**` | `AdminInterceptor` |
| 骑手 | 同一登录接口（role=rider） | 访问 `/api/rider/**` | `RiderInterceptor` |

**强制鉴权范围**（`AuthInterceptor` 的实际规则）：

| 请求类型 | 是否必须带 token |
|---|---|
| 写操作（POST/PUT/DELETE，`/api/**`） | **必须** |
| 私有读：`/api/conversations`、`/api/notifications`、`/api/timetable`、`/api/pet`、`/api/circle-messages`、`/api/users/{id}/` 下的收藏/浏览/优惠券/地址/发布数 | **必须** |
| 公开读：帖子流、搜索、学校、圈子、商家、二手、兼职、活动、推荐、banners | 不需要 |
| 白名单（永不校验）：`/api/auth/**`、`/api/admin/login`、`/api/merchant/apply`、`/api/pay/notify`、`/api/pay/refund/notify`、`/api/ai/**`、`/api/upload` | 不需要 |
| `/api/admin/**`、`/api/merchant/**`、`/api/rider/**` | 由各自拦截器负责（`AuthInterceptor` 直接放行） |

**身份优先级**：token 里的 userId 永远优先于请求参数/body 里的 `userId`。客户端传别人的 userId 只会被忽略（记在自己名下）。

### 1.4 分页约定

分页接口统一参数与返回：

```
?page=1&size=20
```

```json
{ "code": 0, "data": { "list": [...], "total": 128, "page": 1, "size": 20 } }
```

`size` 上限一般是 50（管理端部分接口 100）。

### 1.5 多校隔离参数

多个列表接口支持 `schoolId`：

| 身份 | 行为 |
|---|---|
| 超管（role=super） | 传了就按该校筛，不传看全部 |
| 校管（role=school） | 固定看本校，传别校会返回 403 |

## 六、错误码速查

| code | HTTP | 含义 | 前端该怎么处理 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 400 | 400 | 参数错误 | 直接展示 `msg` |
| 4001 | 400 | 内容含违规词 | 展示 `msg`，提示修改内容 |
| 401 | 401 | 未登录 / token 失效 | 清 token，重新登录 |
| 403 | 403 | 无权访问 | 提示「无权限」，**不要清 token** |
| 409 | 409 | 状态冲突（重复报名等） | 展示 `msg` |
| 429 | 429 | 请求过频 | 提示稍后再试 |
| 500 | 500 | 服务端异常 | 提示「服务异常」并上报 |

## 七、用 curl 快速自测

```bash
# 1. 小程序开发登录（拿 token）
TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/dev-login \
  -H 'content-type: application/json' -d '{"userId":1}' | jq -r .data.token)

# 2. 公开接口（不需要 token）
curl -s 'http://127.0.0.1:8080/api/posts?page=1&size=3'
curl -s 'http://127.0.0.1:8080/api/schools'

# 3. 需要 token 的接口
curl -s -H "Authorization: Bearer $TOKEN" 'http://127.0.0.1:8080/api/conversations'
curl -s -H "Authorization: Bearer $TOKEN" 'http://127.0.0.1:8080/api/timetable?userId=1'

# 4. 管理端登录（另一套 token）
ADMIN=$(curl -s -X POST http://127.0.0.1:8080/api/admin/login \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | jq -r .data.token)
curl -s -H "Authorization: Bearer $ADMIN" 'http://127.0.0.1:8080/api/admin/dashboard'

# 5. 反向验证：拿小程序 token 打管理端应 403/401
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" \
  'http://127.0.0.1:8080/api/admin/users'
```
