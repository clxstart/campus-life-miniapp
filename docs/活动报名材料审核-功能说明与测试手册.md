## 一、这次做了什么（一句话）

给活动报名加了**两种模式**，由管理端在活动编辑里**按活动单独选择**：

| 模式 | 学生体验 | 报名数何时 +1 |
|---|---|---|
| **一键报名**（默认） | 点「报名」立刻成功 | 立即 |
| **填表 + 材料 + 审核** | 跳转到表单页，填姓名/电话 + 上传材料 → 提交 | **审核通过后** |

**关键点**：老活动默认是「一键报名」，行为完全不变，不受影响。

---

## 二、为什么是「按活动开关」而不是全站开关

你原话是"我后台可以选择开启或者不开启"，我理解成**每个活动自己决定**，理由：

- 「校园歌手大赛」需要作品才能筛选
- 「周末操场跑步」点一下报名就够了
- 如果做成全站开关，要么所有活动都被迫填表（过度设计），要么全都不用（功能白做）

所以设计成：**活动级开关 + 默认关闭**。

## 三、数据怎么存的

新增了一个迁移脚本（可重复执行）：

```
backend/src/main/resources/db/module-activity-enroll.sql
```

### 活动表 `campus_activity` 加了 3 个字段

| 字段 | 含义 | 默认 |
|---|---|---|
| `enroll_mode` | `simple` 一键报名 / `material` 填表+材料+审核 | `simple` |
| `enroll_hint` | 报名须知（展示给学生，如"请上传伴奏音频"） | 空 |
| `enroll_max_files` | 材料最多几个文件 | 3 |

### 报名表 `activity_enroll` 加了 8 个字段

| 字段 | 含义 |
|---|---|
| `status` | `approved` 已通过 / `pending` 待审核 / `rejected` 已驳回。**老数据默认 approved** |
| `real_name` | 报名人姓名 |
| `student_no` | 学号 |
| `phone` | 联系电话 |
| `remark` | 自我介绍 |
| `audit_reason` | 驳回原因（学生能看到） |
| `audited_at` | 审核时间 |
| `audited_by` | 审核人（admin_user.id） |

### 新表 `activity_enroll_material`（多材料）

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `enroll_id` | 指向 `activity_enroll.id` |
| `url` | 上传后的文件地址 |
| `file_name` | 原始文件名（便于识别） |

## 四、管理端怎么用

### 4.1 给某个活动开启「材料 + 审核」

**路径**：`业务管理` → 切到「活动」Tab → 找到目标活动 → 点「编辑」

弹窗底部新增了一块「报名方式」：

```
报名方式：[一键报名（点一下就算报上）  ▾]
         [填表 + 上传材料 + 管理员审核    ]
```

选第二项后，会多出两个字段：

| 字段 | 说明 |
|---|---|
| 报名须知 | 展示给学生，如"请上传伴奏音频与个人照片" |
| 材料数量上限 | 1-9，默认 3 |

保存后立即生效，小程序刷新就能看到。

### 4.2 审核学生报名

**路径**：左侧菜单 → **报名审核**（新页面，在「业务管理」下面）

| 功能 | 说明 |
|---|---|
| 待审核队列 | 默认只看 `pending`，可切到「已通过 / 已驳回 / 全部」 |
| 按学校筛选 | 超管可选学校；校管只能看本校 |
| 看材料 | 材料以链接形式列出，点开可在新标签查看 |
| 通过 | 二次确认 → 报名数 +1 → 学生状态变「已通过」 |
| 驳回 | **必须填原因**（学生能看到）→ 报名数不变 |

**只有「材料」模式的活动会出现在这里**，一键报名的活动直接通过、不进队列。

## 五、小程序端怎么用

### 学生侧流程

```
活动列表 → 点「报名」
   ├─ 一键报名模式 → 直接报名成功，按钮变「已报名」
   └─ 材料模式     → 跳到「活动报名」页
                        ├─ 填 姓名* / 学号 / 电话* / 自我介绍
                        ├─ 上传材料（1~N 份，图片或视频）
                        └─ 提交 → 显示「提交成功，等待管理员审核」
```

### 几个细节

| 细节 | 说明 |
|---|---|
| 必填项 | 姓名、电话、至少 1 份材料。缺一个都不让提交，提示具体缺什么 |
| 材料上传 | 复用已有上传接口：**单文件 5MB 上限**、校验真实文件头、按 IP 限流 |
| 上传失败 | 任一文件失败则整体失败，**不会出现"传了一半"** |
| 报名数 | 提交后**不立即 +1**，审核通过才 +1（避免刷报名数） |
| 重复报名 | 同一个人对同一活动只能报一次，第二次提示「已经报名过啦」 |
| 离线 | 材料报名**不做离线兜底** —— 离线假装成功会让用户以为报上了，比报错更糟 |

### 新增页面

| 文件 | 作用 |
|---|---|
| `pages/activity-enroll/activity-enroll.js` | 报名表单逻辑 |
| `...wxml` | 表单 + 材料上传 UI |
| `...wxss` | 沿用项目暖色手账风格 |
| `...json` | 页面配置 |

## 八、已知边界（先告诉你，免得测试时困惑）

| 边界 | 说明 | 是否要改 |
|---|---|---|
| 材料只支持图片/视频 | `wx.chooseMedia` 的 mediaType 限制。**音频（伴奏 mp3）选不了** | ⚠️ 见下 |
| 材料不能预览 PDF | 同上 | 同上 |
| 报名通过后没有站内通知 | 学生只能自己回活动页看状态 | 建议后续加 |
| 审核列表没有批量操作 | 一条条点 | 数据多时再加 |
| 不能撤回报名 | 学生报名后无法取消 | 看你要不要 |

### ⚠️ 关于「伴奏音频」这个边界

你截图里的活动是**校园歌手大赛**，最可能要传的是 **mp3 伴奏**。但微信小程序的 `wx.chooseMedia` **不支持选音频文件**，只有两个办法：

| 办法 | 说明 | 工作量 |
|---|---|---|
| A. 让学生把伴奏存成视频上传 | 用「视频」类型，学生自己录一段或转成 mp4 | 0（现状） |
| B. 改用 `wx.chooseMessageFile` | 从微信聊天记录选文件，**支持 mp3/zip 等任意类型** | 半天（要改上传接口的类型白名单） |

**现在实现的是 A**。如果歌手大赛确实要 mp3，建议上 B —— 说一声我加。

## 十、下一步要不要做（你决定）

1. **支持 mp3 伴奏上传**（改用 `wx.chooseMessageFile`）—— 半天
2. **审核结果站内通知** —— 学生提交后能收到「通过/驳回」消息
3. **学生撤回报名** —— 待审核状态下可以自己取消
4. **审核批量通过** —— 报名多的时候省事
