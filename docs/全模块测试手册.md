## 零、测试前准备

### 0.1 环境

| 服务 | 启动方式 | 地址 |
|---|---|---|
| MySQL | 系统服务 | 127.0.0.1:3306 |
| 后端 | `cd backend && mvn spring-boot:run` | http://127.0.0.1:8080 |
| 管理端 | `cd web && pnpm dev` | **http://localhost:5180** |
| 小程序 | 微信开发者工具打开项目根目录 | 模拟器 |

> 管理端必须用 `localhost`，不能用 `127.0.0.1:5180`（Vite 只绑了 localhost）。

### 0.2 账号

| 端 | 账号 | 密码 |
|---|---|---|
| 管理端超管 | `admin` | `admin123` |
| 小程序 | 无需登录，自动以「林知夏」（1 号演示用户）身份进入 | — |

### 0.3 通用判定标准

| 项 | 合格标准 |
|---|---|
| 页面加载 | 3 秒内出内容，无白屏 |
| 数据一致性 | 小程序改的东西，管理端能看到（反之亦然） |
| 错误处理 | 出错有中文提示，不出现英文报错/堆栈 |
| 空数据 | 显示空态文案，不是空白页 |
| 断网 | 有离线提示，不是崩溃 |

### 1.3 鉴权边界（重要，用 curl 测）

```bash
# 1. 匿名访问管理端接口 → 应 401
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/admin/users
# 预期 401

# 2. 匿名访问私有读接口 → 应 401
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/conversations
# 预期 401

# 3. 匿名访问公开读接口 → 应 200
curl -s -o /dev/null -w '%{http_code}\n' 'http://127.0.0.1:8080/api/posts?page=1&size=1'
# 预期 200

# 4. 拿小程序 token 打管理端 → 应 401/403
TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/dev-login \
  -H 'content-type: application/json' -d '{"userId":1}' | jq -r .data.token)
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8080/api/admin/users
# 预期 401 或 403
```

| 检查 | 预期 | 结果 |
|---|---|---|
| 匿名打管理端 | 401 | ☐ |
| 匿名打私有读 | 401 | ☐ |
| 匿名打公开读 | 200 | ☐ |
| 小程序 token 打管理端 | 401/403 | ☐ |

### 19.1 页面「卡在加载中」怎么排查（踩过的坑）

**症状**：页面一直显示「正在整理…」这类 loading 文案，不报错、不出数据、连请求都不发。

**最常见原因**：`Page({...})` 对象里**同名方法写了两次**。对象字面量里后面的键会**静默覆盖**前面那个，不报任何错：

```js
Page({
  onShow() { this.loadData() },                    // ← 被覆盖了
  // ... 几十行之后
  onShow() { if (this.flag) this.loadData() },     // ← 实际生效的是这个
})
```

**历史案例**：`pages/activities/activities.js` 曾因同时存在两个 `onShow`，导致「季节活动」页点进去永远空白、卡在「正在整理校园活动」——后定义的那个只在某个标记为真时才加载，而首次进入该标记是 undefined，于是**一次请求都不发**。

**快速确认**：

```powershell
(Get-Content pages/xxx/xxx.js) | Select-String -Pattern '^\s*onShow\s*\(' | Measure-Object
# 结果应恰好为 1（需要 onShow 的页面）
```

**其他可能原因**（按概率排序）：

| 原因 | 特征 | 确认方法 |
|---|---|---|
| 同名方法覆盖 | 无报错，连请求都不发 | 数同名方法个数 |
| `loading` 置 true 后 finally 未执行 | 请求发了但没回来 | 开发工具 Network 看有没有该请求 |
| `onShow` 里同步抛错 | 有 toast 或红字 | 看控制台 |
| 页面 json 引用了不存在的组件 | 整页白屏 | 控制台报 `usingComponents` |
| 请求卡在鉴权门等待 | 只有私有读接口会 | Network 里状态是 pending |

### 19.2 上线前建议跑一次「同名方法扫描」

```powershell
node -e "const fs=require('fs'),path=require('path');function w(d,o=[]){for(const n of fs.readdirSync(d)){const f=path.join(d,n);const s=fs.statSync(f);if(s.isDirectory()){if(['node_modules','miniprogram_npm','.git','target','dist'].includes(n))continue;w(f,o)}else if(n.endsWith('.js'))o.push(f)}return o}let bad=0;for(const file of [...w('pages'),...w('components')]){const L=fs.readFileSync(file,'utf8').split('\n');let lv=0;const seen=new Map();for(let i=0;i<L.length;i++){const t=L[i].trim();const m=t.match(/^(?:async\s+)?([A-Za-z_\$][\w\$]*)\s*(?:\(|:\s*function\s*\()/);if(m&&!['if','for','while','switch','catch','function','return'].includes(m[1])){const k=lv+':'+m[1];if(seen.has(k)){console.log(file,m[1],'行',seen.get(k)+1,'与',i+1);bad++}else seen.set(k,i)}lv+=(L[i].split('{').length-1)-(L[i].split('}').length-1)}}console.log(bad?'发现 '+bad+' 处':'OK 无重复')"
```

> 脚本按「大括号层级 + 方法名」判断，所以 `pageLifetimes.resize` 与 `methods.resize` 属于不同层级、**不会误报**。
> 但普通函数调用（如 `this.saveHistory()`）可能被误抓，看到结果人工确认一眼即可。
