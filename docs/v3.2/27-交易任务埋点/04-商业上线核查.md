-- 二手成交：已确认 vs 已发分（差额即静默丢分）

## 四、数据与迁移（前置 SQL、执行顺序、回滚 SQL）

**结论：有条件通过（条件：`module-market-trade-v31.sql` 已跑 + `goods.status` 字典含 2）**

### 4.1 前置 SQL 与执行顺序

```text
1) backend/src/main/resources/db/module-points-v31.sql        -- task_catalog/task_log/point_log/user_points/user_growth
2) backend/src/main/resources/db/module-market-trade-v31.sql  -- market_trade（uk_trade_goods）+ goods.status=2 字典
3) backend/src/main/resources/db/module-food.sql              -- 外卖订单表（供 food_order 埋点使用）
4) backend/src/main/resources/db/module-jobs-marketplace.sql  -- 履约合约表（供 job_settle 埋点使用）
```

顺序理由：本功能是**读三张业务表 + 写 `task_log`**，四条前置缺一条，对应场景就无法工作。

### 4.2 幂等性

本功能不新增表，无建表脚本需要幂等处理。但有两个数据前提必须校验：

```sql
-- 三条任务的日上限是否为 2（与设计一致）
SELECT task_key, p_reward, g_reward, daily_cap, enabled FROM task_catalog
WHERE task_key IN ('food_order','job_settle','market_trade');
-- 期望：3 行，daily_cap 均 = 2，enabled 均 = 1
```

### 4.3 回滚

```sql
-- 止血：停用三条交易任务（发分立即停止，30 秒内生效）
UPDATE task_catalog SET enabled = 0
WHERE task_key IN ('food_order','job_settle','market_trade');
```

**注意**：停用后 `PointsService` 返回 `DISABLED`，桥接器吞掉，用户无感但也没分。回滚期间必须在公告里说明，否则用户会以为「交易不发分了」。

已发出的分无法「冲正」——`point_log` 写入后没有冲正接口（详见功能 20）。所以本功能的回滚能力只有「停止未来的发放」，没有「撤销已发的」。

### 4.4 一个必须处理的数据前提

`goods.status = 2`（已售出）是 F10 新增的状态值（`MarketTradeService.java:43-45` 注释）。如果客户端或管理端有硬编码 `status IN (0,1)` 的查询，成交后的商品会从列表里消失或显示异常。**本轮未验证是否有这类硬编码**，登记为未验证项。

## 九、结论

# 不可上线（阻断项：27-01、27-02、27-03）

逐项说明：

1. **27-01 三处埋点只接上 1 处**——这是功能层面的「承诺不存在」。`task_catalog` 已把 `food_order`/`job_settle` 上架，`PointsService.tasks()` 会把它们返回，用户会看到「外卖点单完成 +10」「兼职结算 +5」并为此付出真实行为（点外卖、接兼职），然后拿不到任何分。**这比「没有积分任务」更糟**——它诱导用户做无回报的事。
2. **27-02 唯一接上的埋点没有入口**——二手成交的四个 API 零页面调用。若只修 27-01 不修 27-02，会出现「三处埋点全接上、两处能触发、一处不能」的怪状态，且 `market_trade` 任务依然完不成。**两条必须同轮修**。
3. **27-03 无补偿无对账**——即使三处都接上，交易成功但发分失败时用户拿不到分，且无人知晓。积分是准货币，必须有补偿路径。

放行路径：修完 27-01 ~ 27-03 后**可降级为「有条件上线」**（条件：补 5 条桥接测试；补「任务上架但零发分」告警；评估连接池大小；27-05 的 `catch` 补齐）。

**值得单独说清的一件事**：本功能的**设计质量是全仓库最高的之一**——`AfterCommitPointsAwarder` 把「提交后才发」与「必须 `REQUIRES_NEW`」两个最易错的点都做对了并写清了原因；二手成交的三层反作弊（一商品一成交 + 7 天同对含角色对调 + 日限 2）且与业务分离。问题是**执行力**：设计只落地了 1/3，而注释用现在时写「三个场景都经过这里」，让这个缺口藏了很久。
