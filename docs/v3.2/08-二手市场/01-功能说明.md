## 一、这个功能解决什么问题

校园二手（教材、旧电脑、自行车、小家电）的真实痛点是**信息不对称**：毕业季卖家不知道谁要买，新生不知道谁在卖，中间只有几个微信群。这个功能做三件事：

1. **发布**：学生拍照 + 填标题/价格/成色/分类，经文本与图片审核后进列表。
2. **发现**：按校隔离的列表（异地无法面交，所以默认只看本校），支持"出售/求购"两种模式、分类筛选、分页、收藏、私聊卖家。
3. **确认成交**：买家点「我已买到」→ 卖家点「确认成交」→ 商品置已售，双方各得积分（V3.1 新增 F10）。

**它刻意不碰钱**：没有担保交易、没有线上支付、没有评价体系（`docs/v3.1/交易任务埋点-功能说明与测试手册.md` 记录了这个取舍）。当面交易当面付款，平台只做撮合与积分激励。

## 二、用户看到的样子（小程序端）

### 2.1 浏览路径

| 步骤 | 入口 | 页面 | 关键行为 |
|---|---|---|---|
| 1 | 首页「二手市场」/ 分类 | `pages/market-list/market-list` | 顶部切「出售/求购」，分类横滑，支持"本校/全部学校"切换（默认本校） |
| 2 | 触底加载 | 同上 | `api.getGoodsPage({mode,category,schoolScope,schoolId,page,size})`，按 id 去重追加（`pages/market-list/market-list.js:74`） |
| 3 | 点卡片 | `pages/market-detail/market-detail` | 拉详情 + 上报浏览（`pages/market-detail/market-detail.js:13`） |
| 4 | 看热度 | 同上 | 按"咨询 > 收藏 > 浏览"优先级显示一句热度文案（`pages/market-detail/market-detail.js:39-47`） |
| 5 | 点收藏 | 同上 | `POST /api/goods/{id}/favorite`，返回 `favored` 决定红心 |

### 2.2 发布路径

`pages/market-publish/market-publish`：选图（最多 6 张，先上传拿服务端地址再提交）→ 填标题（1-28 字）/价格（0-99999）/成色/分类/描述（≤200 字）→ `POST /api/goods`。后端再过一遍文本审核 + 图片审核。

### 2.3 小程序端**没有**的东西

- **没有「我已买到」按钮**。`pages/market-detail/market-detail.js` 全文件 113 行，没有一处调用成交接口。
- **没有「确认成交」入口**。个人页「我的发布」跳的是 `pages/user-home/user-home`（`pages/profile/profile.js:120-123`），没有"待确认成交"角标与按钮。
- **没有二手收藏列表**。个人页的「收藏」读的是 `GET /api/users/{id}/favorites`，而那个接口只返回**帖子**收藏（`backend/src/main/java/com/campuslife/service/UserService.java:43-45`，查的是 `favorite` 表的 `post_id`），不返回 `goods_favorite`。
- **没有交易凭证 / 评价 / 举报入口**（详情页只有联系、收藏、删除）。

`docs/v3.1/交易任务埋点-功能说明与测试手册.md:65-95` 详细写了这套 UI 设计（详情页「我已买到」次按钮、"我的发布"角标与两个按钮、7 天互刷提示文案），**代码里一条都没实现**。API 封装倒是写好了（`utils/api/points.js:213-233` 的 `startMarketTrade / confirmMarketTrade / cancelMarketTrade / getMyMarketTrades`，并在 `:242` 导出），但全仓库无任何页面调用它们。

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 发布会被拒绝的情况

| 现象 | 提示 | 证据 |
|---|---|---|
| 标题长度不在 1-64 | 「标题长度须为1至64字」 | `BizService.java:195` |
| 价格非数字 / <0 / >99999 | 「价格格式不正确」/「价格须为0至99999」 | `BizService.java:196-202` |
| 描述 >200 字 | 「描述不能超过200字」 | `BizService.java:204` |
| 图片数为 0 或 >6 | 「请至少上传一张图片」/「图片最多上传6张」 | `BizService.java:220-221` |
| 图片是本地临时路径（`wxfile://`、`http://tmp/`） | 「图片未上传成功，请重新选择图片」 | `BizService.java:151-159, 224-228` |
| 文本审核不通过 | 由 `auditService.rejectWithLog` 抛出 | `BizService.java:229-230` |

发布成功后 `status` 由审核结果决定：通过=1，不通过=0（`BizService.java:246-250`）。商品 `school_id` 取自发布者学校（`BizService.java:252`）。

### 7.2 成交确认的完整规则（`MarketTradeService`）

| 场景 | 结果 | 证据 |
|---|---|---|
| 买自己的商品 | 「不能购买自己发布的商品」 | `MarketTradeService.java:67` |
| 商品不在售（`status != 1`） | 「商品已下架或已售出」 | `MarketTradeService.java:68-70` |
| 已有 `confirmed` 成交 | 「该商品已有成交记录」 | `MarketTradeService.java:75` |
| 已有 `pending` 且是同一个人 | 幂等返回同一笔（`alreadyPending=true`） | `MarketTradeService.java:76-79` |
| 已有 `pending` 且是别人 | 「该商品已有待确认的成交」 | `MarketTradeService.java:80` |
| 上一笔被 `cancelled` | 复用同一行重新发起（唯一键只允许一行） | `MarketTradeService.java:82-86`、`MarketTradeMapper.java:51-58` |
| 非卖家点确认 | 403「只有卖家可以确认成交」 | `MarketTradeService.java:118-120` |
| 已 `confirmed` 再点确认 | 幂等返回（`alreadyConfirmed=true`） | `MarketTradeService.java:122` |
| 已 `cancelled` 再点确认 | 「该成交已取消，不能确认」 | `MarketTradeService.java:123` |
| 非买卖双方取消 | 403「无权取消该成交」 | `MarketTradeService.java:162` |
| 已确认的成交取消 | 「已确认的成交不能取消」 | `MarketTradeService.java:166` |

**发分规则**：双方各得一次 `market_trade`（5P/12G，日限 2 笔）。三层防互刷——一件商品只允许一笔成交（`uk_trade_goods`）、同一对用户 7 天内只计一次（`countRecentPair`）、积分任务日限 2 笔。发分放在事务提交后（`AfterCommitPointsAwarder`），积分服务异常不影响成交结果（`MarketTradeService.java:194-214`）。

### 7.3 没有补偿，因为不涉及资金

二手全程不经手钱：成交确认只改状态与发分，没有支付、没有退款、没有担保。因此本功能**不存在资金补偿路径**，也不应该有。

代价是：**成交一旦确认就无法撤销**。`uk_trade_goods` 让一件商品只能有一笔成交记录，`confirmed` 是终态（`MarketTradeMapper.java:61-66` 的 UPDATE 只从 `pending` 出发）。若卖家误点确认、或双方谈崩，商品会永久停在 `status=2`，重新上架后也无法再发起成交（因为已有 `confirmed` 记录）。
