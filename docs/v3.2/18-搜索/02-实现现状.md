### 已跑（本次，L2）

```bash
node tools/check-all.js
```

- 结果 **9/9 通过**。对本功能的意义：`pages/search` 的 `bindtap` 方法齐全、`api.searchAll` 导出存在、"接口对账"项确认 `/search/all` 后端存在。

### 未跑（不冒充结论）

| 项 | 为什么没跑 | 补验命令 |
|---|---|---|
| SQL 注入实测 | 读码已确认全参数绑定，无需实测 | 传 `keyword=' OR 1=1--`，预期当作字面量搜索、返回 0 条而非全表 |
| 已下架岗位是否被搜到 | 需造数据 | `UPDATE job SET workflow_status='cancelled' WHERE id=1;` 然后 `curl 'localhost:8080/api/search/all?keyword=<该岗位关键词>&type=job'`，看是否命中 |
| 已下架店铺是否被搜到 | 需造数据 | `UPDATE shop SET status=0 WHERE id=1;` 然后搜该店名，看是否命中 |
| `%` 是否全命中 | 需连库 | `curl 'localhost:8080/api/search/all?keyword=%25&type=post'` 对比 `keyword=不存在的词` |
| 混排条数上限 | 需有数据 | 造 ≥50 条帖子后搜通用词，数"全部" tab 的卡片数（预期 ≤21） |
| 全表扫耗时 | 无压测环境 | `EXPLAIN` 看 `type` 是否为 `ALL`：`db_explain` 或 `EXPLAIN SELECT ... WHERE title LIKE '%台灯%'` |
| 跨校内容混出 | 需多校数据 | 用 A 校账号搜一个只在 B 校存在的商品名 |
