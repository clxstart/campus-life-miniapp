## 一、这个功能解决什么问题

积分只有"能花出去"才有意义。这个功能做三件事：

1. **把积分换成券**（兑换池 → `reward_item` → `coupon`），并保证"扣分 / 发券 / 扣库存 / 写记录"四件事要么全成、要么全不成 —— 证据 `backend/src/main/java/com/campuslife/service/RewardService.java:19-29`（类注释）、`RewardService.java:71-126`。
2. **券有生命周期**：可用(1) → 下单锁定(2) → 支付核销(3)；取消释放回 1；退款作废为 0 —— 证据 `backend/src/main/java/com/campuslife/service/CouponService.java:17-23`、`CouponService.java:52-88`。
3. **新人礼包**：注册即 30P + 7 天白银体验，这是"首次兑换从 20–30 天压到 2–3 天"的留存前提 —— 证据 `backend/src/main/java/com/campuslife/service/AuthService.java:147-164`、`docs/v3.1/新人礼包与积分兑换-功能说明与测试手册.md:19`。

口径红线：**100 积分 = 1 元，券面额 `value_cents` 严格等于 `price_p`（分），只抵外卖（scope=takeout），平台补贴、商家按原价结算** —— 证据 `db/module-reward-v31.sql:3-6`、`RewardService.java:91`、`CouponService.java:41-42`、`BizService.java:642`。

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 兑换会拒绝的情况

| 情况 | 拒绝方式 | 证据 |
|---|---|---|
| 商品下架 | `IllegalArgumentException("该商品已下架")` | `RewardService.java:74` |
| 超过每人限购 | `IllegalArgumentException("每人限兑 N 件")` | `RewardService.java:78` |
| 库存为 0 | `IllegalArgumentException("该商品已兑完")` | `RewardService.java:79` |
| 并发抢最后一件 | `decreaseStock` 返回 0 行 → `IllegalArgumentException("手慢了，刚刚被兑完")` | `RewardService.java:80`、`RewardMapper.java:37-38` |
| 积分不足 | `spend()` 返回 false → `IllegalArgumentException("积分不足，还差 N 分")` | `RewardService.java:107-109` |
| 同一条扣分重复提交 | `spend()` 捕 `DuplicateKeyException` 抛 `IllegalStateException("这笔操作已经处理过了")` | `PointsService.java:159-164` |

**任一步失败整体回滚**：四件事在同一个 `@Transactional` 里（`RewardService.java:71`），不会出现"扣了分没券"或"发了券没扣分"。

### 7.2 券的四种状态与本功能的关系

| 迁移 | 触发方 | 方法 | 证据 |
|---|---|---|---|
| — → 1（可用） | 兑换成功 / 宿舍发券 | `RewardService.redeem`、`DormMapper.grantCoupon` | `RewardService.java:95`、`DormMapper.java:244-249` |
| 1 → 2（锁定） | 下单，且只允许"仍可用"命中 | `CouponService.lock` | `CouponService.java:53-61`、`BizService.java:667-669` |
| 2 → 3（核销） | 支付成功 | `CouponService.useByOrder` | `CouponService.java:64-70`、`PaymentLedgerService.java:112` |
| 2 → 1（释放） | 关单/超时/取消 | `CouponService.releaseByOrder` | `CouponService.java:73-80`、`PayService.java:313`、`:335`、`:346`、`MerchantService.java:232` |
| 2/3 → 0（作废） | 退款 | `CouponService.voidByOrder` | `CouponService.java:83-88`、`MerchantRefundStatusService.java:150` |

**锁定有超时兜底**：支付对账任务每 `60s` 扫一轮，超时未付的单会被关单并 `releaseByOrder`，所以"下单不付款永久占券"不会发生 —— 证据 `PayService.java:273-279`、`PayService.java:305-352`、`UserOrderMapper.java:67-77`（扫 `pay_status='unpaid' AND status='created'`）。这是本功能最扎实的一处设计。

### 7.3 券的可用性判定（下单时）

`CouponService.usable()` 依次检查：归属本人 → `status=1` → 未过期（`expire_on`）→ `scope=takeout` → 达门槛（`threshold_cents`）→ `value_cents > 0` —— 证据 `CouponService.java:33-50`。抵扣额再被"商品应付（扣除店铺折扣后）"封顶，不会把订单金额抵成负数 —— 证据 `BizService.java:640-645`。

### 7.4 会补偿 / 不会补偿

- **会补偿**：关单释放券（`PayService.java:313` 等 4 处）、退款作废券（`MerchantRefundStatusService.java:150`）、库存条件更新防超卖（`RewardMapper.java:37-38`）。
- **不会补偿**：退款**不退券**（设计决定："平台补贴是真实支出，退券会造成循环套利" —— `CouponService.java:82`）；兑换**不可退**（前端文案"兑换后不可退" `pages/points-redeem/points-redeem.js:128`，后端无撤回接口）。
- **不会补偿（问题）**：宿舍发券失败只 `log.warn`，无重试、无台账（`DormService.java:427-430`）。
