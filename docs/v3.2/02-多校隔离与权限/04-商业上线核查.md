## 一、合规与隐私

**结论：不通过（原因：多校隔离是本平台对学校客户的合同级承诺，当前 7 处写接口可跨校，无法向学校客户出具「数据隔离」说明）。**

| 检查项 | 结论 | 证据 |
|---|---|---|
| 是否向学生明示「可跨校浏览内容」 | 不通过：隐私政策/用户协议只写「面向高校在校学生」，未提「你看到的内容可能来自其他学校」 | `pages/agreement/agreement.js:11-60` |
| 学校数据是否与合同承诺一致 | 不通过：列表层隔离成立，单条写操作 7 处缺口 | 见 `03-优缺点与问题.md` 02-01..02-07 |
| 用户能否知道自己属于哪个学校 | 部分：小程序「我的」显示学校字符串，但 `school_id` 可能与字符串不一致（建号硬编码） | `AuthService.java:132`、`User.java:15-17` |
| 学校客户的审计权（谁改了我的数据） | 不通过：`admin_log` 无 `school_id`，且 48 个管理端写接口只有 2 个控制器写日志 | `db/module-multischool-admin.sql:41-53`、`AdminModuleController.java:461-465` |
| 个人信息跨主体流转 | 不通过：校管可读全校用户列表（含昵称/学校/注册时间），但无「校管不得导出用户清单」的约束与记录 | `AdminModuleController.java:196-203`、`AdminModuleMapper.java:100-111` |

**必须补的合规动作**：给学校客户的《数据处理协议》里不能写「数据完全隔离」，只能写「平台方按功能需要可跨校访问」；否则 02-01..02-07 就是违约证据。

## 二、资金与对账

**结论：不涉及直接资金（依据：本功能不写钱包、不下单、不退款）。但有一条间接资金链路必须单列。**

- 榜单重结算会发分：`POST /api/admin/forum-rank/resettle` 由校管可触发（`AdminForumRankController.java:42-49`），发分走积分账本 → 券 → 消费抵扣，间接影响成本。幂等键保证不重复发（`ForumRankService.resettle` 只补 `awarded=0`），但没有「谁触发的」审计记录。
- 报名审核通过会改报名人数（`BizService.java:524-527`），若该活动收费则影响对账口径；当前活动模块无收费字段，暂不影响。
- 订单/支付流水的导出按 `(schoolId, role)` 下推（`AdminOrderController.java:37-38`、`AdminPaymentController.java:63-64`），服务层是资金隔离的唯一正确实现范本——**建议其余模块照抄这个签名**。

## 三、权限与越权

**结论：不通过（原因：7 条 P0 越权 + 3 条全局配置越权）。**

| 越权类型 | 实例 | 等级 |
|---|---|---|
| 跨校写（校管 → 他校数据） | banner 改/删、活动状态、商品状态、圈子编辑、学期编辑、报名 approve/reject、报名设置 | P0 ×7 |
| 越级写（校管 → 全平台配置） | 敏感词表、AI 规则/欢迎语、榜单重结算 | P1 ×3 |
| 越级读（校管 → 全平台数据） | 系统状态（含全平台计数）、前端错误明细 | P1 ×2 |
| 前端隐藏当权限 | `meta.superOnly` 只过滤菜单，路由不拦（`router/index.js:82-101`） | P2 |
| 超级管理员 | 无越权（超管本来就该全平台） | — |
| 商家/骑手 | 已隔离：路径 + 角色双门（`AdminInterceptor.java:57-67`、`RiderInterceptor.java:26`） | 通过 |

**验证方式（上线前必做）**：建两个学校（A/B）、两个校管账号，逐条跑 7 个用例，期望全部 403。当前预期是全部 200。

## 四、数据与迁移（前置 SQL、执行顺序、回滚 SQL）

**结论：有条件通过（条件：必须按顺序执行，且索引缺失要在数据量上来前补）。**

执行顺序：

```sql
-- 1) 学校表 + admin_user + admin_log + 业务表 school_id 列 + 回填
--    db/module-multischool-admin.sql
-- 2) admin_user.token_version（必须在 1 之后，AdminMapper 硬依赖）
--    db/module-commerce-consistency.sql:55-56
-- 3) 每校自定义地点（外键式依赖 school 表）
--    db/module-school-location.sql
-- 4) 补隔离索引（建议与上线同批次，避免上线后追加 DDL 锁表）
--    ALTER TABLE goods           ADD INDEX idx_goods_school (school_id, status);
--    ALTER TABLE job             ADD INDEX idx_job_school (school_id, status);
--    ALTER TABLE campus_activity ADD INDEX idx_activity_school (school_id, status);
--    ALTER TABLE shop            ADD INDEX idx_shop_school (school_id, status);
--    ALTER TABLE banner          ADD INDEX idx_banner_school (school_id, status);
--    ALTER TABLE academic_term   ADD INDEX idx_term_school (school_id);
```

回滚：

```sql
-- 索引可安全回滚
ALTER TABLE goods DROP INDEX idx_goods_school;   -- 其余同理
-- 列不要回滚：业务代码已依赖，回滚列等于回滚整个版本
```

**数据风险点**

1. `UPDATE ... SET school_id = 1 WHERE school_id IS NULL`（`module-multischool-admin.sql:112-117`）是一次性归属推定。若生产库在执行前已有多校真实数据，会把它们全归到 1 号校——**执行前必须备份并人工确认这 6 张表里没有他校数据**。
2. `INSERT IGNORE INTO school(name, city) SELECT DISTINCT school FROM user`（`:103-104`）会把 `user.school` 字符串里所有脏值（空串已排除，但「内蒙古大学 计算机学院」这类）都建成学校。
3. 迁移后 `user.school`（字符串）与 `user.school_id` 并存且可能不一致；`module-multischool-admin.sql:107-108` 只回填一次，之后新用户不再同步（`AuthService.java:132` 只写字符串）。**上线后立刻会出现两套事实。**

## 五、性能与容量

**结论：有条件通过（条件：补 6 个 `school_id` 索引；管理端每请求多一次主键查询可接受）。**

| 项 | 数据 | 证据 | 判断 |
|---|---|---|---|
| 管理端每请求查一次 `admin_user` | 1 次主键查询 | `AdminTokenGuard.java:34-52` | 后台 QPS 低，通过 |
| 看板 6 个子查询 | 每次打开看板 6 个 COUNT + 1 个趋势查询 | `AdminModuleMapper.java:13-24` | 单校数据量小时通过；10 万+ 用户后需缓存 |
| 列表按 `school_id` 过滤缺索引 | `goods/job/campus_activity/shop/banner/academic_term` 无 `school_id` 索引 | `module-multischool-admin.sql:119-130` | 全表扫，数据量线性劣化 → P2 |
| 圈子列表分页 | 已分页 + `LIMIT`，防一次拉全库 | `AdminModuleService.java:578-583` | 通过 |
| 学期/地点列表 | 不分页（`schoolLocations`、`terms` 直接返回全量） | `AdminModuleService.java:516-519, 675` | 每校百级数据量，通过 |
| 越权校验的额外查询 | 每次单条操作多 1-2 次 brief 查询 | `AdminModuleService.java:118-121` 等 | 已修的那些接口成本可接受，说明「补校验」不会明显拖慢 |

**未验证**：管理端并发（多校管同时刷新看板）、单校 10 万用户时的看板耗时。台账未登记，属于漏登记。

## 六、可观测与告警

**结论：不通过（原因：越权尝试不会留下任何痕迹，事后无法追查）。**

| 检查项 | 现状 | 证据 |
|---|---|---|
| 越权被拒是否记日志 | 不记：`ForbiddenException` 由全局异常处理器统一转 403，不写库、不告警 | `config/GlobalExceptionHandler.java`、`config/ForbiddenException.java` |
| 越权成功（当前 7 处）是否可能被发现 | 不可能：这些接口连 `admin_log` 都不写（`updateBanner`/`deleteBanner`/`setActivityStatus`/`setGoodsStatus` 的控制器层有 `log(...)`，但日志只记「编辑店铺」这类动作，**不记 school_id 差异**） | `AdminModuleController.java:409-421, 344-350, 377-383` |
| 是否有「跨校访问」计数指标 | 无 | 全仓无 MeterRegistry |
| 申诉/取证能力 | 弱：`admin_log` 有 adminId/ip/detail，但无 school_id、无请求参数快照 | `db/module-multischool-admin.sql:41-53` |

**缺什么**：① `ForbiddenException` 落一条 `security_denied` 日志（谁、从哪个校、想动哪个校的哪个 id）；② 同账号短时间内多次 403 → 告警；③ 补 `admin_log.school_id`。

## 七、失败与降级（依赖挂了会怎样）

| 依赖 | 挂了的表现 | 是否可接受 | 证据 |
|---|---|---|---|
| MySQL（令牌状态查询） | 所有管理端请求 503「鉴权服务暂不可用」 | 可接受（宁可不可用不可越权） | `AdminInterceptor.java:48-51` |
| `admin_user.school_id` 被误清空 | 该校校管下次请求 401「权限已变更」；重新登录被拒「尚未绑定学校」 | 可接受，但停服面是整校 | `AdminTokenGuard.java:49`、`AdminAuthService.java:45-47` |
| `school` 表被清空/停用 | 超管仍可操作；校管的 `schoolId` 仍在 token 里，但关联名称显示为空 | 部分可接受 | `AdminInterceptor.java:75-77` |
| 索引缺失 + 数据量大 | 列表页超时，前端显示「加载失败」 | 不可接受（体验） | 见第五节 |
| Redis（cluster 限流） | 503（fail-closed） | 可接受 | `RateLimiter.java:52-57` |

**没有降级预案的地方**：如果上线后发现某校数据串到另一校（例如回填脚本跑错），没有「按 school_id 回滚归属」的脚本——只能手工逐表 UPDATE。

## 八、开关与回滚（怎么关、怎么退、数据怎么退）

| 开关 | 默认 | 效果 | 证据 |
|---|---|---|---|
| 无「多校隔离」总开关 | — | 隔离是硬逻辑，改不了也不能关 | — |
| `campus.auth.enforce` | true | 关掉会连用户鉴权一起废掉，**不能用来兜底隔离问题** | `ProductionConfigValidator.java:53-55` |
| 功能开关（`feature_flag`） | 按 key | 可按校关某个功能入口，但**不能关「跨校写」** | `FeatureFlags.java:37-56` |
| 数据级处置 | — | 只能改 `admin_user.school_id` 把人调走，或停用账号 | `AdminMapper.java:86` |

**回滚方案**

1. **代码回滚**：可行，隔离逻辑不改变表结构。
2. **止血手段（发现越权被利用时）**：① 停用涉事校管账号（`POST /api/admin/admins/{id}/status`，立即递增 token_version 使旧令牌失效）；② 用 `admin_log` 的 `admin_id + created_at` 拉出该账号所有操作，逐条核对被改记录；③ 被改的 `banner.school_id` 只能靠备份恢复，**没有变更前快照**。
3. **数据回退**：`school_id` 回填脚本没有反向脚本。上线前必须对 `post/circle/goods/job/campus_activity/shop/banner/academic_term` 七张表做一次 `mysqldump` 快照，写入上线清单。
4. **不可回退项**：`banner`/`activity`/`goods` 的 `DELETE` 是物理删除（`AdminModuleService.java:786`、`:242`、`:385`），删了没有回收站。

## 九、结论

**不可上线。**

阻断项（全部为 P0）：

- 02-01 `PUT /api/admin/banners/{id}` 无校校验且可改 schoolId
- 02-02 `DELETE /api/admin/banners/{id}` 无校校验
- 02-03 `POST /api/admin/activities/{id}/status` 无校校验
- 02-04 `POST /api/admin/goods/{id}/status` 无校校验
- 02-05 `PUT /api/admin/circles/{id}` 收了 scope 但未使用
- 02-06 报名 approve/reject 无校校验
- 02-07 `PUT /api/admin/terms/{id}` 无校校验

这 7 条修完（预计 3.5 人日）并补上越权回归测试后，可转为**有条件上线**，条件为：02-08、02-09、02-11、02-12 四条 P1 在上线前修完（全局配置与跨校读）。
