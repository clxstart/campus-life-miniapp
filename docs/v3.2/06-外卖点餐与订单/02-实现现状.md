## 二、后端：逐条核对

### 2.1 服务端定价（核心正确性）

- [✅] **请求体不接受金额**——DTO 只有 `goodsId/count/address/contactPhone/couponId/idempotencyKey`，没有任何 `total/price/amount` 字段 —— 证据：`backend/src/main/java/com/campuslife/dto/CreateOrderRequest.java:3-16`
- [✅] **商品价格从库读，不用客户端的** —— 证据：`backend/src/main/java/com/campuslife/service/BizService.java:624-631`（`goodsMapper.selectList(...)` 后 `g.getPrice().multiply(count)`）
- [✅] **商品必须属于该店铺且上架** —— 证据：`BizService.java:624-625`（`eq(ShopGoods::getShopId, shop.getId())` + `goods.size() != counts.size()` 报错）
- [✅] **打包费写死常量 2.00 元** —— 证据：`BizService.java:53`（`PACKING_FEE = new BigDecimal("2.00")`）、`:645`
- [✅] **金额上限保护** —— 证据：`BizService.java:646`
- [🟠] **满减读的是 `discount_threshold/discount_amount` 两列** —— 证据：`BizService.java:634`；但写这两列只有商家端一个入口（见 2.2）

### 2.2 满减字段的两条写入口（一条假一条真）

- [🔴] **管理端新建店铺不写满减两列** —— `AdminModuleService.shopRow()` 只回填 9 个字段，不含 `discountThreshold/discountAmount` —— 证据：`backend/src/main/java/com/campuslife/service/AdminModuleService.java:388-400`
- [🔴] **管理端 INSERT 语句只有 11 列，且不含满减两列** —— 证据：`backend/src/main/java/com/campuslife/mapper/AdminModuleMapper.java:455-462`。列默认值是 0（`module-food.sql:8`：`discount_threshold DECIMAL(10,2) NOT NULL DEFAULT 0`、`discount_amount ... DEFAULT 0`）
- [🔴] **管理端 UPDATE 语句也不改满减两列** —— 证据：`backend/src/main/java/com/campuslife/mapper/AdminModuleMapper.java:464-470`
- [✅] **商家端 PUT /api/merchant/shop 才写这两列** —— 证据：`backend/src/main/java/com/campuslife/mapper/MerchantMapper.java:119-127`（`discount_threshold=#{discountThreshold}, discount_amount=#{discountAmount}`）+ `backend/src/main/java/com/campuslife/service/MerchantService.java:150-151`
- [✅ 实测] **库里已有一条不一致的店铺** —— 见本节 2.6 的实跑输出：`shop id=5` 文案「满20减5」而两列均为 0.00
- [✅ 实测] **该店可确认是管理端建的** —— `shop id=5` 的 `owner_name / intro / contact_phone / address` 四个字段全为空串且 `rating=4.8`，这正是 `AdminModuleMapper.insertShop` 的落库特征（它插 `#{rating}`、其余留默认空串，`MerchantMapper.insertMerchantShop` 则会写入 `ownerName/intro/contactPhone/address`）；同时 `select count(*) from merchant_apply` 为 0，即系统里还没有任何商家入驻申请。所以这家店一定是走 `/api/admin/shops` 建的，之后在管理端填了「优惠说明」，满减两列始终为 0
