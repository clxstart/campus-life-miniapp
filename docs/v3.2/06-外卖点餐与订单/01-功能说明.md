## 一、这个功能解决什么问题

校园内食堂/奶茶/小超市在饭点排队十分钟、下课晚就没饭。这个功能把"学生走到窗口点单"换成"手机下单 + 商家接单 + 骑手送到楼下"，把线下排队时间换成交付时间。

业务上它必须同时回答三个问题，缺一个就不可用：

1. **这一单收多少钱**——商品小计、满减、打包费、配送费、优惠券抵扣谁说了算。答案必须是服务端：`backend/src/main/java/com/campuslife/dto/CreateOrderRequest.java:3-16` 的请求体里**没有任何金额字段**，只有 `shopId / items[{goodsId,count}] / address / contactName / contactPhone / remark / idempotencyKey / couponId`。
2. **这一单现在到哪一步**——`created → paid → accepted → delivering → picked → completed`，状态机定义在 `backend/src/main/java/com/campuslife/service/OrderStatus.java:15-47`。
3. **这一单钱对不对得上**——支付流水 `payment_record`、退款流水 `refund_record`、订单 `user_order` 三张账必须能互相核对（核对规则属 07 支付与退款，本文只列订单侧字段）。

## 二、用户看到的样子（小程序端）

### 2.1 完整操作路径

| 步骤 | 入口 | 页面文件 | 关键行为 |
|---|---|---|---|
| 1 | 首页「外卖」/ 分类 | `pages/food-list/food-list` | `api.getFoodShops(category, schoolScope, schoolId)`，按校范围拉店铺；`schoolScope=local` 只看本校 |
| 2 | 点某个店铺卡片 | `pages/food-shop/food-shop` | 用 `schoolScope='all'` 再拉一次店铺信息（`pages/food-shop/food-shop.js:34-37`），按 id 命中后才渲染菜单 |
| 3 | 分类切换 + 加减数量 | 同上 | `changeCount()` 上限 99 份/种；店铺 `isOpen=false` 时点加号直接 toast「本店休息中，暂时不能下单」(`pages/food-shop/food-shop.js:73`) |
| 4 | 点「去结算」 | 同上 | 把 `{shopId, shopName, items[{goodsId,name,price,count}]}` 写进本地缓存 `pending_order`，再 `navigateTo` 结算页（`pages/food-shop/food-shop.js:107-112`） |
| 5 | 结算页确认地址/备注 | `pages/food-order/food-order` | 地址来自 `api.getAddresses()`，可弹窗新增地址；起送未达时按钮拦在 `pages/food-order/food-order.js:45` |
| 6 | 点「提交订单」 | 同上 | `api.createFoodOrder(...)` → 拿到 `orderId` → 立刻 `api.payOrder(orderId)`（`pages/food-order/food-order.js:53-60`） |
| 7 | 微信收银台 | 同上 | `payParams.simulated === true` 说明后端走模拟支付（`pages/food-order/food-order.js:67`），否则 `wx.requestPayment` |
| 8 | 支付结果确认 | 同上 | 轮询订单详情最多 10 次 × 2 秒，拿到 `payStatus=paid` 后跳订单详情（`pages/food-order/food-order.js:91-105`） |
| 9 | 查看进度 | `pages/food-order-detail/food-order-detail` | 每 3 秒轮询一次，终态 `completed/cancelled/refunded` 停止（`pages/food-order-detail/food-order-detail.js:26-32`） |
| 10 | 历史订单 | `pages/food-orders/food-orders` | `api.getFoodOrders(1,50)`，下拉刷新 + `onShow` 自动重载 |

### 2.2 小程序端**没有**的东西（这是本功能最大的现状缺口）

- **没有「取消订单」按钮**，也没有 `POST /api/orders/{id}/cancel` 的任何前端封装。`utils/api/market.js:22-40` 是外卖接口的全部封装，其中只有 `createFoodOrder / getFoodOrders / getFoodOrderDetail / payOrder / getOrderDetail / getFoodOrder`。
- **没有「申请退款」按钮**，同理缺 `POST /api/orders/{id}/refund`。
- **没有优惠券选择**：结算页 `pages/food-order/food-order.js:53` 的请求体里从来没有 `couponId` 字段；`utils/food.js:4-11` 的 `bill()` 计算式里也没有券抵扣项。个人页只有"看券"（`pages/profile/profile.js:290-298` 弹一个 sheet 显示"到店出示即可使用"），没有"下单时用券"。
- **没有「我的发布/成交」之外的售后入口**：订单详情页（`pages/food-order-detail/food-order-detail.wxml:2,5`）只有「返回」和「刷新」两个可点元素。

结论：小程序端能"下单 + 付款 + 看进度"，**不能取消、不能退款、不能用券**。

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 下单会被拒绝的情况（服务端判定，逐条带证据）

| 现象 | 拒绝原因 | 证据 |
|---|---|---|
| 店铺 `status != 1` | 「店铺不存在或已休息」 | `BizService.java:93-97` |
| 店铺 `is_open=0` 或不在营业时段 | 「这家店当前休息或不在营业时间内」 | `BizService.java:616` + `:80-91` |
| 商品不属于该店铺 / 已下架 | 「部分商品已下架或不属于该店铺」 | `BizService.java:624-625` |
| 单种商品累计 > 99 | 「单件商品最多购买99份」 | `BizService.java:618-623` |
| 商品小计 < 起送价 | 「未达到起送金额」 | `BizService.java:633` |
| 券不是本人的 / 已用 / 已过期 / 非外卖范围 / 未满门槛 / 面额为 0 | 对应 6 种中文提示 | `CouponService.java:33-49` |
| 券被并发订单抢走 | 「优惠券已被使用或已失效，请重新选择」 | `BizService.java:667-669` |
| 订单金额 > 99999999.99 | 「订单金额超出限制」 | `BizService.java:646` |
| 同一幂等键对应订单已关闭/取消 | 「上一笔订单已关闭，请重新提交订单」 | `BizService.java:604-606` |

### 7.2 金额计算规则（唯一口径，服务端）

```
subtotal        = Σ(goods.price × count)               // BizService.java:630
discount        = subtotal >= shop.discount_threshold
                    ? min(shop.discount_amount, subtotal) : 0    // :634
couponDiscount  = min(coupon.value_cents/100, subtotal - discount)  // :640-642
total           = subtotal - discount - couponDiscount + 2.00(打包) + shop.delivery_fee  // :644-645
payAmountCents  = round(total × 100)                    // :660
```

- 起送门槛按**优惠前**小计判断（`:633`），与小程序 `utils/food.js:10` 的 `missing` 口径一致。
- 券面额不会超过"小计减满减"，即**运费与打包费永远不能用券抵扣**（`:642` 的 `.min()`）。
- `payAmountCents` 是支付渠道唯一认的金额；`total` 只用于展示。

### 7.3 补偿与幂等

- **下单幂等**：`idempotency_key` 唯一键 `uk_order_user_idem(user_id, key)`（`module-commerce-consistency.sql:47-50`），撞键后改用当前读回对方订单（`UserOrderMapper.java:90-96`）。
- **支付入账幂等**：同一 `transaction_id` 只入一条 `payment_record`（`module-payment.sql:41` 唯一键），订单用 `markPaidIfUnpaid` 条件更新（`UserOrderMapper.java:22-27`）。
- **超时关单**：对账任务 5 分钟后开始向渠道核验、15 分钟关单、渠道持续不可达 120 分钟强制本地关单（`PayService.java:255-259`）。关单同时释放锁定的券（`CouponService.java:73-80`）。
- **关单后到账**：登记 `payment_exception(kind=PAID_AFTER_CLOSE)` 并由补偿任务自动退款（属 07）。
