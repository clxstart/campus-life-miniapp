**结论：有条件通过（条件：迁移必须按固定顺序执行，且新环境种子店铺 5 的满减两列为 0）。**


## 九、结论

**有条件上线。**

上线前必须完成的阻断项：

1. **06-01（P0）满减双源**——管理端必须能写 `discount_threshold/discount_amount`，且展示文案由后端按数值生成。修复前，只要运营在 Web 管理端动过店铺优惠，就会对用户多收钱，属价格误导。
2. **06-02（P1）小程序无取消/退款入口**——接口具备而入口缺失，"下错单只能打电话"会直接变成运营工单。
3. **06-03（P1）券链路断开**——要么上线前把券的展示一并摘掉（避免"有券不能用"），要么补齐小程序选择入口 + 修 `DormMapper.grantCoupon`。
4. **06-04（P1）停用店铺订单消失**——上线后第一个停业的商家就会触发无法退款。
5. **06-05（P1）时区口径**——统一到 `Asia/Shanghai`，成本 0.5 人日，不做等于在生产机上赌时区。

P2 四项（06-06~06-09）可上线后迭代，其中 06-07（弱网假成功）建议与本次一起修，因为它是"用户以为下单成功"类问题。

   ```bash
   java -XshowSettings:properties -version 2>&1 | grep user.timezone
   ```
   预期：`user.timezone = Asia/Shanghai`。不是的话先修代码或加 JVM 参数 `-Duser.timezone=Asia/Shanghai`。

2. **修 06-01，并跑一致性核对**（修复后此查询必须返回 0 行）
   ```bash
   mysql -h127.0.0.1 -uroot -p*** --default-character-set=utf8mb4 campus_life -e "
   SELECT id,name,discount,discount_threshold,discount_amount FROM shop
   WHERE discount_amount > 0 AND (
     discount NOT LIKE CONCAT('%满', TRIM(TRAILING '.00' FROM CAST(discount_threshold AS CHAR)), '减%')
     OR discount NOT LIKE CONCAT('%减', TRIM(TRAILING '.00' FROM CAST(discount_amount AS CHAR)), '%')

   ```
