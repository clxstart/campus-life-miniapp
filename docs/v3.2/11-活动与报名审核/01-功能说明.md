## 一、这个功能解决什么问题

校园里每年有大量"要筛人"的活动：歌手大赛要伴奏、辩论赛要报名表、志愿者要身份证明。原来点一下"报名"就完事，主办方拿不到任何材料，也没法拒绝人。

这个功能给每个活动**单独**选择报名模式：

- `simple`：一键报名，立刻成功，报名数 +1（老活动默认，行为不变）。
- `material`：填表（姓名/学号/电话/自我介绍）+ 上传 1–N 份材料 → 落 `pending` → 管理员逐个通过/驳回 → **通过后**报名数才 +1。

设计来自 `docs/bug1.md` 第 3 条（"报名不应该跳转到页面上传一些东西吗"），方案 C。

## 二、用户看到的样子（小程序端）

路径 A（一键报名）：

1. 首页「季节活动」或底部导航 → `pages/activities/activities`（`pages/index/index.js:13`）；
2. 列表分页 20 条，支持「本校/全部」切换（`pages/activities/activities.js:28-33`、`:75-80`）；
3. 点「报名」→ 直接 `POST /api/activities/{id}/enroll` → toast「报名成功」，本地把 `enrolled+1`、`enrolledByMe=true`（`pages/activities/activities.js:58-68`）；
4. 已报名的人按钮不再响应（`if (!item || item.enrolledByMe ...) return`，`pages/activities/activities.js:49`）。

路径 B（材料报名）：

1. 列表里 `enrollMode==='material'` 的活动，点报名 → 跳 `pages/activity-enroll/activity-enroll?id=x`（`pages/activities/activities.js:53-56`）；
2. 报名页**先拉一次完整活动列表再前端 find** 这条活动，拿 `enrollMaxFiles`（`pages/activity-enroll/activity-enroll.js:35-50`）；
3. 填姓名/学号/电话/自我介绍，选材料（只支持图片/视频，`wx.chooseMedia`，`activity-enroll.js:66-74`）；
4. 每份材料走 `api.uploadImage` 逐个上传，任一失败整体失败（`activity-enroll.js:79-86`）；
5. 提交 → `enrollActivityWithForm` → 后端落 `pending` + 材料表 → 返回 `enrollId`（`activity-enroll.js:114-123`）；
6. **之后就没有了**：学生端没有「我的报名」页，列表接口虽然返回 `myEnrollStatus`（`ModuleMapper.java:184`），页面从不渲染 → 学生看不到"待审核/已驳回/驳回原因"。

| POST | `/api/admin/enrollments/{id}/reject` | 管理端 token | 驳回，必填原因 | `AdminEnrollmentController.java:48-56` |
| PUT | `/api/admin/activities/{id}/enroll-config` | 管理端 token | 改报名模式/须知/材料上限 | `AdminEnrollmentController.java:58-74` |

## 五、数据表与字段

| 表 | 关键字段 | 用途 | 谁写 |
|---|---|---|---|
| `campus_activity` | `enrolled`（报名人数）、`status`、`school_id`、`user_id`、`enroll_mode`、`enroll_hint`、`enroll_max_files` | 活动主体与报名配置 | 学生发布或运营新建 |
| `activity_enroll` | `status`（pending/approved/rejected）、`real_name`、`student_no`、`phone`、`remark`、`audit_reason`、`audited_at`、`audited_by`、唯一键 `uk_enroll(activity_id,user_id)` | 报名记录 | 学生写基础字段，管理员写审核字段 |
| `activity_enroll_material` | `enroll_id`、`url`、`file_name` | 材料（一报名多文件） | 学生提交时写 |

迁移脚本：`backend/src/main/resources/db/module-activity-enroll.sql`（活动 3 字段 + 报名 8 字段 + 材料表 + `idx_enroll_status`）。

**表里没有的东西**（这才是关键）：

- `campus_activity` **没有名额字段**（无 `quota`/`max_people`）——`module-market-jobs-activities.sql:48-56` 建表只有 `id/title/poster/time_desc/location/enrolled/status`，后续迁移也没加。所以"名额超卖"在当前数据模型下不是一个 bug，而是"根本没有名额这回事"。
- `campus_activity` **没有审核字段**（无 `audit_status`）——活动发布即上线。
- `activity_enroll` **没有取消状态**（无 `cancelled`），也没有取消接口。

## 七、业务规则与边界（什么情况会拒绝、什么情况会兜底）

| 场景 | 现状 | 证据 |
|---|---|---|
| 重复报名（一键） | 先查重 + 唯一键兜底，提示「已经报名过啦」 | `BizService.java:415`、`:427-431`、`module-market-jobs-activities.sql:63` |
| 活动不存在 | 「活动不存在或已结束」 | `BizService.java:413` |
| 活动已下架（`status=0`）+ 一键报名 | `incrementEnrollment` 带 `AND status=1`，返回 0 → 抛错，事务回滚 | `ModuleMapper.java:300`、`BizService.java:432` |
| 活动已下架 + **材料报名** | **不校验 `status`**，能提交成功、落 `pending` | `BizService.java:437-489`（全程无 status 判断） |
| 材料少于 1 份 | 拒绝「请至少上传 1 份材料」 | `BizService.java:458` |
| 材料超过活动上限 | 拒绝「最多上传 N 份」 | `BizService.java:457-459` |
| 材料地址不是 `/uploads/` 或 `http` 开头 | 拒绝「材料必须是已上传成功的文件」 | `BizService.java:462-464` |
| 材料功能开关关闭 | **静默降级为一键报名**，只打一条 warn 日志 | `BizService.java:418-424` |
| 已审核过的报名再审核 | 拒绝「该报名已处理过」 | `BizService.java:518`、`:522-523`、`ModuleMapper.java:295` |
| 驳回不填原因 | 拒绝「请填写驳回原因」 | `BizService.java:520` |
| 被驳回后再报名 | **被拒**：`countEnrollment` 计所有状态，仍判"已报名" | `ModuleMapper.java:233-236`、`BizService.java:415` |
| 名额上限 | **无此规则** | 无字段、无校验 |
| 取消报名 | **无此能力** | 无接口 |
| 跨校报名 | **允许**：报名只校验用户存在，不校验活动是否属本校 | `BizService.java:412-415` |
