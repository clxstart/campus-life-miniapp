## 一、这个功能解决什么问题

平台有两套完全独立的身份体系，共用「登录」这个词但互不相通：

| 身份 | 谁能登录 | 凭证 | 用来干什么 |
|---|---|---|---|
| 小程序用户（学生/商家申请人） | 微信用户 | 微信 `code` → `openid` → 自签 JWT | 发帖、下单、报名、私信、看自己的收藏/地址/优惠券 |
| 管理端账号（超管/校管/商家/骑手） | 平台运营方 | 用户名 + BCrypt 密码 | 后台审核、改数据、退款、导出、改配置 |

它要解决四个具体问题：

1. **小程序不能让用户填账号密码**——学生只用微信，所以走静默登录：页面发起请求时自动 `wx.login()` 拿 code，后端换 `openid`，查库有号就复用、没号就建号。
2. **写接口不能靠客户端自报 `userId`**——历史版本所有接口「谁传 `userId` 就代表谁」，改个数字就能替别人发帖/退款。现在写操作与「我的数据」读接口必须带有效 token。
3. **管理端不能匿名访问**——`/api/admin/**` 全部经过 `AdminInterceptor`，无 token 直接 401，不是「前端隐藏」。
4. **令牌要能失效**——注销用户的旧 token 必须立刻作废；管理员改密/停用后旧 token 必须立刻作废。

## 二、用户看到的样子（小程序端）

操作路径（全部自动，用户不感知「登录」这件事）：

1. 打开任意需要身份的小程序页（「我的」、发帖、订单）→ `utils/api/core.js` 的 `request()` 判断这是需要身份的请求且本地无 token → `ensureLogin()`。
2. `ensureLogin()` 调 `wx.login()` 拿 `code` → `POST /api/auth/login` → 后端返回 `{token, expiresIn, userId, nickname, newUser}` → 存 storage（`campus_auth_token` / `campus_auth_user`）。
3. 之后每个请求自动带 `Authorization: Bearer <token>`。
4. token 失效（过期/注销）→ 后端 401 → 前端清本地登录态（`utils/api/core.js:76`）→ 下次请求重新走第 1 步。
5. 403 不清 token：已登录但无权（例如操作别人的订单）时只报错，避免把用户莫名踢下线。

**生产环境的硬约束**：`utils/config.js:9` 的 `PRODUCTION_ORIGIN` 目前是 `https://api.your-domain.example`。release/trial 包启动时 `productionConfigError()` 判定为占位地址，`CONFIG_ERROR` 非空，`send()` 第一行就 `reject`（`utils/api/core.js:59`）——**请求根本不会发出去**，页面看到的是终端错误而不是「网络不好」。设计上是「宁可全挂也不静默回退到 127.0.0.1」。

开发登录（仅非生产）：`config.ALLOW_DEV_LOGIN` 在 develop 为 true，微信登录失败可降级到 `POST /api/auth/dev-login`，默认只能登 1 号演示账号。

## 三、运营看到的样子（Web 端）

1. `#/login` 输入账号密码 → `POST /api/admin/login`。
2. 若返回 `mustChangePassword=true`（超管新建账号 / 重置过密码），路由守卫强制跳到 `#/change-password`，且后端也禁止访问其他业务接口（`AdminInterceptor:69-72`），**绕过前端页面直接打接口同样 403**。
3. 登录后 `#/admins` 管理管理员账号（仅超管）：新建（可指定 super/school 与所属学校）、启用/停用。
4. `#/logs` 看操作日志：超管看全部，校管只看自己（`AdminAuthController:116-118`）。
5. 点「退出」只清浏览器本地 token（`web/src/stores/auth.js:49-53`）；后端没有 logout 接口，令牌在 8 小时有效期内仍然可用。

## 四、接口清单

| 方法 | 路径 | 权限 | 作用 | 证据 |
|---|---|---|---|---|
| POST | `/api/auth/login` | 公开（IP 限流 10/分） | 微信 code 换 token，首次登录自动建号 | `AuthController.java:21-26` |
| POST | `/api/auth/dev-login` | 公开（三重开关 + 限流） | 本地调试登指定账号，默认只能 1 号 | `AuthController.java:29-35` |
| GET | `/api/auth/status` | 公开 | 返回 `devLogin` / `wechatConfigured` | `AuthController.java:37-43` |
| POST | `/api/admin/login` | 公开（无 IP 限流） | 管理端账号密码登录 | `AdminAuthController.java:28-33` |
| GET | `/api/admin/profile` | 管理端 token | 当前账号 id/role/schoolId/shopId/realName | `AdminAuthController.java:36-45` |
| POST | `/api/admin/change-password` | 管理端 token（首次改密唯一放行口） | 自助改密，递增 token_version 作废旧令牌 | `AdminAuthController.java:48-55` |
| GET | `/api/admin/admins` | 仅超管 | 管理员列表 | `AdminAuthController.java:58-62` |
| POST | `/api/admin/admins` | 仅超管 | 新建管理员（校管必须绑学校，初始密码强制改密） | `AdminAuthController.java:65-97` |
| POST | `/api/admin/admins/{id}/status` | 仅超管 | 启用/停用，递增 token_version | `AdminAuthController.java:100-108` |
| GET | `/api/admin/logs` | 超管全部 / 校管本人 | 操作日志分页 | `AdminAuthController.java:111-125` |

鉴权不是靠这三个接口，而是靠三个拦截器统一挂载：

| 拦截器 | 覆盖范围 | 关键行为 | 证据 |
|---|---|---|---|
| `AuthInterceptor` | `/api/**`（排除 `/api/pay/notify`） | 解析 user token；写操作与「我的数据」读接口无 token → 401；注销账号 → 401 | `WebConfig.java:41`、`AuthInterceptor.java:100-131` |
| `AdminInterceptor` | `/api/admin/**`、`/api/merchant/**` | 无 token/过期 → 401；角色不匹配 → 403；账号停用/权限变更 → 401；首次未改密 → 403 | `WebConfig.java:43`、`AdminInterceptor.java:24-85` |
| `RiderInterceptor` | `/api/rider/**` | 只放行 `role=rider` | `WebConfig.java:45`、`RiderInterceptor.java:19-42` |

## 五、数据表与字段

| 表 | 关键字段 | 谁写 | 用途 |
|---|---|---|---|
| `user` | `openid`（微信身份）、`nickname`、`school`/`school_id`、`status`（1 正常 / 0 注销）、`deleted_at` | 登录建号、注销 | 小程序用户主表；`openid` 为唯一身份锚点 |
| `admin_user` | `username`、`password_hash`(BCrypt)、`role`（super/school/merchant/rider）、`school_id`、`shop_id`、`status`、`fail_count`、`locked_until`、`must_change_password`、`credential_rotated_at`、`token_version` | 管理端登录/改密/停用 | 管理端账号；与 `user` 完全隔离，避免普通用户提权 |
| `admin_log` | `admin_id`、`action`、`target_type`、`target_id`、`detail`、`ip` | 管理端写操作 | 操作留痕 |

建表与变更脚本：`db/module-multischool-admin.sql:19-53`（admin_user / admin_log）、`db/module-account-delete.sql:12-24`（user.status / deleted_at）、`db/module-commerce-consistency.sql:55-56`（admin_user.token_version）、`db/module-admin-seed.sql`（本地演示管理员，需显式 `@ALLOW_DEMO_SEED='YES'` 才插入）。

## 七、业务规则与边界

**会拒绝的情况**

1. 微信参数未配置（`appid`/`secret` 空或仍是 `touristappid`）→ 登录 503「微信登录未配置」，**不回落 dev-1**（`AuthService.java:50-52, 84-86`）。
2. `code` 为空 → 400「缺少登录凭证 code」（`AuthService.java:83`）。
3. 同一 IP 每分钟超过 10 次登录 → 429（`RateLimiter.java:34`、`AuthController.java:24`）。
4. 开发登录在 prod profile 下一律拒绝；非 prod 但微信已配置也拒绝（`AuthService.java:46-48, 93-96`）。
5. 管理端账号不存在/密码错 → 同一句「账号或密码错误」（防枚举，`AdminAuthService.java:30-31`）。
6. 管理端连续 5 次失败 → 锁 15 分钟（`AdminAuthService.java:21-22, 36-41`）。
7. 商家/骑手无 `shop_id`/`school_id` → 拒绝登录（`AdminAuthService.java:42-47`）。
8. 停用、改密、调权限后的旧令牌 → 401；`AdminTokenGuard` 查库失败 → 503，绝不放行（`AdminInterceptor.java:47-55`）。
9. 首次登录未改密 → 除改密/profile/logout 外全部 403（`AdminInterceptor.java:87-89`）。

**会放行的情况（必须知道）**

1. 匿名可调用的写接口白名单：`/api/auth/`、`/api/admin/login`、`/api/merchant/apply`、`/api/pay/notify`、`/api/pay/refund/notify`、`/api/ai/`、`/api/log/client`、`/api/upload`（`AuthInterceptor.java:61-71`）。
2. 匿名可读的「我的数据」之外的所有 GET：帖子列表、学校列表、搜索、用户主页等（设计如此，只用 `userId` 做「我点过赞吗」）。
3. `campus.auth.enforce=false` 时退回旧行为（谁传 userId 就是谁），启动会打 WARN 要求仅限本机（`AuthInterceptor.java:91-99`），prod 下配置闸门直接拒绝启动（`ProductionConfigValidator.java:53-55`）。
4. `/api/admin/upload/private` 无 token 也放行（`AdminInterceptor.java:30`）——见 `19-个人中心与账号安全/03-优缺点与问题.md` 的 P0 项。
