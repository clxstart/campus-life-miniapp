## 二、后端：逐条核对

- [✅] 微信登录换 openid——证据：`backend/src/main/java/com/campuslife/service/AuthService.java:106-121`（`jscode2session` 直连，失败抛 503 而非降级）。
- [✅] 微信参数缺失时 fail-closed——证据：`AuthService.java:50-52`（`touristappid` 也算未配置）、`AuthService.java:84-86`；启动日志 `log.error` 提示「不会回落到 dev-1」，`AuthService.java:61-69`。
- [✅] 首次登录自动建号 + 新人礼包——证据：`AuthService.java:124-145`；发分/发体验失败只记日志不影响登录，`AuthService.java:153-164`。
- [🟠] 建号时**硬编码学校**——证据：`AuthService.java:132` `user.setSchool("内蒙古大学")`，且未写 `school_id`（`User.java:15-17` 两个字段并存）。多校上线后新用户会全部挂到一个校名字符串上、`school_id` 为 NULL。
- [✅] user token 签发——证据：`config/JwtUtil.java:33-41`（subject=userId，HS256）；TTL 默认 604800 秒=7 天，`config/JwtUtil.java:22-23` 与 `application.yml` 的 `campus.jwt.ttl-seconds: 604800`。
- [🟠] 未配置密钥时用开发默认值——证据：`JwtUtil.java:24`；仅 warn 不阻断，`JwtUtil.java:25-28`。生产靠配置闸门兜住（见下条）。
- [✅] 生产密钥强校验——证据：`config/ProductionConfigValidator.java:60-63`（空、长度<32、含 `change-me`/`dev-secret` 等特征一律拒绝启动）。
- [🟠] user token **无吊销清单**——证据：`AuthInterceptor.java:109-121` 只在 `UserStatusGuard` 判定账号已注销时拒绝；没有 jti 黑名单、没有用户级 token_version。泄露的 token 在 7 天内一直有效。
- [✅] 写操作强制身份——证据：`AuthInterceptor.java:137-148`（`WRITE_METHODS` + `PUBLIC_WRITE_PATHS` 白名单），`AuthInterceptor.java:123-129` 拒绝并返回 401 JSON。
- [✅] 「我的数据」读接口强制身份——证据：`AuthInterceptor.java:74-92`（`PRIVATE_READ_PREFIXES` + `/api/users/{id}/{favorites,views,coupons,addresses,publish-count}`）。
- [✅] 注销后旧 token 立刻失效——证据：`AuthInterceptor.java:113-119` → `service/UserStatusGuard.java:36-53`（60 秒本地缓存，注销时 `invalidate`，`UserController.java:146-148`）。
- [✅] `userId` 只认 token——证据：`config/CurrentUser.java:17-31`（token 身份优先，claimed 只作为匿名读接口的个性化参数）；`UserController.java:24-29` 的 `requireSelf` 在路径 id 与身份不一致时 403。
- [✅] `campus.auth.enforce` 降级开关——证据：`AuthInterceptor.java:45-47`；prod 下被闸门锁死，`ProductionConfigValidator.java:53-55`。
- [✅] 管理端密码 BCrypt 存储——证据：`service/AdminAuthService.java:20, 24, 36`。
- [✅] 管理端登录失败锁定——证据：`AdminAuthService.java:21-22, 33-41`；`mapper/AdminMapper.java:23`（`fail_count+1` 并写 `locked_until`）、`AdminMapper.java:26`（成功后清零）。
- [🟠] 管理端登录**无限流**——证据：`controller/AdminAuthController.java:28-33` 全程未调用 `RateLimiter`；`service/RateLimiter.java:33-40` 的 `LOGIN` 规则只被 `AuthController.java:24,33` 使用。锁定是「按账号」计数，挡不住「一个密码打 200 个账号」的密码喷洒。
- [✅] 管理端改密后旧令牌全废——证据：`AdminAuthService.java:69-83`；`mapper/AdminMapper.java:75-83`（同一 UPDATE 里 `token_version=token_version+1`）。
- [✅] 停用/启用都递增版本——证据：`mapper/AdminMapper.java:85-87`。
- [✅] 每请求查库校验令牌状态——证据：`config/AdminTokenGuard.java:34-52`（status、tv、role、schoolId、shopId 五项全比对）；查库异常 → `UNAVAILABLE` → 503，`AdminInterceptor.java:48-51`。
- [✅] 首次改密强制拦截（服务端）——证据：`AdminTokenGuard.java:54-57`、`AdminInterceptor.java:68-72, 87-89`。
- [🟠] 管理端登出接口**不存在**——证据：`AdminInterceptor.java:88` 把 `/api/admin/logout` 列入「改密类放行路径」，但全仓 `grep -rn "logout" controller/` 无任何映射；`web/src/stores/auth.js:49-53` 只清本地。8 小时内令牌仍可用。
- [✅] 两种令牌不能互相冒用——证据：`config/AdminJwtUtil.java:20-27`（管理端密钥 = 用户密钥 + `-admin-scope` 后缀）；`AuthInterceptor.java:130-135` 把 `/api/admin|merchant|rider` 交给下游拦截器。
- [✅] 管理端角色门：商家路径只认 merchant、其余只认 super/school、骑手不得进管理端——证据：`AdminInterceptor.java:57-67`。
- [🟠] 登录限流的 IP 可伪造——证据：`AuthController.java:45-49` 取 `X-Forwarded-For` 首段；该头由客户端可控，攻击者每次换一个值即可无限次登录尝试。`service/RateLimiter.java:46-63` 本身是固定窗口计数，没问题；问题在键的来源。
- [✅] 限流存储故障 fail-closed——证据：`RateLimiter.java:52-57`（Redis 不可用 → 503，除非显式 `campus.ha.rate-limit-fail-open=true`）。
