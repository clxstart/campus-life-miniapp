## 一、这个功能解决什么问题

校园产品的社交骨架里，「宿舍」是最小、最真实的关系单元——同宿舍的人天然认识、天然会一起行动。这个功能把它产品化：

1. **建关系**：一个人建宿舍、生成 6 位邀请码，其他人用码加入（`DormService.java:179-250`）。
2. **给一个每天要一起做的事**：全员签到。宿舍不单独做签到按钮，复用全局签到，只在**事务提交后**回调宿舍判定（`SignCompletedListener.java:8-11`、`DormService.java:35-36`）。
3. **给一个团体荣誉**：周榜第一，全员拿成长值 + 奶茶券（`DormService.java:342-395`）。

要解决的核心矛盾（注释写得很清楚，`DormService.java:28-33`）：

| 矛盾 | 解法 |
|---|---|
| 一人多宿舍 → 跨宿舍刷全员签到 | 数据库级 `uk_dorm_user (user_id)` 唯一键，服务层文案只是友好提示 |
| 中途有人退出 → 「7/8 变 7/7」白拿奖励 | `dorm_sign.member_count` 在当日首行创建时**固化**，之后不再变 |
| 并发签到 → 全员奖励发两次 | `dorm_sign.all_done` 用条件更新（`signed_count >= member_count AND all_done = 0`），只有返回 1 的那次发分 |

明确**不做**的事：

- 不做跨校互通：`dorm.school_id` 只是落库字段，注释明示「本期不做跨校互通」（`db/module-dorm-v31.sql:26`）——**但代码没有校验，见 26-02**。
- 不做宿舍内聊天/公告/舍费（代码里没有对应表与接口）。
- 不做独立签到按钮（复用全局签到）。

## 三、运营看到的样子（Web 端）

路由已注册：`web/src/router/index.js:40`（`dorms`，标题「宿舍管理」）。

页面 `web/src/views/Dorms.vue`（302 行）：

1. 列表：宿舍名/学校/楼栋房间/邀请码/成员数/本周得分/状态/创建时间（`DormMapper.java:193-216`）。
2. 筛选：学校（超管可用）、状态、关键字（宿舍名模糊）（`DormService.java:437-455`）。
3. 展开成员：调 `GET /api/admin/dorm/{id}` 拿成员与今日签到态（`Dorms.vue:262`、`DormService.java:457-471`）。
4. 解散：必填原因 → `POST /api/admin/dorm/{id}/dismiss`（`Dorms.vue:280-290`、`AdminDormController.java:46-55`）。

**权限**：

- `super` 看全平台，可切学校；`school` 强制本校，传别校直接 403（`AdminDormController.java:91-101`）。
- 解散：校管只能解散本校；宿舍 `school_id` 为 NULL 时**校管一律被拒**（`DormService.java:483-488`）。
- 周榜补跑 `POST /api/admin/dorm/settle-week`：**仅 super**（`AdminDormController.java:61-66`），理由是「一次补跑会影响全平台宿舍的成长值」。

**运营拿不到的能力**：`settle-week` 这个补跑接口**前端没有按钮**——`grep -rn "settle-week" web/src/` 零命中。补跑只能靠 curl，见 26-07。

## 四、接口清单

| 方法 | 路径 | 权限 | 作用 | 证据 |
|---|---|---|---|---|
| GET | `/api/dorm/me` | 登录本人 | 我的宿舍（未加入/已加入/已解散三态） | `DormController.java:33-36` |
| POST | `/api/dorm` | 登录本人 + **已认证** | 创建宿舍（返回邀请码） | `DormController.java:39-45`、`DormService.java:181` |
| POST | `/api/dorm/join` | 登录本人 | 用邀请码加入 | `DormController.java:48-53` |
| DELETE | `/api/dorm/leave` | 登录本人 | 退出（舍长受限） | `DormController.java:56-60` |
| GET | `/api/admin/dorm` | 管理端 super/school | 列表（学校/状态/关键字/分页） | `AdminDormController.java:27-37` |
| GET | `/api/admin/dorm/{id}` | 管理端 super/school | 详情（宿舍 + 成员 + 本周榜） | `AdminDormController.java:39-43` |
| POST | `/api/admin/dorm/{id}/dismiss` | 管理端 super/school | 解散（必填原因） | `AdminDormController.java:46-55` |
| POST | `/api/admin/dorm/settle-week` | **仅 super** | 手动补跑某周周榜 | `AdminDormController.java:61-73` |

路径策略（`DormController.java:16-17` 注释）：「一律不带 userId —— 只能操作自己的宿舍，传别人的 id 也没有入口」。这是对的：少一个参数就少一类越权。

读接口在 `AuthInterceptor` 的私有读前缀里（`/api/dorm`），未登录返回 401 而不是「未加入」（`AuthInterceptor.java:74-86`）——避免前端把「没登录」误判成「没宿舍」。

## 五、数据表与字段

### 5.1 `dorm`（一宿舍一行）

建表：`db/module-dorm-v31.sql:24-40`。

| 字段 | 类型 | 用途 |
|---|---|---|
| `school_id` | BIGINT NULL | 所属学校；NULL = 用户未绑定学校 |
| `name` / `building` / `room` | VARCHAR | 宿舍名 / 楼栋 / 房间号 |
| `leader_id` | BIGINT | 舍长（不能直接退出） |
| `invite_code` | CHAR(6) | 6 位邀请码，`uk_dorm_code` 全站唯一 |
| `member_limit` | TINYINT | 成员上限，默认 8（**无下限，见 26-03**） |
| `status` | TINYINT | 1=正常 0=已解散（不物理删除，历史签到还在） |
| `dismissed_by` / `dismissed_at` / `dismiss_reason` | — | 解散审计，原因必填 |

邀请码字母表去掉易混字符 `0/O/1/I`（`DormService.java:54-56`），撞码重试 10 次（`:195-212`）。

### 5.2 `dorm_member`（舍友关系）

建表：`db/module-dorm-v31.sql:43-51`。

| 字段 | 用途 |
|---|---|
| `dorm_id` / `user_id` | 关系 |
| `role` | `leader` / `member` |
| `joined_at` | 加入时间 |

**关键约束**：`UNIQUE KEY uk_dorm_user (user_id)` ——「一人一宿舍」的**数据库级**保证（`:49`）。注释明说「服务层的『请先退出当前宿舍』只是友好文案，真正兜底的是这个唯一键」（`:6-8`）。

### 5.3 `dorm_sign`（当日签到汇总）

建表：`db/module-dorm-v31.sql:54-63`。

| 字段 | 用途 |
|---|---|
| `dorm_id` + `biz_date` | `uk_dorm_sign` 唯一，一天一宿舍一行 |
| `signed_count` | 当日已签人数（按成员集合实时重算，不盲加） |
| `member_count` | 当日首签时**固化**的成员数，当日不再变 |
| `all_done` | 1=当日已达成且已发分 |

### 5.4 `task_catalog`（奖励来源）

两条种子（`db/module-dorm-v31.sql:69-72`）：

| task_key | 名称 | P | G | daily_cap |

| `dorm_all_sign` | 宿舍全员签到 | 5 | 8 | 1 |
| `dorm_week_first` | 宿舍周榜第一 | 0 | 30 | 1 |

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 创建

| 规则 | 行为 | 证据 |
|---|---|---|
| 必须已认证 | 403「创建宿舍需要先完成学生认证」 | `DormService.java:181`、`:499-504` |
| 一人一宿舍 | 403「你已在宿舍中」 | `DormService.java:182` |
| 宿舍名必填、≤32 字 | 400 | `DormService.java:184-186` |
| 楼栋 ≤32、房间 ≤16 | 400 | `DormService.java:189-190` |
| 邀请码撞码 | 自动重试，最多 10 次，仍失败则 500「邀请码生成失败」 | `DormService.java:195-213` |
| 并发双击建宿 | `uk_dorm_user` 挡第二行，事务回滚 | `DormService.java:215-220` |
| **成员数下限** | **无**：单人宿舍可以存在并每天拿全员签到奖励 | 见 26-03 |

### 7.2 加入

| 规则 | 行为 | 证据 |
|---|---|---|
| 邀请码长度必须 6 | 400「邀请码无效」 | `DormService.java:229` |
| 一人一宿舍 | 403「请先退出当前宿舍」 | `DormService.java:230` |
| 邀请码不存在 | 400「邀请码无效，请确认后重试」 | `DormService.java:232-235` |
| 宿舍已解散 | 400「该宿舍已解散」 | `DormService.java:236` |
| 已满员 | 400「该宿舍已满 N 人」 | `DormService.java:238-242` |
| 并发挤入第 9 人 | 先 `SELECT ... FOR UPDATE` 锁宿舍行再数人数 | `DormService.java:239`、`DormMapper.java:59-60` |
| **校内外校验** | **无**：任何学校的用户都能凭码加入任何宿舍 | 见 26-02 |

### 7.3 退出

| 规则 | 行为 | 证据 |
|---|---|---|
| 未加入 | 400「你还没有加入宿舍」 | `DormService.java:260` |
| 舍长且有其他成员 | 403「需先把宿舍交给其他成员，或联系管理员解散」 | `DormService.java:264-266` |
| 舍长且只剩 1 人 | 自动解散空壳宿舍并记录原因 | `DormService.java:268-270`、`DormMapper.java:71-75` |

**注意**：代码里有「需先转让」的提示，但**没有转让接口**（`DormController` 只有 me/create/join/leave 四个方法）。所以舍长在有成员的情况下**只能找管理员解散**——功能上是死路，见 `03` 第 26-08 条。

### 7.4 全员签到（回调链）

```
用户签到 → SignService 事务提交 → afterCommit → SignCompletedListener.onSigned
        → DormService.handleSigned
            1. 查我的宿舍（未加入直接返回）
            2. 宿舍必须 status=1
            3. ensureSignRow(dormId, bizDate, memberCount)   ← 当日首行固化成员数
            4. countSignedMembers(dormId, bizDate)           ← 按成员集合实时重算
            5. updateSignedCount(...)
            6. claimAllDone(...) == 1 ? 逐人发 dorm_all_sign : 返回
```

证据：`SignService.java:150-163`（afterCommit 注册）、`SignCompletedListener.java:13-17`、`DormService.java:280-323`。

**关键设计**：宿舍判定失败只记日志，不回滚签到（`DormService.java:280-287`、`SignService.java:151-157`）。这个方向是对的——签到是主业务，宿舍是附加。

### 7.5 周榜结算

| 规则 | 行为 | 证据 |
|---|---|---|
| 结算时间 | 每周一 00:20（排在论坛周榜 00:10 之后，避免抢连接） | `DormService.java:328-339` |
| 多实例 | 租约锁 `dorm-week-settle`，10 分钟 | `DormService.java:60`、`:333` |
| 分数口径 | 宿舍成员本周 `task_log.p` 之和 | `DormMapper.java:180-189` |
| 排序 | 分数降序，并列 `dorm_id` 小者在前 | `DormMapper.java:187` |
| 奖励 | 冠军宿舍全员 +30G；`milk_tea` 有库存则每人再发一张券 | `DormService.java:372-384` |
| 券不可用 | 吞异常/记日志，只发成长值 | `DormService.java:401-412` |
| 库存不足 | 逐人扣库存，扣不到就 `break`（前面已发的保留） | `DormService.java:419-431` |
| 幂等 | `bizKey = week:{periodKey}` 走 `task_log` 唯一键 | `DormService.java:372`、`:376` |
| 补跑 | `POST /api/admin/dorm/settle-week`，仅 super | `AdminDormController.java:61-73` |

### 7.6 补偿规则的缺口

| 场景 | 现状 | 结论 |
|---|---|---|
| 周榜漏跑 | 有后台补跑接口（前端无按钮） | 能补（靠 curl） |
| 全员签到发分中途失败 | `all_done` 已置 1，剩余成员**永不再发**，且**无补跑入口** | 不能补（见 26-05） |
| 宿舍被解散后历史 | `status=0`，`dorm_sign` 与流水保留 | 可查 |
| 解散误操作恢复 | 代码注释称「误操作可由运维恢复」（`AdminDormController.java:18`），但**没有恢复接口**，只能改库 | 半可恢复 |
