## 一、这个功能解决什么问题

校园里最需要"说一句话就有人接"的场景：失物招领、求助、拼车、吐槽、社团招新。论坛社区是平台的**内容入口与流量基座**——首页推荐、搜索、圈子、日榜周榜、积分任务全都要读 `post` 表。

它要解决的三个具体问题：

1. **发得出去**：学生用手机拍张图 + 写两句话就能发帖，不需要排版、不需要审核等待。
2. **看得见**：同校学生能刷到彼此的内容，跨校内容按"本校 + 无归属"混合可见（`ForumService.java:15-18`）。
3. **管得住**：违规内容能被敏感词拦在入库前，疑似内容能被人工复核，被下架的内容能恢复（`AuditService.java:416-446`）。

对应的商业价值：论坛是 UGC 平台**合规义务最重**的一块（微信小程序审核要求"用户可举报 + 平台可下架"），也是拉新与留存的入口。

## 二、用户看到的样子（小程序端）

### 2.1 发帖路径

入口：`pages/community`（社区列表）右上角发布按钮 → `openPublish()` → `wx.navigateTo('/pages/publish/publish')`（`pages/community/community.js:50`）。

发布页有四个类型，**四种类型走四条完全不同的后端链路**，不是换个标签（`pages/publish/publish.js:11-16`）：

| 类型 | key | 实际落到哪 | 代码位置 |
|---|---|---|---|
| 校园动态 | `daily` | `POST /api/posts`（论坛帖） | `pages/publish/publish.js:184-192` |
| 闲置好物 | `idle` | `POST /api/goods`（二手，goods 表） | `pages/publish/publish.js:152-162` |
| 兼职信息 | `job` | `POST /api/jobs`（job 表） | `pages/publish/publish.js:164-172` |
| 活动组队 | `event` | `POST /api/activities`（campus_activity 表） | `pages/publish/publish.js:174-181` |

"校园动态"具体操作流：

1. 填标题（必填）+ 正文（必填）+ 选图（最多 6 张，`chooseMedia`，`pages/publish/publish.js:76-90`）。
2. 可选地点（按当前选中学校拉地点列表，`pages/publish/publish.js:98-107`）。
3. 点提交 → 先逐张上传图片换服务端 URL（失败则不带图发布，`pages/publish/publish.js:116-124`）→ `api.publishPost`。
4. 成功 toast "发布成功"（`pages/publish/publish.js:197`），700ms 后返回上一页并标记重载（`pages/publish/publish.js:204-218`）。

**用户在这个流程里看不到自己帖子的审核状态**：没有任何"审核中/仅自己可见"的提示。

### 2.2 浏览与互动路径

- 列表：`pages/community` 七个 tab（关注/推荐/学习/生活/求助/二手/社团），tab 映射到 `tag` 与 `scope`（`pages/community/community.js:4-5`），顶部还有"本校/全部"切换（`switchPostScope`，`pages/community/community.js:42-47`）。
- 详情：点卡片 → `pages/post-detail`，正文全文展示、浏览上报 `POST /api/posts/{id}/view`（`pages/post-detail/post-detail.js:17-25`）。
- 互动四件：点赞（`onLike`）、收藏（`onFavorite`，先本地生效再上报、失败回滚，`pages/post-detail/post-detail.js:69-80`）、评论（`submitComment`，先本地插入再静默对账，`pages/post-detail/post-detail.js:122-139`）、评论点赞（`onLikeComment`，同样先本地生效，`pages/post-detail/post-detail.js:83-116`）。
- 关注作者、进作者主页、私聊作者（`pages/post-detail/post-detail.js:55-61,140-143`）。
- "更多"菜单：**举报这条帖子 / 屏蔽作者**两个动作（`pages/post-detail/post-detail.js:146-159`）。举报原因六选一：广告/辱骂/色情/诈骗/侵权/其他（`pages/post-detail/post-detail.js:164`）。

### 2.3 用户看不到的部分

- 自己发的帖子如果被判 `reviewing`/`pending`，列表里查不到、详情页打不开，**没有任何"我的待审内容"入口**。
- 举报后的处理结果不会回执给举报人（`ContentReportService.java:60-62` 只返回 `{reported:true}`）。

## 三、运营看到的样子（Web 端）

### 3.1 内容管理（`/posts`）

`web/src/views/Posts.vue` 是帖子的 CRUD 台：超管可按学校筛选（`Posts.vue:18-21`）、可"只看已下架"（`Posts.vue:22-25`）、支持编辑标题/正文/标签/配图（`Posts.vue:56-82`）、上架/下架切换（`Posts.vue:169-177`）、删除（`Posts.vue:179-187`）。

注意：这里改的是 `post.status`（业务可见位），**不碰 `audit_status`**；改动会写一条管理端审计日志（见 28-管理后台）。

### 3.2 内容审核（`/audit`）

`web/src/views/Audit.vue` 是审核台，只有三个 tab：**待人工审核 / 已拒绝 / 敏感词管理**（`Audit.vue:110`）。

- 待人工审核：按 `audit_status='reviewing'` 拉数据，支持批量通过/批量拒绝（`Audit.vue:28-32,157-158`），拒绝必填原因且回执通知作者（`AuditService.java:428-439`）。
- 已拒绝：可"恢复"重新上架（`Audit.vue:51`，`AuditService.java:441-446`）。
- 敏感词管理：增删改 + 批量导入 TXT（最多 5000 个/次，`AuditService.java:499-509`），改完立即重建引擎，不需要重启（`AuditService.java:484`）。

审核台覆盖六类内容：发帖/评论/二手/兼职/私信/圈子（`AuditMapper.java:12-40`，`AuditService.java:36`）。

### 3.3 运营看不见的部分

- `audit_status='pending'` 的内容**在审核台上没有入口**：tab 只有 reviewing/rejected，请求永远带 `status=reviewing`（`Audit.vue:146`）。
- 举报有独立的 `/reports` 页（见 29-内容治理与安全），与审核台是两套台子。

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 发帖时的四种结局

| 结局 | 触发条件 | `status` | `audit_status` | 用户能看到吗 |
|---|---|---|---|---|
| 直接通过 | 文本审核 passed 且无图 | 1 | `passed` | 能 |
| 疑似，等人工 | 微信返回 `suggest=review` | 0 | `reviewing` | 不能，需审核台通过（`ForumService.java:154`，`AuditService.java:200-202`） |
| 有图，等图片审核 | 文本 passed 且有图 | 0 | `pending` | 暂不能，图片审核回调后转 `passed`（`ForumService.java:152-157`，`AuditMapper.java:144`） |
| 免审先发 | 黄金段位 + `post.fastlane.enabled=1` + 文本无疑似 | 有图=1，无图=1 | 有图 `pending` / 无图 `passed` | 能（先上线后审，`ForumService.java:149-157`） |

### 7.2 会被直接拒绝（入库前抛异常，但已写 `audit_log`）

1. 标题+正文命中敏感词库 → "内容包含违规词：X、Y"（`ForumService.java:136-137`，`AuditService.java:170-173`）。
2. 图片是本地临时路径（`wxfile://`、`http://tmp/`）→ "图片未上传成功，请重新选择图片"（`ForumService.java:87-95,135`）。
3. 学习分类不在白名单（`daike/paper/job/kaoyan/kaogong`）→ "学习分类不合法"（`ForumService.java:39,134`）。
4. 跨校 + 学习分类同时为真 → "学习交流仅在所选学校可见"（`ForumService.java:141`）。
5. `post.publish.enabled=0` → "发帖功能维护中，请稍后再试"（`ForumController.java:171-173`）。
6. 超过 10 次/分钟 → 429 + "发布过于频繁，请 N 秒后再试"（`RateLimiter.java:59-63`）。

### 7.3 可见性规则

- 列表只查 `status=1`（`ForumService.java:12`），详情也要求 `status==1`（`ForumService.java:124`）。
- 本校流 = 本校帖 + `school_id IS NULL` 的跨校帖；`postScope=all` 才放开（`ForumService.java:15-18`）。
- 学习专区只查本校，**绝不并入 NULL 归属**（`ForumService.java:54-56`）。
- 拉黑双向过滤只作用于**帖子列表**（`ForumService.java:27-28`）；详情、评论、群聊不过滤（见 `03-优缺点与问题.md` 04-06）。

### 7.4 补偿与自愈

- 图片审核在事务提交后异步触发（`AuditService.java:258-276`），命中 87014 → 下架 + 通知作者（`AuditService.java:307-311,365-371`）。
- 审核执行器队列满 → 直接放行并记 `source=local/pass` 日志（`AuditService.java:263-267`）。
- 微信接口异常 → 放行并记 `source=local/pass`（`AuditService.java:317-321`）。
- 人工拒绝后作者收到站内通知；人工恢复后 `status=1`（`AuditService.java:438,441-446`）。

### 7.5 明确不做的事

- 不做"我的待审列表"、不做"审核中"角标、不做举报回执。
- 不做敏感词的学校维度——词库是平台级单表（`module-audit.sql:63-70`）。
- 不做帖子编辑历史（`Posts.vue` 编辑直接覆盖字段）。
