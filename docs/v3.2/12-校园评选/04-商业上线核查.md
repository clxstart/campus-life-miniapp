## 一、合规与隐私

**结论：不通过。** 原因：用户上传的真人照片在**无审核、无授权、无未成年人保护**的前提下公开展示，且分享拉票文案主动引导传播（`pages/activity-idol/activity-idol.js:41-44`）。

| 检查项 | 结论 | 证据 |
|---|---|---|
| 参赛内容是否经审核后公开 | ❌ 未经审核，`status` 直接置 1 上墙 | `backend/src/main/java/com/campuslife/service/IdolService.java:31` |
| 用户是否勾选肖像使用授权 | ❌ 报名页无任何协议勾选 | `pages/idol-join/idol-join.js:42-57` |
| 未成年人保护 | ❌ 无年龄判定，无监护人同意流程 | 同上（`submit()` 只校验照片非空、昵称非空） |
| 照片是否走内容安全 | ❌ 未上传、未调图片审核 | `pages/idol-join/idol-join.js:50`（无 upload 调用）；`IdolService.java:31`（无 `auditService` 调用） |
| 昵称/宣言是否过敏感词 | ❌ `join()` 无 `checkText` | `backend/src/main/java/com/campuslife/service/IdolService.java:30-31` |
| 隐私政策是否覆盖"参赛照片公开展示" | 需人工核对文案 | `pages/agreement/agreement.js:6-7,61`（有隐私政策页，条款文本未逐句核对，**未验证**） |
| 参赛者身份可核实性 | ❌ `college` 用户自填，无校验 | `pages/idol-join/idol-join.js:39` |

**为什么这一维是"不通过"而不是"有条件通过"**：真人照片公开 + 零审核 + 无授权，这三条同时成立时，一旦出现违规图片或肖像权投诉，平台没有可出示的审核记录与用户授权记录，属于"无法自证已尽责"。补上审核与授权两项后可降为"有条件通过"。

## 二、资金与对账

**结论：不涉及。** 依据：

- 无任何支付/退款/钱包/分成调用：评选两表（`idol_contestant`、`idol_vote`，`backend/src/main/resources/db/schema.sql:13-14`）无金额字段。
- 全文无 `payService` / `WalletService` / `PayController` 引用：见 `backend/src/main/java/com/campuslife/service/IdolService.java` 全部 32 行，只有 `IdolContestantMapper` 与 `IdolVoteMapper` 两个依赖（`:6`）。
- 投票不消耗积分/成长值：`IdolService.vote()`（`:23-29`）无 `PointsService`/`TierService` 调用。

> 但存在一处**类资金口径的风险**：票数是可被刷的公共数字（见 12-05）。若将来把票数接进"人气值"或"分红/奖励"，本功能立刻升级为资金相关，必须重做本节。

## 四、数据与迁移（前置 SQL、执行顺序、回滚 SQL）

**结论：有条件通过（条件：确认目标库已执行 `schema.sql` 的评选段；锚点文件不含评选建表）。**

### 4.1 前置 SQL（按执行顺序）

```sql
-- 1) 选手表（若不存在）
CREATE TABLE IF NOT EXISTS idol_contestant (
  id BIGINT PRIMARY KEY AUTO_INCREMENT, user_id BIGINT NOT NULL, name VARCHAR(32) NOT NULL,
  gender TINYINT NOT NULL DEFAULT 1, college VARCHAR(64) DEFAULT '', photo VARCHAR(255) NOT NULL,
  slogan VARCHAR(128) DEFAULT '', vote_count INT NOT NULL DEFAULT 0, status TINYINT NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP, KEY idx_idol_gender(gender,status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 2) 投票表（唯一键是一人一票的唯一实质防线，必须存在）
CREATE TABLE IF NOT EXISTS idol_vote (
  id BIGINT PRIMARY KEY AUTO_INCREMENT, contestant_id BIGINT NOT NULL, user_id BIGINT NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_idol_vote(contestant_id,user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 3) 入口 banner（评选页的唯一可达入口）
--    见 schema.sql:53，INSERT ... ON DUPLICATE KEY UPDATE
```

- 执行位置：`backend/src/main/resources/db/schema.sql:13-14`、`schema.sql:53`。
- **不是** `module-market-jobs-activities.sql`（该文件只有 `goods`/`job`/`campus_activity`/`activity_enroll`，见 `module-market-jobs-activities.sql:4,31,48,58`）。
- 上线前自检：

```sql
SHOW KEYS FROM idol_vote WHERE Key_name='uk_idol_vote';   -- 必须有 1 行
SELECT COUNT(*) FROM idol_contestant;                      -- 大于 0 说明种子还在
```

### 4.2 迁移风险

| 项 | 风险 | 处理 |
|---|---|---|
| 种子 7 名假选手 | 与真实活动混在一起，票数手写（862/645/…）| 上线前删除：`DELETE FROM idol_contestant WHERE user_id IN (1,2,3,4) AND photo LIKE '/assets/%'`（**执行前人审**） |
| `vote_count` 与 `idol_vote` 不一致 | 种子数据天生不一致 | 用 4.3 的核对 SQL，上线前清零重算 |
| `photo` 存量含 `wxfile://` | 已产生的无效照片 | `SELECT id,photo FROM idol_contestant WHERE photo NOT LIKE 'http%' AND photo NOT LIKE '/%'` → 通知重传或下架 |

### 4.3 回滚 SQL

```sql

-- 清空评选数据（不可逆，需备份后执行）
-- mysqldump campus_life idol_contestant idol_vote > backup_idol_$(date +%F).sql
```

## 九、结论

**不可上线（阻断项：12-01、12-02、12-03）。**

三条阻断项各自独立成立，任一存在都不应对外开启评选：

1. **12-01 照片链路断** —— 报名者上传的照片别人看不到（`pages/idol-join/idol-join.js:33,50`）。这是主链路不可用。
2. **12-02 零审核上墙** —— 真人照片未经任何审核直接公开展示（`backend/src/main/java/com/campuslife/service/IdolService.java:31`）。这是合规不通过。
3. **12-03 活动无终点** —— 截止时间硬编码且已过期 10 天，`vote()` 不校验（`IdolService.java:8,23-29`）。这是"对外承诺不可信"。

补齐三条后可重新评为**有条件上线**，条件为：加投票频控（12-05）、修并发投票提示（12-06）、补授权与未成年人保护（12-07）、加开奖前票数核对（第五节 4.3 的核对 SQL 写成管理端按钮）。
