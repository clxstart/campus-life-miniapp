> 建立时间：2026-11-10
> 代码快照：分支 `merge-all` @ `083f7b4`，工作区 **238 项未提交改动**（V3.1 新体系、兼职生态、骑手配送、圈子火花大量代码尚未提交）
> 用途：**给"要上线的这一版代码"逐个功能建档**——它做了什么、做到什么程度、优缺点是什么、有哪些问题、离商业上线还差什么。

---

## 一、这份文档回答什么问题

一句话：**"现在这套代码里，到底哪些功能能用、哪些是半成品、哪些有问题、能不能上线收钱。"**

它必须能回答三个问题：

1. **有哪些功能？** —— 30 个功能文件夹，覆盖小程序 47 个注册页面、Web 41 条路由、后端 46 个控制器 301 个方法级接口、数据库 82 张表。
2. **每个功能做到哪一步了？** —— 三端分别标状态（已实现 / 半实现 / 占位假值 / 已下线），每条结论带 `文件:行号` 证据。
3. **能不能上线？** —— 每个功能给出 P0/P1/P2 问题清单与商业上线核查结论（可上线 / 有条件上线 / 不可上线）。

## 二、它不是什么

| 不是 | 因为 |
|---|---|
| **不是设计稿** | 设计稿是 `docs/v3.1/`，写"打算做什么"。本目录只写"代码实际是什么样"。 |
| **不是交付报告** | 交付报告是 `docs/v3.1-交付/`，写"这一轮做完了什么"。本目录是**全量横切盘点**，含老功能和半成品。 |
| **不是测试报告** | 本目录会引用测试命令与实跑结果，但没有跑过的项一律标"未验证"，不冒充结论。 |
| **不是修复承诺** | 本轮只排查不修代码。问题清单是下一轮修复的输入。 |

## 四、先给三个已核实的结论（抓手）

> 这三条不是推测，是本次盘点前已用命令验过的，详细取证见 `04-证据与复核台账.md`。

1. **旧文档的数字口径全面失效。** 接口 211 → 实测 **301 个方法级接口（349 个映射注解）**；库表 51/52 → **82**；小程序页 37 → **42**；后台页 19 → **30 条路由**。对外汇报再引用旧数字会被当场问倒。
2. **小程序整包当前编译不过。** `app.json:49` 注册了 `pages/dorm/dorm`，但该目录不存在——`node tools/check-static.js` 报 4 个缺文件（js/json/wxml/wxss）。撰写期间有人把 points / points-redeem / verify / forum-rank 补注册了（10:23–10:34），所以"页面没注册"的问题已消除，但换成了"注册了不存在的页面"，同样阻断发布。**注意这两个状态时间点不同，引用前先重跑检查。**
3. **V3.1 交付报告与代码事实脱节。** `docs/v3.1-交付/README.md` 写"只有积分体系后端已交付"，但代码里签到、段位、礼包券、论坛榜、学生认证、宿舍、兼职、骑手、圈子火花**都已有实现**（多数未提交、未写报告、未验证）。

## 五、状态字典（全目录统一）

| 标记 | 含义 | 判定依据 |
|---|---|---|
| ✅ 已实现-已验证 | 三端链路通，且有实跑证据（测试/静态检查/接口实测） | 有命令与结果 |
| 🟡 已实现-未验证 | 代码齐，但没实跑过 | 只有读码证据 |
| 🟠 半实现 | 后端有、前端没有；或前端有、入口没接；或主链路断在某一环 | 列出断点 |
| 🔴 占位/假值 | UI 在但数据写死，或接口返回 mock | 指出写死位置 |
| ⚫ 已下线 | 代码保留但入口停用 | 指出停用位置 |

## 六、问题等级（全目录统一）

| 等级 | 定义 | 典型例子 |
|---|---|---|
| **P0 上线阻断** | 会造成资金损失、数据泄露、越权、合规不通过、主链路不可用 | 支付可伪造 / 跨校能看别人数据 / 无隐私政策 / 发布版域名还是占位 |
| **P1 上线前必修** | 不阻断但上线后必炸运营或体验 | 审核漏审、通知不到、状态不同步、无告警、无回滚 |
| **P2 可迭代** | 体验与增长类，可上线后再做 | 批量操作缺失、移动端适配、埋点不全 |

判定细则与示例见 `_模板/00-写作规范.md` 第四节。

## 九、写作纪律

1. **不夸大**：没跑过的测试不写"已验证"；没读到的代码不写结论。
2. **每条问题带 `文件:行号`**：给不出位置的写"推测"并单独标注，不算结论。
3. **不许写"暂无问题"**：写不出来就写"本维度未覆盖，原因 X"。
4. **数字以实测为准**：与旧文档不一致的，写进 `04-证据与复核台账.md` 的口径差异表。
5. **不写空话**：禁止"后续优化""架构上还有提升空间"这类无法验收的表述，换成"差什么能力、多少工作量、什么条件下必须补"。
6. **回滚优先**：涉及钱、数据、权限的功能，没有回滚方案就写"不可上线"。

## 十、口径与前提

- 人日 = 熟悉本仓库的 1 名开发者，不含联调等待、资质审批、UI 设计。
- 金额：库里同时存在 `BigDecimal`（元）与 `Integer`（分）两种口径，**换算风险单列在 `02-横切问题排查.md`**。
- 文档只对快照 `083f7b4 + 当前工作区` 负责；代码变动后以本目录 front-matter 的快照行为准。
- 本目录**不含**任何产品代码改动；发现的问题只记录，不修复。
- 未验证项（真实支付、真机、微信审核、压测）统一登记在 `04-证据与复核台账.md` 第四节。
