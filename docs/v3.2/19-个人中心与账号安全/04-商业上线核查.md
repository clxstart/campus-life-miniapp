## 二、资金与对账

**结论：不涉及（依据：本功能不产生资金流水）。有一条间接依赖需登记。**

- 注销前置校验未完成订单（`CampusMapper.java:147-155`），是为了避免「钱还没结清人没了」。方向正确。
- 但校验只覆盖 `user_order`，**不覆盖兼职结算/骑手结算/退款中**。若用户有「退款中」的订单且状态值是 `refunding`，该状态**不在**排除列表（排除的是 `finished/completed/cancelled/canceled/closed/refunded`），会被算作未完成 → 拒绝注销。这是正确行为。
- 优惠券不回收：注销后券仍挂在 userId 上（`coupon` 表不动），若券可被他人冒用则涉及资损；当前核销需本人 token，暂不构成风险。
- 积分/成长值同理，保留在已注销用户身上。

## 四、数据与迁移（前置 SQL、执行顺序、回滚 SQL）

**结论：有条件通过（条件：必须确认 `user.status`/`deleted_at` 列已建，且注销前不存在 NULL 状态的历史用户）。**

执行顺序：

```sql
-- 1) 主 schema（含 user_address / feedback / favorite / post_view）
--    db/schema.sql:44, 46
-- 2) 注销所需列
--    db/module-account-delete.sql:12-24
-- 3) 拉黑表
--    db/module-user-block.sql:14-22
```

回滚：

```sql
-- 可回滚
ALTER TABLE `user` DROP COLUMN status, DROP COLUMN deleted_at;
DROP TABLE IF EXISTS user_block;
-- 不可回滚：已经注销的账号无法恢复（openid 已置空，见 UserService.java:131）
```

**数据风险点**

1. `user.status` 默认 1；历史行不需要回填。但如果生产库有 `status IS NULL` 的行（老 schema 遗留），`AuthInterceptor` 的 `UserStatusGuard` 会把 `status == null` 当作「可用」（`UserStatusGuard.java:44`），这是安全的默认方向。
2. 注销后 `openid=NULL`。MySQL 唯一索引对 NULL 不生效，所以**多个已注销用户可以共存 `openid=NULL`**；但如果 `openid` 上有 `UNIQUE` 且业务代码期望非空，需要确认（未验证：`schema.sql` 是否对 openid 建唯一索引未在本轮核对）。
3. 私有文件不会随注销删除——文件系统与 DB 无关联记录，只能靠孤儿清理（`UploadService.java:149-189`，且它按 mtime 清，不区分 public/private，**会把私有文件一起删**——这是唯一会碰到 `private/` 的地方，且 `Files.list(root)` 不会递归进 `private/` 子目录，所以私有文件实际上**永远不会被清理**）。
4. 迁移前必须备份 `user`、`user_address`、`favorite`、`post_view`、`user_block`、`feedback` 六张表。

## 八、开关与回滚（怎么关、怎么退、数据怎么退）

| 开关 | 默认 | 效果 | 证据 |
|---|---|---|---|
| 功能开关 `upload.enabled` | 开 | 关闭后上传接口返回「维护中」，已有图片仍可访问 | `UploadController.java:22-26`、`FeatureFlags.java:37-41` |
| `campus.upload.dir` | `uploads` | 换目录需迁移旧文件；改了之后旧 URL 全部 404 | `ha/LocalObjectStorage.java:18-25` |
| `campus.upload.private-prefix` | `/private` | 只影响返回给前端的 path 字符串，**不影响实际目录** | `UploadService.java:34, 91-96` |
| 注销 | 无开关 | 只能改代码 | — |
| 拉黑 | 无开关 | 只能改代码 | — |

**回滚方案**

1. **代码回滚**：本功能无破坏性 schema 变更（除 `user.status`/`deleted_at`），可直接回滚。
2. **私有文件泄露后的处置**：① 立即改写 `WebConfig` 去掉 `/uploads/**` 对整个 root 的映射（或改代码指向 `root` 之外）；② 轮换文件名（无法批量改名，只能迁移目录）；③ 已是既成泄露，需按个保法做事件评估与告知。
3. **注销不可回退**：`openid` 已置空（`UserService.java:131`），用户无法用原微信恢复账号；只能手工改库 `status=1` 并**要求用户重新绑定**（但绑定接口不存在）。
4. **上传目录回滚**：切换 `campus.upload.dir` 前必须把旧目录文件迁到新目录，否则历史图片全部失效且不可恢复（DB 只存路径）。

## 九、结论

**不可上线。**

阻断项：

- **19-01（P0）**：私有上传目录位于 `/uploads/**` 静态映射根下，学生证等敏感影像可被直链下载。
- **19-02（P0）**：`/api/admin/upload/private` 无 token 放行，匿名可写私有目录。

修完这两条（预计 1.5 人日）后转为**有条件上线**，条件为：19-03（注销不实承诺）、19-04（`school_id` 未清）、19-06（隐私政策缺敏感信息）、19-14（报名材料走公开通道）四条 P1 必须先修——这四条是审核与合规会直接问的。
