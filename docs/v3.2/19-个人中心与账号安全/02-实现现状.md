## 二、后端：逐条核对

### 2.1 归属校验（「我的数据」只认 token）

- [✅] 统一 `requireSelf(pathId, request)`：先取 token 身份，再比路径 id——证据：`backend/src/main/java/com/campuslife/controller/UserController.java:24-29`。
- [✅] 收藏/浏览/券/地址/发布数全部走 `requireSelf`——证据：`UserController.java:63-116`。
- [✅] 改/删地址按 `id + userId` 双条件，查不到即报错——证据：`service/UserService.java:84-92, 95-99`。
- [✅] 拉黑的操作人取 token 身份，不取路径 id——证据：`UserController.java:124-129`（注释明确「路径里的 {id} 是被拉黑的人」）。
- [✅] 注销也走 `requireSelf`——证据：`UserController.java:143-149`。
- [✅] `userId` 只认 token——证据：`config/CurrentUser.java:17-31`、`config/AuthInterceptor.java:109-121`。
- [🟠] `POST /api/feedback` 用 `CurrentUser.resolve(request, r.getUserId())`，匿名时回落 default=1——证据：`UserController.java:151-155` + `CurrentUser.java:26-35`。虽然 `/api/feedback` 是 POST 会被 `AuthInterceptor` 要求登录（`AuthInterceptor.java:137-148`），但代码意图上仍保留了「匿名当 1 号」的路径，属隐患。

### 2.2 资料

- [🟠] `updateProfile` 只写 `nickname`，其余字段全部忽略——证据：`UserService.java:37-41`（`u.setNickname(...)` 后直接 `updateById`）。
- [🔴] 小程序无头像上传入口：全仓 `updateProfile` 只被 `pages/profile/profile.js:332` 调用且只传昵称；头像只能由管理端改（`AdminModuleController.java:241-246`）。
- [🟠] `profile()` 对不存在的 id 返回 `nickname="校园同学"` 而不是 404——证据：`UserService.java:11-21`。看别人主页时若 id 不存在，页面显示一个「假用户」而不是「用户不存在」。

### 2.3 收藏 / 浏览 / 券 / 地址

- [✅] 收藏是切换语义，收藏他人帖子会发通知——证据：`UserService.java:51-56`。
- [🟠] 浏览记录读时去重但**每次浏览都插一行**，`post_view` 会无限增长且无清理任务——证据：`UserService.java:47-50`（读时用 `LinkedHashSet` 去重，写入端在别处）。
- [✅] 券只返回 `status=1` 且未过期——证据：`UserService.java:57-72`。
- [✅] 地址联系方式为空时默认「我」——证据：`UserService.java:79, 88`。

### 2.4 拉黑

- [✅] 双向不可见语义（我拉黑的 + 拉黑我的）——证据：`mapper/UserBlockMapper.java:20-29`；`service/UserBlockService.java:38-64`。
- [✅] 拉黑/解除都主动失效双方缓存——证据：`UserBlockService.java:80-82`。
- [🟠] 缓存 30 秒，且**读库失败按「不过滤」处理**——证据：`UserBlockService.java:43-50`（`catch` 后 `ids = List.of()`，注释「本次不过滤」）。数据库抖动期间被拉黑的人能重新看到你。
- [🟠] 切换语义无二次确认：`toggle` 直接反转状态，前端只 Toast（`pages/profile/profile.js:380-386`）；误触会把黑名单解除。

### 2.5 注销

- [🟠] 注销是「软删除 + 匿名化」`user` 单行——证据：`UserService.java:116-135`：`status=0`、`deletedAt=now`、`nickname="已注销用户"`、`avatar=null`、`openid=null`、`school=null`。
- [🔴] **未清 `school_id`**——证据：`UserService.java:127-134` 只 `setSchool(null)`，`entity/User.java:15-17` 有两个字段（`school` 字符串 + `schoolId`）。注销后 `school_id` 仍在，与「匿名化」目标冲突，也让 `02-多校隔离` 的按校统计把已注销用户算进原校。
- [🔴] **不删帖子/评论/收藏/地址/浏览记录/反馈**——证据：`UserService.java:116-135` 全文只有 `userMapper.updateById(user)` 一次写操作；`db/module-account-delete.sql:1-8` 的注释也自认「订单、支付、审计记录需要按法规保留」——但**笔记/帖子不属于「按法规必须保留」**，仍被保留。
- [🔴] 小程序确认文案说「你的资料、帖子、收藏等将被删除且无法恢复」——证据：`pages/profile/profile.js:145`。与实现不符，属于对用户的**虚假承诺**。
- [🟠] 注销前只校验外卖订单未完成——证据：`service/CampusMapper.java:147-155`（`user_order` 单表）。兼职合约/争议、活动报名材料、骑手任务、认证状态都不校验。
- [✅] 注销后旧 token 立即失效——证据：`UserController.java:145-148`（`statusGuard.invalidate`）+ `AuthInterceptor.java:113-119`。
- [✅] 注销后同微信再登录会建新号——证据：`AuthService.java:125-136`（`openid` 已置空，查不到即新建）。

### 2.6 上传（安全重点）

- [✅] 扩展名白名单 + 文件头魔数校验——证据：`service/UploadService.java:28, 74-79, 118-138`（PNG/JPEG/GIF/WEBP 四种签名）。
- [✅] 文件名服务端生成，客户端名字不落地——证据：`UploadService.java:82`（`LocalObjectStorage.randomName`）、`ha/LocalObjectStorage.java:63-69`（`safeName` 拒绝路径分隔符与 `..`）。
- [✅] 大小上限 5MB，双层限制（Spring multipart 5MB/10MB + 业务校验）——证据：`UploadService.java:29, 69`、`application.yml`（`max-file-size: 5MB`）。
- [🔴] **私有目录落在静态映射根下**——证据：`ha/LocalObjectStorage.java:27`（`privateDir() = root.resolve("private")`）、`:37`（写入 `privateDir()`）；`config/WebConfig.java:54`（`/uploads/**` → `root`）。故 `/uploads/private/<name>` 可直取。
- [🔴] **私有上传接口匿名放行**——证据：`config/AdminInterceptor.java:30`（`/api/admin/upload/private` 且无 token → return true）；`controller/UploadController.java:51-57`。
- [✅] 私有上传的响应不返回可访问 URL（`url: ""`，只给 `path`）——证据：`UploadService.java:91-96`。这是「以为私有」的设计意图来源，但静态映射把它推翻了。
- [🟠] 无内容安全扫描：图片不送微信内容安全，也不做 OCR/鉴黄——证据：`UploadService.java:67-108` 无任何外呼。
- [🟠] 限流键用 `getRemoteAddr()`（不可伪造，好）但匿名可写——证据：`UploadController.java:80-82`。
- [🟠] 对象存储模式下私有文件是否公开取决于 bucket 策略，代码只委托 `ObjectStorage.putPrivate`——证据：`ha/S3ObjectStorage.java`（未在本轮读全，标注为未验证）。

## 六、测试现状

**能跑的命令**

```bash
# 1) 私有文件是否可直链访问（需先起后端 + 有一个私有文件）
curl -i http://127.0.0.1:8080/api/admin/upload/private -F "file=@test.png"   # 无 token，记录返回的 path
curl -i http://127.0.0.1:8080/uploads/private/<返回的文件名>                  # 期望 403/404，当前预期 200

# 2) 越权读别人的收藏
curl -i http://127.0.0.1:8080/api/users/2/favorites -H "Authorization: Bearer <1号用户token>"

# 3) 注销后旧 token
curl -X DELETE http://127.0.0.1:8080/api/users/1/account -H "Authorization: Bearer <1号token>"
curl -i http://127.0.0.1:8080/api/users/1/favorites -H "Authorization: Bearer <1号token>"  # 期望 401

# 4) 注销后数据是否还在
mysql -e "SELECT COUNT(*) FROM post WHERE user_id=1; SELECT COUNT(*) FROM user_address WHERE user_id=1;"
```

**本轮执行情况**

| 命令 | 是否执行 | 结果 |
|---|---|---|
| 读码核对 16 个用户接口 + 4 个上传接口 | ✅ | 完成 |
| 私有文件直链验证 | ❌ 未执行 | 无运行中后端；结论来自 `WebConfig.java:54` + `LocalObjectStorage.java:27,37` 的路径推导 |
| 越权读别人收藏 | ❌ 未执行 | 同上；`requireSelf` 逻辑明确，属低风险项 |
| 注销后数据留存核对 | ❌ 未执行 | 代码路径明确（只有一次 `updateById`） |
| `node tools/check-all.js` | ✅ 已执行（台账记录 9/9） | 与隐私/上传无直接关系 |

**⚠️ 现有的测试给了虚假的安全感（重点）**

`backend/src/test/java/com/campuslife/ha/LocalObjectStorageTest.java:32-41` 有一个用例 `privateFileIsNotExposedThroughPublicDir`，断言的是：

```java
storage.putPrivate("lic.jpg", ...);
assertThat(dir.resolve("private").resolve("lic.jpg")).exists();      // 私有文件确实在 private/ 下
assertThatThrownBy(() -> storage.readPublic("lic.jpg"))              // 「公开读」拿不到
    .isInstanceOf(java.io.IOException.class);
```

它证明的是「`readPublic(name)` 不会穿越到 `private/` 里找文件」，**完全没有覆盖 HTTP 层**：`GET /uploads/private/lic.jpg` 由 Spring 的 `ResourceHttpRequestHandler` 处理，直接读 `root/private/lic.jpg`，与 `readPublic()` 无关。所以这条测试**绿着，漏洞还在**。

同类测试还覆盖了路径穿越被拒（`:42-50` `traversalInNameIsStripped`）、公开 URL 形状（`:22-30`）。这些都写得对，问题在于**测试边界画在了类库层，而漏洞在 Web 配置层**。

**结论**：私有目录可直链访问这条 P0 是**路径推导结论**（两个文件各自正确、组合起来错误），必须用上面第 1 组命令实测确认后再动手修。
