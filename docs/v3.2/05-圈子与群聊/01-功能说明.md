## 一、这个功能解决什么问题

论坛解决"跟全校说话"，圈子解决"跟同好说话"。两件事的产品差异很大：

- **论坛**：内容公开、按时间流、靠推荐分发。
- **圈子**：有成员关系、有实时群聊、有"连续活跃"的运营抓手（火花）。

圈子要解决三个问题：

1. **找到同好**：发现页按分类浏览圈子、热门圈子轮播、加入/退出（`pages/discover/discover.js:100-131`）。
2. **实时聊天**：进圈后进群聊，消息 HTTP 落库 + WebSocket 广播，支持重连补量与已读（`CircleChatController.java:24-59`，`utils/chat-sync.js:65-104`）。
3. **留住活跃**：某圈一天只要有一条有效消息就算活跃，连续 3 天点亮"火花"（`CircleStreakService.java:14-25`）。

火花是本模块唯一的**增长机制**：它是给圈主看的"你这个圈子活着"的反馈，也是运营判断哪些圈该给流量、哪些该关停的依据。

## 二、用户看到的样子（小程序端）

### 2.1 发现页（`pages/discover`）

已注册在 `app.json:5`。页面结构（`pages/discover/discover.js:60-140`）：

1. 顶部热门圈子轮播：`GET /api/circles/hot?limit=5`（`discover.js:118`）。
2. 分类栏：来自 `GET /api/circles/categories`，失败用本地兜底分类（`discover.js:100`）。
3. 圈子列表：`GET /api/circles?category=&page=1&size=50`（`discover.js:131`），一次拉 50 条，**不分页**。
4. 每张卡片显示：名称、分类、简介、人数、帖子数、未读数、最后一条消息摘要、**火花状态**（`discover.js:49-64`，`discover.wxml:79`）。
5. 卡片上的"加入"按钮：`POST /api/circles/{id}/join`（`discover.js:181`）。

### 2.2 圈子详情（`pages/circle-detail`，已注册 `app.json:7`）

- 头部展示圈子信息 + **火花块**：已点亮显示"连续 N 天"，未满 3 天显示"连续 N/3 · 再 X 天点亮"，今天没活跃显示"今日待续上"，断了整块不渲染（`circle-detail.js:26-40`，`circle-detail.wxml:32-36`）。
- 圈内帖子流：`GET /api/circles/{id}/posts`（`circle-detail.js:96,116`）。
- 加入/退出：按当前 `joined` 切（`circle-detail.js:138`）。
- 发圈内帖入口 → `pages/circle-publish`（已注册 `app.json:9`）。

### 2.3 群聊（`pages/circle-chat`，已注册 `app.json:8`）

1. 进页面先 `ensureLogin` → 拉最近 30 条 → 连 WebSocket → 再按 `afterId` 补一次增量（`circle-chat.js:68-76`）。
2. 消息 HTTP 发送：`POST /api/circle-messages`，带 `clientId` 做幂等（`CircleChatController.java:33-47`）。
3. WebSocket 只收不写：客户端只发 `pong`（`CircleWebSocketHandler.java:47-52`）。
4. 断线重连：`utils/chat-sync.js` 先把最新一页渲染出来，再在后台 8 秒预算内向前分段补齐缺口（`chat-sync.js:65-104`）；补不完就丢掉缺口前的旧消息，允许用户上拉继续取（`chat-sync.js:46-49`）。
5. 在线人数与名单：WebSocket `online` 事件推送（`CircleWebSocketHandler.java:63-68`）。
6. 已读：进页面记 `lastReadId`，未读数按 `circle_read` 表算（`CircleChatMapper.java:74-85`）。

### 2.4 用户看到的"红线"

- **圈子里没有任何举报入口**：`grep -rn "report" pages/circle-detail pages/circle-chat pages/discover` 零命中。用户在群里被辱骂、看到违规内容，只能退出圈子。
- 火花断档会直接归零（不是"保留记录"），用户看到的是 `0`（`CircleStreakService.java:94-95`）。
- 用户建圈后接口固定返回 `status=pending`，前端只能显示"提交成功，等待审核"（`CircleService.java:166`）。

### 7.3 火花（连续活跃）

规则（`CircleStreakService.java:17-24`、`67-78`）：

1. 一个自然日 + 一个圈子 + 至少一条**真正落库且过审**的消息 = 记 1 天。
2. 连续满 3 天点亮；漏一天归零，下次从 1 重新开始。
3. 日期按 `Asia/Shanghai` 判定，不依赖服务器时区、不依赖设备时间（`CircleStreakService.java:32,40-42`）。
4. 系统消息、审核拒绝、发送失败不计（`CircleChatService.java:102-105` 只在 `created` 为真时调用）。
5. 并发靠 `INSERT IGNORE` + `(circle_id,active_date)` 唯一键，不靠"先查再插"（`CircleStreakMapper.java:15-27`）。
6. 展示时**再算一次**：`last_active_date` 早于昨天则展示 0，不拿库里旧值骗人（`CircleStreakService.java:88-105`）。

### 7.4 明确不做的事

- 不做群聊内容审核台、不做群消息举报、不做群消息撤回/删除。
- 不做火花奖励：点亮火花不发积分、不触发任何权益（`CircleStreakService.java` 全文无权益调用）。
- 不做圈主权限体系：`circle_member.role` 只在建圈时写 `owner`（`CircleMapper.java:102`），全仓库无任何地方按 `role` 判权限。
- 不做圈子自身的举报入口（`ContentReportService.java:29` 的类型白名单里没有 circle）。
