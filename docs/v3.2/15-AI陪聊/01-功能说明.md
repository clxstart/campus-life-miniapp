## 一、这个功能解决什么问题

给小程序一个"随时能说话"的入口：今天吃什么、有什么活动、有兼职吗、陪我聊聊。

**必须先说清它是什么**：这不是大语言模型。它是**关键词匹配 + 话术库**（`AiChatService.java:38-75`）。命中哪条规则就回哪句话，部分意图会用真实校园数据（`enrichWithCampusData`，`:241`）把话术里的空填上。全链路没有一次外部模型调用。

## 二、用户看到的样子（小程序端）

1. 首页「✦」按钮 → `/pages/ai-chat/ai-chat`（`pages/index/index.wxml:33-36`、`pages/index/index.js:161`）；
2. 进页 `GET /api/ai/welcome` 取欢迎语与快捷追问（可被运营在后台改，`AiChatService.java:179-189`）；
3. 发消息 → `POST /api/ai/chat`，带 `userId` + `schoolId`（游客也能进，`AiChatController.java:18-20` 注释）；
4. 后端按"关键词长度优先 + 优先级"选一条规则（`AiChatService.java:208-240`）；
5. 命中：回 `reply` + `quickReplies`；未命中：回兜底话术（配置或内置），并把问题记日志供运营补规则（`AiChatService.java:47-60`）；
6. 每次对话都会写一条 `ai_chat_log`（原文截断到 200 字，`:78-92`）。

无「AI 生成」标识、无免责声明、无"仅供参考"提示（`pages/ai-chat/*` 全文无相关文案）。

## 五、数据表与字段

| 表 | 关键字段 | 用途 | 谁写 |
|---|---|---|---|
| `ai_chat_rule` | `category`、`keywords`（逗号分隔）、`reply`、`quick_replies`、`priority`、`status` | 话术规则（种子 24 条） | 管理端 |
| `ai_chat_log` | `user_id`、`school_id`、**`message`（用户原话，≤200 字）**、`matched`、`category`、`rule_id`、`created_at` | 对话日志 / 未命中分析 | 服务端每次对话写 |
| `ai_chat_config` | `config_key`、`config_value` | 欢迎语、兜底快捷语 | 管理端 |

迁移脚本：`module-ai-chat.sql`（规则表 + 种子）、`module-ai-config.sql`（日志表 + 配置表）。

⚠️ `ai_chat_log.message` 是**用户原话明文**，没有脱敏、没有保留期、没有字段级访问控制。用户可能在闲聊里输入手机号、宿舍号、姓名。

## 七、业务规则与边界（什么情况会拒绝、什么情况会兜底）

| 场景 | 现状 | 证据 |
|---|---|---|
| 功能开关关闭 | 拒绝「AI 陪聊维护中，请稍后再来」 | `AiChatController.java:32-34` |
| 消息为空 | 「说点什么吧」 | `AiChatService.java:40` |
| 消息 >200 字 | 「消息不能超过 200 字」 | `AiChatService.java:41` |
| 频率限制 | 每 `userId` 每小时 60 条 | `AiChatController.java:36-37`、`RateLimiter.java:38` |
| 匿名用户限流键 | `userId` 缺省 1 → **所有游客共用 `ai:1` 配额** | `AiChatController.java:35` |
| 未命中规则 | 回兜底话术（可配置），并记 `matched=0` 日志 | `AiChatService.java:47-60` |
| 内容命中敏感词 | **不做任何检查**：不走 `AuditService.checkText` | `AiChatService.java:38-92`（全文无 audit） |
| 用户输入含个人信息 | 原文入库，管理端可见 | `module-ai-config.sql:15`、`AiBot.vue:112` |
| 规则回复由运营随便写 | 回复文本无审核、直出 | `AiChatService.java:62-74` |
