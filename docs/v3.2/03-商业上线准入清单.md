# 03 · 商业上线准入清单（Gate）

> 复核时间：2026-11-10 10:45
> 用途：把"能不能上线"从争论变成**一张可勾选、可签字、可复验**的表。
> 依据：30 个功能文档的 `04-商业上线核查.md` + `01-上线风险总表.md` 的 40 个 P0。

---

## 一、Gate 怎么判

| 判定 | 含义 | 谁能签 |
|---|---|---|
| ✅ 通过 | 全部检查项满足，且有可复验证据 | 技术负责人 |
| 🟡 有条件通过 | 有明确条件 + 验收方式 + 截止时间 | 技术负责人 + 业务负责人 |
| ❌ 不通过 | 存在 P0，或关键证据缺失 | —— |

**当前总判定：8 维中 0 维通过、2 维有条件、5 维不通过、1 维未验证。** 不具备上线条件。

## 六、上线后 7 天观察项

| 指标 | 看什么 | 异常阈值（建议） |
|---|---|---|
| 注册成功率 | 新用户是否 500 | 失败 > 1% 立即回滚相关变更 |
| 支付未验签数 | 回调是否异常 | 出现即告警 |
| 退款率 / 退款金额 | 是否被恶意退 | 单日退款额 > 订单额 5% 升级 |
| 内容拦截率 | 审核是否真在跑 | 拦截数为 0 且有人在发帖 = 审核可能没生效 |
| 审核跳过日志 | `AuditService` 的 skip warn | 出现即查配置 |
| 结算账单 vs 订单数 | 是否漏结算 | 差异 > 0.5% 人工核 |
| 接口错误率 | 5xx / 429 | 5xx > 0.5% 回滚 |

## 七、一句话总结

**这套代码的功能完成度不低，但"上线"要求的是另一套东西：能付钱、能证明没泄露、能扛住审核、出事能回滚。当前 8 维里 0 维通过。先按第四节 1–10 做完，才谈得上"上线"；11–12 做完，才谈得上"商业"。**
