## 一、这个功能解决什么问题

把"学生付钱给商家"这件事拆成三个必须可独立验证的环节，任何一个环节做错都会直接丢钱：

1. **收钱**：用户点「支付」，平台向微信下单拿到 `prepay_id`，用户付款，微信回调通知平台，平台落账并把订单改成已付。
2. **对账**：万一回调丢了、晚了、重复了、金额不对，平台要能自己发现并收敛，不能靠用户投诉。
3. **退钱**：用户取消、商家拒单、关单后却到账——三种场景都要把钱退回去，且**绝不能退两次**。

代码里这三件事分别落在：`PayService`（编排）、`PaymentLedgerService`（唯一入账口）、`RefundInitiationService` + `UserRefundService` + `MerchantRefundService` + `MerchantRefundStatusService`（退款四段式）、`PaymentCompensationService`（异常单补偿）。

## 二、用户看到的样子（小程序端）

| 步骤 | 入口 | 页面 | 关键行为 |
|---|---|---|---|
| 1 | 结算页点「提交订单」 | `pages/food-order/food-order.js:53` | 先 `POST /api/orders` 建单，拿到 `orderId` |
| 2 | 立刻发起支付 | 同上 `:60` | `api.payOrder(orderId)` → `POST /api/orders/{id}/pay` |
| 3a | 后端返回 `simulated:true` | 同上 `:67` | 直接进轮询，不走收银台（说明本机用的是模拟支付） |
| 3b | 后端返回收银台参数 | 同上 `:68` | `wx.requestPayment` 拉起微信付钱 |
| 4 | 轮询订单状态 | 同上 `:91-105` | 最多 10 次 × 2 秒；仍拿不到 `paid` 就提示「支付结果还在确认中，请稍后在订单中查看」 |
| 5 | 看订单进度 | `pages/food-order-detail/food-order-detail` | 每 3 秒轮询；`refunded` 显示「已退款」 |

### 2.1 小程序端**没有**的东西

- **没有「申请退款」**：`utils/api/market.js` 里没有 `POST /api/orders/{id}/refund` 的封装，页面也没有按钮。用户想退钱只能打电话。
- **没有「取消待支付订单」**：同上，缺 `POST /api/orders/{id}/cancel`。
- **看不到退款进度**：`pages/food-order-detail/food-order-detail.js:3-12` 的状态表里没有 `refunding`，订单进入退款流程后页面显示「订单处理中」。
- **收不到退款结果通知**：退款结果只写站内信（`notification` 表），小程序没有订阅消息授权流程。

结论：小程序端只在"付钱那一刻"接入了支付，**退钱完全依赖人工**。

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 支付会被拒绝的情况

| 现象 | 拒绝方式 | 证据 |
|---|---|---|
| `pay.enabled=0` | 「支付通道维护中，请稍后再试」 | `PayController.java:28-30` |
| 订单不是自己的 | 403「无权操作该订单」 | `PayService.java:364-367` |
| 没登录 | 401「请先登录后操作订单」 | `PayController.java:71-75` |
| 订单已是 `paid` 或更后 | 幂等返回「已支付」，不重复下单 | `PayService.java:75` |
| 订单不是 `created+unpaid` | 「订单当前不可支付」 | `PayService.java:76` |
| 微信支付未启用且未允许模拟 | 「微信支付未配置，暂不能在线支付或退款，请稍后再试」 | `PayService.java:379-381` |
| prod profile 下开模拟支付 | 启动阶段就拒绝，服务起不来 | `ProductionConfigValidator.java:56-58` |
| 用户没有 openid | 「用户未绑定微信，无法发起支付」 | `PayService.java:85` |

### 7.2 回调与对账的收敛规则

- **验签失败**：不写任何数据库记录，只计数 + 限速告警，返回 401（`PayService.java:126-131`）。伪造请求无法制造流水。
- **非 SUCCESS 状态**：不入账，交给对账流程决定是否关单（`PaymentLedgerService.java:54`）。
- **金额不符**：登记 `AMOUNT_MISMATCH` 异常单，**不改订单状态**（`PaymentLedgerService.java:64-69`）。
- **本地无此订单**：登记 `UNKNOWN_ORDER`（`PaymentLedgerService.java:59-63`）。
- **同单二次扣款**：交易号不同则登记 `DUPLICATE_PAYMENT`；交易号相同视为重复回调（`PaymentLedgerService.java:84-90`）。
- **已关闭/已取消后到账**：登记 `PAID_AFTER_CLOSE`，由补偿任务用确定性单号 `PAC{exceptionId}` 自动退款（`PaymentLedgerService.java:91-97`、`PaymentCompensationService.java:83-92`）。
- **对账节奏**：5 分钟后开始核验、15 分钟关单、渠道持续不可达 120 分钟强制本地关单（`PayService.java:255-259`），单轮预算 20 秒、批 100 单、60 秒一轮（`application.yml`）。

### 7.3 退款规则

| 订单状态 | 能否进退款 | 证据 |
|---|---|---|
| `created`（未付款） | 不能，只能取消 | `RefundInitiationService.java:57-59`、`OrderStatus.java:33` |
| `paid/accepted/delivering/picked/completed` | 能，**全部能吃，包括已送达** | `RefundInitiationService.java:29-31` |
| `refunding` / `refunded` | 幂等返回既有退款单，不新建 | `RefundInitiationService.java:53-56` |
| `cancelled` / `closed` | 不能走这条路（走补偿任务） | `OrderStatus.java:44` |

退款结果状态映射：`SUCCESS → success`、`PROCESSING → pending`、`CLOSED/ABNORMAL → failed`，且**终态不可回退**（`MerchantRefundStatusService.java:125-132`）。退款成功会同时：核销券作废、冲销平台补贴账、订单转 `refunded`、写站内信（同一个 `REQUIRES_NEW` 事务，`MerchantRefundStatusService.java:137-175`）。
