## 一、设计优点（为什么这么设计，好在哪）

1. **复用论坛而不是另起一套。** 学习专区只加了 `post.learn_category` 一列（`module-learn.sql:4-8`），发布、审核、点赞、评论、举报、校隔离全部白拿。这让一个"新功能"的代码量只有 15 行 SQL + 26 行 api 封装。
2. **因此天然继承了内容审核与举报。** `publishPost` 走 `AuditService.checkText`（`ForumService.java:136-137`），评论也过审（`:166`）。很多"新功能"最缺的就是这两样，这里是免费的。
3. **游标分页，不用 offset。** 用 `beforeId` 做主键游标（`utils/api/learn.js:5-12`），列表加载期间有人发帖/删帖也不会翻页重复或漏读。这是比首页推荐（用 offset 取模）更严谨的做法。
4. **强制本校可见，且明确拒绝跨校。** `crossSchool=true` 直接抛「学习交流仅在所选学校可见」（`ForumService.java:141`）。学习互助本质上依赖同校（同一门课、同一个老师），这个约束是对的。
5. **索引与查询条件完全对齐。** `idx_post_learn(school_id, learn_category, status, id)`（`module-learn.sql:10`）就是一个覆盖"本校+本类+有效+游标"的复合索引。
6. **离线体验是仓库里的正确示范。** `offline:true` 被 UI 真正使用：顶部 banner、列表副标题「等待网络恢复」、空态按钮从"发布"变成"看入门建议"、点赞时明确拒绝并说明原因（`pages/learn/learn.js:44-45`、`:58-59`、`:75`、`:102`、`learn.wxml:7`、`:29`）。对比首页推荐"丢掉 offline 标记"，这里有完整交代。
7. **发布页贴心且不啰嗦。** 离开前只在真有内容时才确认「内容不会保存」（`learn-publish.js:85-87`）；提交成功后才锁按钮，失败可重试（`:77-80`）。
8. **每个分类都有"如何有效提问"的静态引导。** `utils/learn.js` 里 5 组 `tips` 不是装饰——它降低了低质量求助帖的比例，是内容质量的前置治理。

## 二、设计缺点与代价（架构/体验/合规/维护）

1. **首页卖的是"真人辅导"，交付的是"论坛分类"。** 首页学习专区卡写着「学习专区 · 作业答疑 · 论文指导 · 学习好物」「真人辅导」「全科可问」（`pages/index/index.wxml:109-141`）。点进去是一个帖子列表：不能下单、不能报价、不能看老师资质、不能直接联系。用户（尤其家长视角的付费方）会认为这是一个"接单平台"。这是**宣传与能力不符**，比功能缺失更危险——它会在客服、投诉、甚至监管问询时暴露。
2. **没有交易闭环，所以这个板块无法商业化。** 想收钱就得有：服务定义、报价、下单、支付、交付、评价、退款。现在一样都没有。首页把它和"外卖/二手/兼职"并列为五大入口，会让人误以为它同等级可用。
3. **分类写死在两端。** 客户端 `utils/learn.js` 5 个常量 + 服务端 `LEARN_CATEGORIES` 白名单。运营想加「四六级」「竞赛」必须发版；改个分类名也要发版。而同一仓库里的其它运营配置（如 `ai_chat_config`）已经做成表驱动，这里没有。
4. **运营完全看不见"学习专区"这个业务线。** 后台只有"内容管理（全部帖子）"和"审核台"。没有按 `learn_category` 筛选、没有分类计数、没有优质帖置顶。内容量一上来，运营无法分层治理。
5. **发布只能 1 张图，不能传附件。** 学习互助最高频的物料是真题、课件、笔记（PDF/Word/压缩包），现在只能发图片（`learn-publish.js:29`）。这是"功能看起来有了，实际用不了"的典型。
6. **`learn/counts` 成了死接口。** 角标下线后页面不再调用（`pages/learn/learn.js:35`），但 `utils/api/learn.js:18-24` 仍导出、后端仍保留接口。死代码会误导后来的人以为有人在用。
7. **学习帖与普通帖在治理层面完全混同。** 举报处理页、内容管理页都无法区分，意味着"学习专区的违规率"这个指标永远算不出来。

## 三、权衡过的替代方案（如果不这么做还能怎么做，为什么没选）

| 方案 | 做法 | 为什么当前没选 | 代价/收益 |
|---|---|---|---|
| 独立 `learn_post` 表 + 独立审核 | 业务隔离彻底 | 要重写发布/审核/举报/点赞，约 10 人日，且与论坛重复 | 不选是对的 |
| 建"答疑接单"轻交易闭环 | 老师发布服务卡 → 学生下单 → 平台担保 | 涉及支付、结算、资质，属另一条业务线 | 约 15–20 人日；不做则首页文案必须改 |
| 分类表驱动 | `learn_category` 配置表 + 后台 CRUD | 未评估 | 约 1 人日；消灭 14-03 |
| 支持附件 | 上传白名单扩 pdf/doc/zip + 预览页 | 未评估 | 约 2 人日（含安全校验与存储成本） |
| 学习帖独立运营页 | 按分类筛选 + 置顶 + 专题合集 | 未评估 | 约 2 人日 |

## 五、如果重做会怎么改

1. **先定业务形态，再定实现。** 如果目标是"知识分享社区"，就把首页文案改成"学习交流"，删掉"真人辅导/全科可问"，本站只做内容不做交易。如果目标是"答疑接单"，就必须先有服务卡 + 报价 + 担保交易，否则不要在教育这个强监管品类上给出付费暗示。
2. **分类配置化**：`learn_category(key, label, hint, guide, tips, sort, enabled)`，后台可增删改。这样"加一个四六级板块"是运营动作而不是发版动作。
3. **支持附件**：学习内容的载体天然是文件。图片只是封面，正文应是可下载的资料 + 可预览的文档。安全上必须做类型白名单 + 大小限制 + 病毒/敏感扫描（至少大小与类型）。
4. **给学习帖单独的治理视图**：按分类看新增量、违规率、平均互动。治理指标要能和普通水帖区分开。
5. **保留离线那套写法**：`offline` 标记贯穿 UI 是这个小模块最值得复用的模式，应当反向推广到首页推荐与二手列表。
