## 四、数据与迁移（前置 SQL、执行顺序、回滚 SQL）

**结论：有条件通过（条件：先跑论坛/学校基础迁移，再跑本脚本；demo 种子可选）**

```bash
# 0) 前置：基础 schema + 多校字段（post.school_id）
# 1) 学习专区字段 + 索引（幂等）
mysql -u root -p campus_life < backend/src/main/resources/db/module-learn.sql
# 2) 可选：演示内容
mysql -u root -p campus_life < backend/src/main/resources/db/module-learn-demo.sql
# 3) 核对
mysql -u root -p campus_life -e "
SELECT learn_category, COUNT(*) FROM post WHERE learn_category IS NOT NULL GROUP BY learn_category;
SHOW INDEX FROM post WHERE Key_name='idx_post_learn';"
```

- 本次**未执行**，原因：无 MySQL 会话。

回滚 SQL：

```sql
DROP INDEX idx_post_learn ON post;
ALTER TABLE post DROP COLUMN learn_category;
```

⚠️ 回滚会丢掉全部学习分类归属（帖子本身保留，变成普通帖）。**不可恢复分类信息**，除非先 dump。上线后如要回滚，建议只回滚代码（多一列不影响运行）。

## 九、结论

**有条件上线（条件：1. 改掉"真人辅导/全科可问"文案；2. 代写类词进必拦词库；3. 内容安全参数必须配置）**

- 无 P0 阻断项。这条业务线的技术实现是干净的：复用论坛带来了审核、举报、权限、校隔离，全部到位。
- 真正的风险不在代码，在**表述**。首页把它包装成"人工辅导服务"，而系统交付的是"帖子列表"。只要改文案（0.2 人日），这个板块就是一个健康的社区板块。
- 若产品确实想做付费答疑，那必须先补交易闭环（15+ 人日）与师资资质审核，不能用当前形态对外承诺。
