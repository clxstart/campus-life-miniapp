## 二、后端：逐条核对

- 🟡 推荐接口按 `batch`/`perType` 出卡，返回 `cards/batch/shopTotal/goodsTotal/hasMore/generatedAt` —— 证据：`RecommendController.java:19-26`、`RecommendService.java:131-139`
- 🟡 热度公式：二手 `浏览×3 + 收藏×5 + 咨询×8`；外卖 `真实订单×5 + 浏览×1` —— 证据：`RecommendMapper.java:22`、`RecommendMapper.java:50`
- 🟡 同分排序确定性：二手 `heat DESC, created_at DESC, id DESC`；外卖 `heat DESC, rating DESC, id` —— 证据：`RecommendMapper.java:25`、`RecommendMapper.java:53`
- 🟠 推荐榜**未过内容审核口径**：二手查询只有 `WHERE g.status=1`，而同列表页要求 `status=1 AND audit_status='passed'` —— 证据：`RecommendMapper.java:24` 对比 `ModuleMapper.java:23`
- 🟠 推荐榜**未按学校隔离**：`hotGoods`/`hotShops` 两条 SQL 均无 `school_id` 条件，控制器也不接收 `schoolId` —— 证据：`RecommendMapper.java:23-24`、`RecommendMapper.java:51-52`、`RecommendController.java:19-26`
- 🟡 收藏关系独立成表，不污染帖子收藏 —— 证据：`module-hotness.sql:35-42`
- 🟡 收藏数按表重算而非 +1，避免并发漂移 —— 证据：`RecommendMapper.java:75-77`
- 🔴 `viewGoods`/`contactGoods`/`viewShop` 三个自增**无去重、无限流**：同一账号循环 POST 即可刷量 —— 证据：`RecommendMapper.java:63-64`、`:79-80`、`:82-83`；`RecommendController.java:38-47` 未调用 `RateLimiter`
- 🟡 缓存：`CACHE_TTL_MS=60_000`、`ConcurrentHashMap`、key 为 `goods:size:offset` —— 证据：`RecommendService.java:26-55`
- 🟠 缓存无主动失效：`toggleGoodsFavorite`/`viewGoods`/`orderPlaced` 均不清 key —— 证据：`RecommendService.java:157-175`
- 🟠 缓存是进程内单机：多实例各存各的，同一时刻两个用户可能看到不同推荐 —— 证据：`RecommendService.java:32`（`private final Map`，未走 `ha/` 里的 Redis）
- 🔴 缓存无命中率/回源次数指标 —— 证据：全文件无 counter/日志埋点，`RecommendService.java:35-43`
- 🟡 排序键是计算式，`idx_goods_hot` 用不上（作者自认）—— 证据：`module-hotness.sql:47`、`RecommendService.java:19-21` 注释
- 🟡 Banner 管理端 CRUD 齐全（列表含分页与校域） —— 证据：`AdminModuleController.java:393-419`
- 🔴 匿名访问默认按 user 1 出星标 —— 证据：`RecommendService.java:84`、`CurrentUser.java:33-35`
