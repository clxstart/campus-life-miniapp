## 二、资金与对账

**结论：不通过（原因：配送报酬无任何结算出口；骑手可见收入与账本口径不一致）。**

- **本域不持有资金**：`earnings_ledger` 明确"不是钱包余额、不是已付款、不可提现"（`backend/src/main/resources/db/module-earnings-ledger.sql:1-8`），`wallet.enabled=0`（`backend/src/main/resources/db/module-safety-gates.sql:7`）。
- **P0 缺陷**：配送报酬没有结算出口——没有结算单、没有批量打款、没有"平台已支付骑手"的确认（见 10-01）。平台无法证明"这笔钱该给谁、给了没"。
- **防重复结算：通过**。`delivery_pay_recorded` 条件更新 0→1（`backend/src/main/java/com/campuslife/mapper/DispatchMapper.java:126-130`）+ `biz_no` 唯一键（`earnings_ledger` 表约束）+ 0 行时区分"已存在/真失败"（`service/DispatchService.java:202-211`）。三处都在，这一项是本域做得最好的。
- **金额快照：通过**。`delivery_pay_cents = ROUND(delivery_fee*100)` 在派单/改派时落快照（`DispatchMapper.java:46`、`:70`），记报酬读快照（`DispatchMapper.java:132-133`）。
- **金额口径分裂（P1）**：页面"共赚"取 `SUM(delivery_fee)`（元，含不计酬单），账本取 `delivery_pay_cents`（分，排除不计酬）（`RiderMapper.java:105-111` vs `DispatchService.java:181-199`）。见 10-06。
- **不计酬的单对学生没有交代**：接管且不计酬时只写一条 0 元 `void` 记录（`DispatchService.java:185-193`），学生照付配送费，方案要求的"免收或退回"未实现（方案 `docs/校园帮功能方案-兼职钱包配送与圈子.md:162`）。
- **无对账**：没有"当日应结配送费总额 vs 账本总额"的核对任务，也没有差异清单。现有 4 个定时任务里没有一个是配送对账（`service/PayService.java:273` 是支付对账，不含配送报酬）。

## 四、数据与迁移（前置 SQL、执行顺序、回滚 SQL）

**结论：有条件通过（条件：先备份、按序执行、生产只允许关闸门不允许删表）。**

### 4.1 执行顺序

| 顺序 | 脚本 | 内容 | 依赖 |
|---|---|---|---|
| 1 | `backend/src/main/resources/db/module-rider.sql` | `user_order` 加 7 列、`admin_user` 加 2 列、`shop` 加 2 列、2 个索引 | `user_order`/`admin_user`/`shop` 已存在 |
| 2 | `backend/src/main/resources/db/module-rider-dispatch.sql` | 建 `building`、`order_dispatch_log`；`user_order` 加 6 列 | 第 1 步（同表加列，避免并发 ALTER 冲突） |
| 3 | `backend/src/main/resources/db/module-earnings-ledger.sql` | 建 `earnings_ledger` | 无（若先于兼职域执行也安全） |
| 4 | `backend/src/main/resources/db/module-safety-gates.sql` | `rider.grab.enabled=0` | `feature_flag` 表 |

> 顺序依据：两个骑手脚本都对 `user_order` 做 `ALTER`，必须串行；本顺序**未实际执行验证**（推测）。

### 4.2 幂等性

- 全部加列前查 `information_schema`（`module-rider.sql:4-36`、`module-rider-dispatch.sql:19-32`）。
- 建表 `CREATE TABLE IF NOT EXISTS`（`module-rider-dispatch.sql:6`、`:35`）。
- 索引前查 `information_schema.statistics`（`module-rider.sql:38-43`）。
- 演示 seed 需显式 `SET @ALLOW_DEMO_SEED='YES'`（`module-rider.sql:48`）。

### 4.3 回滚

**⚠️ 没有回滚脚本。** 手写如下（只在试运行环境执行）：

```sql
-- 回滚（先 dump；生产环境禁止执行删表）
DROP TABLE IF EXISTS order_dispatch_log;
DROP TABLE IF EXISTS building;
ALTER TABLE user_order
  DROP COLUMN rider_id, DROP COLUMN rider_name, DROP COLUMN accepted_at,
  DROP COLUMN picked_at, DROP COLUMN delivered_at, DROP COLUMN contact_name,
  DROP COLUMN contact_phone,
  DROP COLUMN building_id, DROP COLUMN dispatch_status, DROP COLUMN actual_rider_id,
  DROP COLUMN dispatch_note, DROP COLUMN delivery_pay_cents, DROP COLUMN delivery_pay_recorded,
  DROP COLUMN delivery_pay_counted;
ALTER TABLE admin_user DROP COLUMN rider_status, DROP COLUMN phone;
ALTER TABLE shop DROP COLUMN address, DROP COLUMN contact_phone;
ALTER TABLE user_order DROP INDEX idx_rider, DROP INDEX idx_order_status_shop_created;
DELETE FROM feature_flag WHERE flag_key='rider.grab.enabled';
-- 骑手账号：只停用，不删（admin_user 有历史外键引用）
UPDATE admin_user SET status=0, token_version=token_version+1 WHERE role='rider';
```

**风险**：`user_order` 一次撤 15 列会丢配送全链路数据；`shop.address`/`contact_phone` 撤了会让商家与骑手都看不到取餐地址（骑手池查询用 `COALESCE(NULLIF(s.address,''),s.notice,'')`，撤列直接 500）。所以**生产回滚只能关开关 + 停账号，不能撤列**。

## 九、结论

**不可上线。** 阻断项：**10-01**（配送报酬无任何结算出口，骑手拿不到钱）、**10-02**（送达零凭证，骑手单方点完成即记报酬，学生无确认与申诉入口）。

补充说明：若产品决定"骑手由平台线下发工资、系统只做记录"，则 10-01 可降级为 P1（需在骑手端页面把"共赚 ¥X"改成"平台待结算 ¥X"并给出结算周期）；但 **10-02 不可降级**——虚假送达在任何一个真实场景里都会发生，且无法用运营手段弥补。
