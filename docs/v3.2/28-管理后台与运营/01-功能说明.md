## 一、这个功能解决什么问题

这是平台方的**驾驶舱**。它不服务学生，只服务两类人：平台超管（看全平台）、学校校管（看本校）。它要回答四个问题：

1. **现在怎么样？**——看板：用户/帖子/圈子/商品/兼职/活动/评论/订单八个计数 + 近 7 天发帖趋势（`AdminModuleService.java:61-70`）。
2. **有什么要处理？**——审核台：6 类内容（帖子/评论/商品/兼职/私信/圈子）的待审队列、通过/驳回/恢复，以及敏感词表维护（`AdminAuditController.java:20-105`）。
3. **谁动了什么？**——操作日志：谁、什么时候、从哪个 IP、改了什么（`AdminAuthController.java:111-125`）。
4. **系统还活着吗？**——系统状态：数据库、上传目录、磁盘、连接池、JVM、慢请求、今日前端错误数（`SystemStatusService.java:39-49`）。

外加三个「出事了能止血」的能力：功能开关（关一个功能不用发版）、运营配置（改文案/二维码不用发版）、HA 模式（单机/集群切换）。

## 二、用户看到的样子（小程序端）

本功能不面向小程序用户。间接影响：

1. 管理员在下架违规帖子 → 小程序帖子列表立刻消失（`AdminModuleService.java:117-123`，直接改 `post.status`）。
2. 管理员在审核圈子 → 通过后小程序圈子列表出现，驳回会带原因通知创建者（`AdminModuleService.java:592-615`，含站内通知）。
3. 管理员改 Banner → 小程序发现页轮播位变化（但运营配置路由当前**已从 Web 菜单下线**，见第七节）。
4. 管理员关功能开关 → 小程序对应入口显示「维护中」+ 运营填的文案（`FeatureFlags.java:59-64`）。

后台共 **30 条路由**（`web/src/router/index.js:18-64`），本章覆盖其中 7 个页面：

## 七、业务规则与边界

**会拒绝的情况**

1. 非 super 调用学校/管理员/功能开关/运营配置/任务目录/兑换商品池写接口 → 403（各自的 `requireSuper`）。
2. 校管传别校 `schoolId` 到列表接口 → 403「只能查看本校数据」（`AdminModuleController.java:446-449`）。
3. 审核驳回不填原因 → 400（`AuditService.java:428-431`）。
4. 学校不存在时 `updateSchool` 影响行数为 0 → 400「学校不存在」（`AdminModuleService.java:100`）。
5. 学生认证/创业者等敏感词写的接口？—— 见下条，这类**没有**拒绝规则。

**会放行、但按规范不该放行的情况**

1. 校管可以增/改/删全平台敏感词表（`AdminAuditController.java:69-92`，无 super 校验）。
2. 校管可以改全平台 AI 规则（`AiAdminController.java:30-66`）——而 Web 菜单对他是隐藏的。
3. 校管可以读全平台系统状态（JVM、磁盘、全平台业务计数、慢请求日志行）——`AdminSystemController.java:30-33` 无 super 校验。
4. 校管可以读全平台前端错误明细、并 purge 删除（`ClientErrorController.java:46-57`）。
5. 校管可以触发全平台榜单重结算（`AdminForumRankController.java:42-49`）。
6. 导出 CSV 无二次确认、无审计：`web/src/views/Payments.vue:9` 一个按钮直接下载；后端 `AdminOrderController.java:34-35` 与 `AdminPaymentController.java:41-56` 都不写 `admin_log`。
7. 功能开关变更只写 `log.info`（`FeatureFlags.java:79-84`），不落 `admin_log`；`updated_by` 记的是显示名（可能重复）。
8. 运营配置保存同样只写 `log.info`（`AppConfigService.java:90-105`），不落 `admin_log`。

**边界**

- 前端 33 个视图里 18 个用浏览器原生 `confirm()` 做二次确认（`grep -rn "confirm(" web/src/views/*.vue`）；导出、敏感词删除、错误日志清理**没有**确认。
- 服务端**没有任何**二次确认机制（无幂等令牌、无「输入 DELETE 确认」）：客户端 confirm 被绕过时接口照常执行。
