## 一、这个功能解决什么问题

这是**横切模块**：它不属于任何一个业务功能，而是给所有 UGC 通道提供"拦得住、留得下、追得回"的三件事。

| 要解决的问题 | 手段 | 主实现 |
|---|---|---|
| 违规内容进不来 | 本地敏感词 DFA 引擎 + 微信 `msg_sec_check` / `img_sec_check` | `AuditService.java`（553 行）、`SensitiveWordEngine.java`（131 行） |
| 进不来的要有记录 | `audit_log` 表，区分来源（local/wechat/manual/fastlane） | `AuditMapper.java:78-89,131-134` |
| 进来了的能撤下来 | 审核台六类内容：通过/拒绝/恢复 | `AuditService.java:416-459`、`web/src/views/Audit.vue` |
| 用户能投诉 | 举报入队，人工判定，不自动下架 | `ContentReportService.java:95 行`、`web/src/views/Reports.vue` |
| 出事能一键止血 | 功能开关（含"安全闸门"默认关闭的六项） | `FeatureFlags.java`、`db/module-safety-gates.sql` |
| 不被刷 | 固定窗口限流，失败 fail-closed | `RateLimiter.java` |
| 资质类风险 | 校外岗位/有偿接单/替课/自由抢单/钱包/自助认证默认关闭 | `db/module-safety-gates.sql:6-12` |

**为什么它是上线门槛而不是加分项**：微信小程序审核对 UGC 平台有三条硬要求——用户可举报、平台可处置、留存审核记录。这三条全部落在本模块。同时，校园产品的用户是学生（含未成年人），内容事故的后果不只是罚款，还有校方合作关系。

## 二、用户看到的样子（小程序端）

普通用户**看不到"治理"这件事本身**，只能看到它的四种结果：

1. **发不出去**：发帖/评论/私信/建圈命中敏感词 → 提示"内容包含违规词：X、Y"（`AuditService.java:170-173`），列表里不会出现这条内容。
2. **发出去了但别人看不见**：微信判 `review` → `audit_status='reviewing'`、`status=0`，作者自己也就打不开了（`ForumService.java:154,157`）。
3. **被下架了会收到通知**："你的帖子因违反社区规范已被下架"（`AuditService.java:369-371`）或"内容未通过审核" + 拒绝原因（`AuditService.java:438`）。
4. **可以举报**：帖子详情的"更多" → 举报这条帖子，六选一原因（广告/辱骂/色情/诈骗/侵权/其他），提交后提示"已收到举报，我们会尽快处理"（`pages/post-detail/post-detail.js:161-179`）。

用户**看不到**的：

- 举报处理结果没有回执（`ContentReportService.java:60-62` 只返回 `{reported:true}`）。
- 没有"我的举报"列表，无法查询进度。
- 举报入口只覆盖帖子：评论、用户、圈子、群聊消息都没有入口（见 `03-优缺点与问题.md` 29-11）。

### 3.2 举报处理页（`/reports`，`web/src/router/index.js:54`）

- 按状态（待处理/已处理/已忽略）与类型（帖子/评论/二手/消息/用户）筛选（`Reports.vue:11-24`）。

### 3.3 功能开关与安全闸门

`/system` 页可开关六个功能（`ai_chat`/`upload`/`pay`/`enroll.material`/`circle_chat`/`post.publish`，见 `db/module-feature-flag.sql:19-24`；读写接口在 `web/src/views/System.vue:231,241`）。

另有六个**默认关闭**的资质类闸门（`db/module-safety-gates.sql:6-12`）：`wallet.enabled`、`job.offsite.enabled`、`job.paid.enabled`、`job.category.takeover_class.enabled`、`rider.grab.enabled`、`verification.student.enabled`。它们由 `FeatureFlags.enabledStrict` 判定——**查不到就当关闭**，与普通开关的"查不到就当开启"相反（`FeatureFlags.java:37-56`）。

## 七、业务规则与边界（什么情况会拒绝、什么情况会补偿）

### 7.1 文本审核的判定顺序

```text
输入文本
  ↓
① 本地敏感词引擎（DFA，全角/半角归一 + 跳分隔符）
    命中 → 白名单按位置覆盖判断 → 未覆盖 → 拒绝"内容包含违规词：X"
  ↓ 未命中
② 取作者 openid（userMapper.selectById）
    缺 appid/secret          → 直接通过（AuditService.java:180-182）
    openid 空 / dev- 前缀    → 直接通过（:183-186）
  ↓ 有真实 openid
③ 调微信 msg_sec_check
    suggest=risky  → 拒绝"微信内容安全检测未通过"
    suggest=review → 通过但标记 reviewing（等人工）
    suggest=pass   → 通过
    异常/errcode≠0 → 捕获后通过（:204-207）
```

### 7.2 图片审核的判定顺序（仅 post / goods）

```text
① 未配 appid/secret → 直接通过（AuditService.java:297-302）
② 逐张调 img_sec_check
    errcode=87014 → 整体下架 + 通知作者（:307-311）
    errcode≠0     → 抛异常 → 捕获后通过（:317-321）
③ 全部通过 → imagePassed，把 pending 升为 passed
④ 线程池队列满 → 直接通过（:263-267）
```

**注意**：多图帖只要有一张违规就整体下架，不做"删违规图保留合规图"（`AuditService.java:303-314`）。

### 7.3 举报的规则

| 规则 | 实现 | 证据 |
