## 二、启动步骤

### 1. 数据库

```bash
cd backend/src/main/resources/db

# 首次：依次执行（均幂等，可重复跑）
mysql -uroot -p<密码> < schema.sql
mysql -uroot -p<密码> < module-pet.sql
mysql -uroot -p<密码> < module-pet-companion.sql   # 本轮新增
```

`module-pet-companion.sql` 做的改动：
- `user_pet` 增加 `fur / pattern / eyes / mouth / accessory` 五个外观字段
- 新建 `pet_item`（装扮字典）、`pet_item_owned`（拥有记录）
- 新建 `pet_task`（派遣任务字典）、`pet_dispatch`（派遣记录）
- 写入 4 件装扮、4 个派遣任务的种子数据

### 2. 后端

```bash
cd backend
export JAVA_HOME=/e/jdk21        # Windows 用 set JAVA_HOME=E:\jdk21

mvn -DskipTests spring-boot:run
# 启动成功标志：Started CampusLifeApplication in x.xxx seconds
```

默认端口 `8080`，数据库连接在 `backend/src/main/resources/application.yml`。

### 3. 小程序端

```bash
# 1) 安装依赖（已锁定版本）
npm install

# 2) 构建 miniprogram_npm（关键！不做这步 TDesign 组件不可用）
#    方式 A：微信开发者工具 → 工具 → 构建 npm
#    方式 B：命令行
"D:\JavaStudy\微信web开发者工具\cli.bat" build-npm ^
  --project "E:\goodworlk\campus-life-miniapp" --lang zh

# 3) 用微信开发者工具打开项目目录
```

**验证 npm 构建成功**：

## 四、接口清单

所有接口在 `/api/pet` 下，参数 `userId`。

### 外观
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pet/appearance?userId=1` | 读取外观 |
| PUT | `/api/pet/appearance` | 保存外观（body: userId + 五项部件编号） |
| POST | `/api/pet/appearance/reset` | 重置为默认 |

### 衣柜
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pet/wardrobe?userId=1` | 物品列表（含 owned/equipped/state）+ 积分余额 |
| POST | `/api/pet/wardrobe/purchase` | 兑换（body: userId, code） |
| POST | `/api/pet/wardrobe/equip` | 装备（body: userId, code） |
| POST | `/api/pet/wardrobe/unequip` | 卸下（body: userId） |

### 派遣
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pet/dispatch?userId=1` | 任务列表 + 当前派遣状态 |
| POST | `/api/pet/dispatch/start` | 开始派遣（body: userId, code） |
| POST | `/api/pet/dispatch/claim` | 领取奖励（body: userId, dispatchId） |

## 六、已知限制（须明示）

### ⚠️ 未完成的验证

| 项 | 状态 | 原因 |
|---|---|---|
| **微信开发者工具真机/模拟器运行验证** | ❌ **未完成** | 见下方详述 |
| Lottie 破壳动画 | 用 Canvas 替代 | 无可用 Lottie JSON 资源，按"不引入空依赖"处理 |

**关于微信运行验证为什么没做成：**

项目 `appid` 是 `touristappid`（游客模式）。实测结论：

1. `cli preview` → 返回 `code 10`。游客 AppID 不能生成预览二维码
2. `cli auto` 能开启自动化端口，但 `reLaunch` / `currentPage` / `systemInfo` 全部超时
3. **用原有页面 `pages/index/index` 单独测试，同样超时** —— 证明与新增代码无关
4. `miniprogram-automator 0.13.0` 的 `connect()` 内部 `checkVersion()` 对空版本串 `.split` 会崩，已改用底层 `Connection` 绕过，但 IDE 仍不响应业务调用

**要完成这项验证，需要**：
- 真实小程序 AppID（替换 `project.config.json` 的 `appid`）
- 在开发者工具中登录该 AppID 的开发者账号

### 其他限制

| 项 | 说明 |
|---|---|
| 支付 | 模拟（`wxpay.enabled=false`），不产生真实扣款 |
| 微信内容安全 | 未配置 `appid/secret`，审核走本地敏感词 |
| AI 对话 | 当前为 **Mock 适配器**，消息上明确标注"演示数据"；接真实模型需服务端代理 |
| 敏感词表 | 22 条 fraud 类，侧重点在兼职诈骗与学术不端 |
| 衣柜类别 | 第一版只有"配饰"一类 |

## 七、素材与许可

### 宠物美术

**全部为原创 Canvas 矢量绘制**，代码在 `utils/pet-engine.js`。

- 不使用任何第三方图片素材文件
- 5 种毛色 × 4 种花纹 × 4 种眼睛 × 4 种嘴巴 × 5 种配饰，组合由 `utils/pet-appearance.js` 定义
- 因此**不存在**第三方美术的署名义务

### 参考的开源项目

| 项目 | 来源 | 复用什么 | 是否使用其素材 |
|---|---|---|---|
| TDesign 微信小程序版 | `tdesign-miniprogram@1.17.0` | Button/Popup/Tabs/Input/Toast/Dialog 组件 | 组件代码，按其开源许可使用 |
| 微信小程序官方示例 | `miniprogram-demo` | Canvas 2D 节点查询与 dpr 适配写法 | 否 |
| cat-avatar-generator | `vicalejuri/cat-avatar-generator` | **仅"分层部件按编号组合"的思路** | **否**，未使用其任何素材文件 |
| Lottie 小程序版 | `lottie-miniprogram` | 未使用（用 Canvas 实现破壳） | 否 |

### 文字素材

所有 UI 文案（宠物描述、气泡、任务说明）为本项目原创。
