# 生产部署与性能优化指南

> 适用：腾讯云 4核4G 单机部署（Java + MySQL 同机）
> 目标承载：1000 同时在线（多学校场景）
> 编写日期：2026-10-25

---

## 一、这份配置解决什么问题

| 问题 | 优化前 | 优化后 |
|---|---|---|
| 数据库连接池 | 默认 10 个 | **25 个**（可支撑约 1250 QPS） |
| school_id 索引 | 13 张表只有 **5 张**有 | **13 张全覆盖** |
| MySQL 内存占用 | 默认可能吃 1.5G+ | **限制在 700M 内** |
| JVM 堆 | 未指定，可能只给 1G | **锁定 1536M** |

**不做这些优化，4C4G 撑不住 1000 在线；做了之后有余量。**

### 2.2 MySQL 配置文件

编辑 `/etc/mysql/my.cnf`（或 `/etc/my.cnf`，视系统而定）：

```ini
[mysqld]
# ===== 内存控制（4G 机器关键）=====
innodb_buffer_pool_size = 512M      # 数据量小，512M 足够
innodb_log_file_size = 128M
innodb_log_buffer_size = 16M

# ===== 关闭 performance_schema（省 200-400M！）=====
performance_schema = OFF

# ===== 连接数控制 =====
max_connections = 200                # 与 HikariCP 25 匹配，留足余量
wait_timeout = 1800                  # 必须大于 HikariCP max-lifetime(1800)
interactive_timeout = 1800

# ===== 查询缓存与排序（小内存优化）=====
sort_buffer_size = 2M
join_buffer_size = 2M
tmp_table_size = 32M
max_heap_table_size = 32M

# ===== 慢查询日志（排查用）=====
slow_query_log = 1
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 2

# ===== 字符集 =====
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
```

**改完重启**：

```bash
sudo systemctl restart mysql
```

### 2.3 验证内存占用


**预期**：约 500-700 MB。如果超过 1G，检查 `performance_schema` 是否真的关闭。

## 三、应用部署

### 3.1 JVM 参数（关键）

```bash
java -Xms1536m -Xmx1536m \
     -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -XX:MaxMetaspaceSize=256m \
     -XX:+HeapDumpOnOutOfMemoryError \
     -XX:HeapDumpPath=/var/log/campus/heap.hprof \
     -jar campus-life-api.jar
```

**参数说明**：

| 参数 | 值 | 原因 |
|---|---|---|
| `-Xms` / `-Xmx` | 1536m | 4G 机器留 2.5G 给 MySQL + 系统 |
| `-XX:+UseG1GC` | — | 低延迟 GC，适合 Web 服务 |
| `-XX:MaxMetaspaceSize` | 256m | 防止元空间无限增长 |
| `-XX:+HeapDumpOnOutOfMemoryError` | — | OOM 时留存现场，便于排查 |

### 3.2 后台启动脚本

创建 `/opt/campus/start.sh`：

```bash
#!/bin/bash
cd /opt/campus
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk
nohup $JAVA_HOME/bin/java \
  -Xms1536m -Xmx1536m \
  -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
  -XX:MaxMetaspaceSize=256m \
  -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/var/log/campus/heap.hprof \
  -jar campus-life-api.jar \
  --spring.profiles.active=prod \
  > /var/log/campus/app.log 2>&1 &
echo $! > /var/log/campus/app.pid
```

### 3.3 应用配置（生产环境要改）

配置已按 profile 拆开，**不要再改 `application.yml`**：

| 文件 | 用途 |
|---|---|
| `application.yml` | 与环境无关的默认值（端口、连接池、鉴权开关、上传限制） |
| `application-dev.yml` | 本机开发：127.0.0.1 数据库、明文演示密码、模拟支付开启、允许本机跨域 |
| `application-prod.yml` | 生产：**所有敏感项都没有默认值**，缺一个环境变量就启动失败 |

启动时必须显式指定 profile：

```bash
java -jar campus-life-api.jar --spring.profiles.active=prod
```

需要的环境变量（`application-prod.yml` 里全部**无默认值**）：

```bash
export DB_URL='jdbc:mysql://127.0.0.1:3306/campus_life?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false'
export DB_USERNAME='campus_user'          # 不要用 root
export DB_PASSWORD='<强密码>'
export CAMPUS_JWT_SECRET='<32 位以上随机串>'    # 生成：openssl rand -base64 48
export CAMPUS_WX_APPID='wx...'            # 配了微信 AppID 后 /auth/dev-login 自动关闭
export CAMPUS_WX_SECRET='...'
export CAMPUS_WEB_ORIGINS='https://admin.your-domain.com'   # 管理端跨域白名单，逗号分隔
export CAMPUS_UPLOAD_BASE_URL='https://api.your-domain.com' # 上传图片对外基址
# 外卖支付（不接支付可全部留空并保持 WXPAY_ENABLED=false）
export WXPAY_ENABLED='true'
export WXPAY_APP_ID='wx...'
export WXPAY_MCH_ID='...'
export WXPAY_CERT_SERIAL_NO='...'
export WXPAY_API_V3_KEY='<32 位>'
export WXPAY_PRIVATE_KEY_PATH='/opt/campus/certs/apiclient_key.pem'
export WXPAY_NOTIFY_URL='https://api.your-domain.com/api/pay/notify'
export WXPAY_REFUND_NOTIFY_URL='https://api.your-domain.com/api/pay/refund/notify'
```

> **安全提醒**：生产环境不要用 root 连接数据库，单独建一个只对 `campus_life` 有权限的账号。

小程序端后端地址在 `utils/config.js` 里切换（把 `ENV` 改成 `'prod'` 并填真实域名），
同时要在微信公众平台配置 request 合法域名。

### 3.4 接口鉴权（v2 起强制）

`AuthInterceptor` 现在会真正拦人，规则如下：

| 请求类型 | 是否必须带 token |
|---|---|
| 写操作（POST/PUT/DELETE，`/api/**`） | **必须**，无 token 一律 401 |
| 「我的数据」读接口（会话、通知、课表、校历、宠物、`/users/{id}/` 下的收藏/浏览/优惠券/地址/发布数） | **必须**，无 token 401 |
| 公开只读（帖子流、搜索、学校、圈子、商家、二手、兼职、活动、推荐） | 不需要，匿名可读（userId 只用于「我点过赞吗」这类个性化） |
| 例外：`/api/auth/**`、`/api/pay/notify`、`/api/pay/refund/notify`、`/api/ai/**`、`/api/upload` | 不需要 |

同时：

- **身份以 token 为准**。控制器不再相信客户端传来的 `userId`，写请求里即使伪造别人的 `userId` 也只会记在自己名下。
- **`/api/conversations` 等私读接口**还会校验路径里的 `{id}` 必须等于登录用户，不一致返回 403。
- **模拟支付**由 `campus.pay.simulate` 控制：dev 默认开、prod 强制关（prod 下开了也会被代码拒绝）。
- **开发登录**（`/api/auth/dev-login`）默认只能登录 **1 号演示账号**。想切换成别的账号调试多用户，
  需要设 `CAMPUS_DEV_LOGIN_ANY_USER=true`；配置了真实微信 AppID 后整个开发登录自动关闭，
  prod 下这个开关也无效。
- 临时排查可以设 `CAMPUS_AUTH_ENFORCE=false` 关掉强制鉴权，启动日志会打警告，**绝不要带上线**。

## 四、系统层优化

### 4.1 添加 swap（4G 机器必需）

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

**作用**：内存吃紧时兜底，避免直接 OOM 被杀进程。用 swap 会变慢，但总比服务挂掉好。

### 4.2 文件句柄数

```bash
# /etc/security/limits.conf 追加
* soft nofile 65535
* hard nofile 65535
```

**原因**：WebSocket 每条连接占一个文件句柄，1000 连接需要足够配额。

### 4.3 内核参数

```bash
# /etc/sysctl.conf 追加
net.core.somaxconn = 1024
net.ipv4.tcp_max_syn_backlog = 2048
net.ipv4.tcp_tw_reuse = 1
net.ipv4.ip_local_port_range = 10000 65000
```

```bash
sudo sysctl -p
```

## 五、Nginx 反向代理（建议）

### 5.1 配置

```nginx
upstream campus_backend {
    server 127.0.0.1:8080;
    keepalive 64;
}

server {
    listen 80;
    server_name your-domain.com;

    # 上传文件大小限制
    client_max_body_size 10M;

    # 静态资源（前端 dist）
    location / {
        root /opt/campus/web;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://campus_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Connection "";
    }

    # WebSocket 群聊（关键：必须升级协议）
    location /ws/ {
        proxy_pass http://campus_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;    # 长连接超时设长
    }

    # 上传的图片
    location /uploads/ {
        proxy_pass http://campus_backend;
    }
}
```

> **WebSocket 段必须配 `Upgrade` / `Connection` 头**，否则群聊连不上。

### 5.2 HTTPS（微信要求）

微信小程序**强制要求 HTTPS**，且域名需备案。用 certbot 免费证书：

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## 七、扩展到 5000 在线的路径

当业务增长到需要扩容时，按顺序做：

### 第一步：数据库分离

```
应用服务器 4C4G  →  数据库服务器 4C8G（独立）
```

收益：应用和数据库不再抢内存，各自可独立扩容。

### 第二步：加 Redis

```yaml
# pom.xml 加依赖
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

**必须加缓存的内容**：
- 店铺列表（变化少、查询频繁）
- 学校列表
- 用户会话
- 超管看板统计结果

### 第三步：WebSocket 改 Redis 广播

**当前实现的限制**：

```java
// CircleWebSocketManager.java
private final Map<Long, Map<Long, WebSocketSession>> rooms = new ConcurrentHashMap<>();
```

这是**内存 Map，只对单机有效**。部署两台应用后，A 机发的消息 B 机用户收不到。

**改造方案**：用 Redis 发布订阅

```
用户A（应用1）→ 发消息 → Redis publish
                              ↓
                    ┌─────────┴─────────┐
              应用1 subscribe      应用2 subscribe
                    ↓                   ↓
              推给应用1用户        推给应用2用户
```

### 第四步：应用多实例 + 负载均衡

```
Nginx → 应用1 (4C8G)
      → 应用2 (4C8G)
```

**前提**：第三步必须先做，否则 WebSocket 会出问题。

## 九、监控建议

4C4G 是紧配置，**必须上监控**，否则出问题只能靠猜。

| 监控项 | 阈值 | 工具 |
|---|---|---|
| CPU 使用率 | > 80% 告警 | 云监控 |
| 内存使用率 | > 85% 告警 | 云监控 |
| 磁盘使用率 | > 80% 告警 | 云监控 |
| JVM 堆使用 | > 85% 告警 | Spring Boot Actuator |
| 数据库连接数 | > 20 告警 | MySQL 监控 |
| 接口响应时间 | > 1s 告警 | 日志分析 |

**最省事的方案**：接入腾讯云自带监控，配好告警短信即可。
