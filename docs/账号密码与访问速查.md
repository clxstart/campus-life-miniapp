### 为什么数据库里查不到密码

`admin_user.password_hash` 存的是 **BCrypt 哈希**，单向不可逆：

`admin_user.password_hash` 示例格式：`$2a$10$...`（仓库不保存可用哈希）。

历史上部分供应商账号共用过演示哈希，对应一个很弱的公开密码；该哈希已列入生产启动拦截名单。生产环境应由商家入驻审核生成账号，并立即改密。

`admin` 与 `neimenggu` 只会在本地显式设置 `@ALLOW_DEMO_SEED=YES` 后由种子脚本创建；默认执行不会插入任何账号。生产清除步骤见 `docs/部署与上线指南.md`。

### 商家账号是怎么建的

走「商家入驻申请 → 管理端审核通过」，后端自动建账号（`MerchantService.approve`）：

- 用户名 = `m` + 手机号后 8 位（重名自动加后缀）
- **初始密码 = 服务端随机生成的一次性密码（12 位），账号首次登录必须先改密**
- 审核接口返回 `initialPassword`，管理端弹窗给运营看

所以新增商家不用手动插库，审核完就有账号了。

## 三、端口与服务

| 服务 | 端口 | 启动方式 | 地址 |
|---|---|---|---|
| 后端 API | `8080` | `cd backend && mvn spring-boot:run` | http://127.0.0.1:8080/api |
| 管理端 / 商家端 web | `5180` | `cd web && npm run dev` | http://127.0.0.1:5180 |
| 小程序自动化端口 | `9420` | 开发者工具 `cli.bat auto --auto-port 9420` | — |

管理端 dev server 会把 `/api`、`/uploads`、`/ws` 代理到 `127.0.0.1:8080`，所以浏览器里访问 5180 即可，不用处理跨域。

| 端 | 入口 |
|---|---|

| 管理端首页 | http://localhost:5180/#/dashboard |
| 商家端首页 | http://localhost:5180/#/merchant |
| 商家入驻申请（免登录） | http://localhost:5180/#/merchant/apply |
| 外卖管理 | http://localhost:5180/#/shops |

| 商家入驻审核 | http://localhost:5180/#/merchant-audit |
| **骑手端首页** | http://localhost:5180/#/rider |

> 要改回 IPv4，在 `web/vite.config.js` 的 `server` 里加 `host: '127.0.0.1'`。

### 骑手端 vs 管理端「骑手管理」不是一回事

| | 骑手端 `/#/rider` | 管理端 `/#/riders` |
|---|---|---|
| 谁用 | 骑手自己（`role=rider`） | 管理员（`super`/`school`） |
| 干什么 | 抢单、标记取货、标记送达、查配送记录 | 新建骑手账号、启用/禁用、重置密码 |
| 接口 | `/api/rider/**`（`RiderInterceptor` 只认 rider token） | `/api/admin/riders`（`AdminInterceptor` 只认 super/school） |
| 交叉访问 | 骑手调 `/admin/**` → 403 | 管理员调 `/rider/**` → 403 |

## 四、怎么改密码

### 方式一：管理端界面（推荐）

`admin` 登录 → 管理员页 → 新建/改密，后端走 `AdminAuthController` + `AdminAuthService.encode()`，自动 BCrypt。

### 方式二：直接改库（应急）

BCrypt 哈希必须先生成再写入，不能手写明文：

```bash
# 在项目里生成哈希（bcryptjs 已在 tools/rec 装好）
cd tools/rec
node -e "console.log(require('bcryptjs').hashSync('你要的新密码',10))"
```

```sql
UPDATE admin_user SET password_hash='<上一步输出的哈希>' WHERE username='merchant01';
```

> 注意：每次 `encode()` 结果都不同（自带随机盐），但都能校验通过，这是正常的。

## 五、常见问题

**Q：登录提示账号或密码错误，但账号明明存在？**
A：先确认 `status=1`（启用），再按现场交付的密码或重置流程处理。仓库不再提供可直接使用的默认密码。

**Q：数据库连不上？**
A：`netstat -ano | findstr :3306` 看 MySQL 起没起。起不来的话先看 `D:\mysql` 下的服务状态。

**Q：后端 8080 起着，但 web 端接口全 404？**
A：确认 web dev server 用的是 5180（`web/vite.config.js` 里写死），别开了别的端口。

**Q：生产要怎么配？**
A：见 [`docs/部署与上线指南.md`](./部署与上线指南.md)。核心是 `--spring.profiles.active=prod` + 全套环境变量，`DB_USERNAME` 换成 `campus_user`，`CAMPUS_JWT_SECRET` 换随机串，`CAMPUS_WX_APPID` 必须配真值（否则启动失败）；开发登录只在显式设置 `CAMPUS_DEV_LOGIN_ENABLED=true` 且非生产 profile 时可用。
