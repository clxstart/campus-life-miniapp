## 一、这是什么

一个**面向高校的多校 SaaS 校园生活平台**，一套代码服务多所学校，每所学校的数据互相隔离。

### 三端结构

| 端 | 技术 | 规模 | 给谁用 |
|---|---|---|---|
| 微信小程序 | 原生 WXML/WXSS/JS（未用框架） | 37 个页面 | 学生 |
| Web 管理端 | Vue 3 + Vite + Tailwind | 19 个页面 | 平台超管 / 校级管理员 / 商家 / 骑手 |
| 后端 | Spring Boot 3.2.5 + MyBatis-Plus 3.5.6 | 26 控制器 / 211 接口 | 为上面两端提供 API |
| 数据库 | MySQL 8 | 51 张表 | — |

### 一句话概括

学生用小程序点外卖、逛二手、发帖、看课表、养宠物；运营用管理端管内容、审核商家、看订单、配活动。

## 五、数据流（三条主链路）

### 5.1 普通读请求

```
小程序页面
  → utils/api/xxx.js 的某个函数
  → core.request()
      ├─ 有 token 或不需要身份 → 直接发
      └─ 需要身份但没 token → 先等登录（最多 2.5 秒）
  → 后端 Controller → Service → Mapper → MySQL
  → 返回 {code:0,data}
      ├─ 成功 → 页面渲染
      └─ 网络失败 → 本地 mock 兜底（标记 offline）
      └─ 服务端报错 → 原样抛出（不兜底）
```

**关键规则**：断网才兜底，服务端报错必须抛出。否则用户会把假数据当真。

### 5.2 写请求

```
小程序页面
  → core.request(POST/PUT/DELETE)
  → AuthInterceptor 校验 token（缺失 → 401）
  → Controller 用 CurrentUser 取真实身份（忽略客户端传的 userId）
  → Service 业务校验 → 写库
  → 返回结果
```

**关键规则**：身份以 token 为准，客户端传的 `userId` 不可信。

### 5.3 群聊（WebSocket）

```
小程序进入圈子群聊
  → app.connectCircleChat(circleId)
  → ws://host/ws/circle?token=JWT&circleId=N
  → 服务端校验 token + 圈子状态 + 成员关系
  → 通过后：页面订阅消息，服务端广播新消息
  → 断线自动重连（最多 5 次），带心跳（25 秒）
```

## 六、多校隔离怎么做的

这是本项目最关键的设计，也是最容易出 bug 的地方。

### 6.1 三层隔离

| 层 | 机制 |
|---|---|
| 数据层 | 主要业务表都有 `school_id` 字段（帖子/商品/店铺/活动/圈子/兼职/用户…） |
| 接口层 | 列表接口支持 `schoolId` 参数；`effectiveSchool(req, schoolId)` 决定看哪所 |
| 权限层 | 校管（role=school）的 token 里带 `schoolId`，**强制只能看本校**，传别校返回 403 |

### 6.2 超管 vs 校管

| 身份 | 列表接口行为 |
|---|---|
| 超管（super） | 前端选了学校就按校筛；不选看全部 |
| 校管（school） | 固定本校，前端传值被忽略（防越权） |

### 6.3 已知的历史坑（已修）

| 坑 | 现象 | 修复 |
|---|---|---|
| 学期按学校**名字**匹配 | 学校改名后学生课表全报错 | 改成按 `school_id` 匹配（2026-10-26） |
| 管理端 35 个接口只认 token 里的学校 | 超管无法切校看数据 | 加 `effectiveSchool` 支持前端传 schoolId |
| 部分更新丢弃影响行数 | 编辑不存在的数据返回「成功」 | 改为检查 `!= 1` 抛错 |

## 七、内容审核机制

> ⚠️ **重要更正**：早前版本的项目说明里写过「没有接入微信内容安全」，**这是错的**。
> 代码里 `msg_sec_check`（文本）和 `img_sec_check`（图片）都真实实现了。
> 之所以运行时看起来像没接入，是因为 `campus.wx.appid` 为空时代码会**静默放行**。

### 7.1 两道防线

| 防线 | 时机 | 实现 | 代码位置 |
|---|---|---|---|
| 文本审核 | 发布时同步 | ① 本地敏感词引擎（当前 ToolGood.Words，DFA 匹配）② 微信 `msg_sec_check` | `AuditService.java:189` |
| 图片审核 | 发布后异步 | 微信 `img_sec_check`（走异步队列） | `AuditService.java:323` |

### 7.2 为什么现在「看起来只有本地词库」

`AuditService` 里有两个静默放行的分支：

```java
// 分支一：没配微信 AppID → 直接判定通过
if (appid == null || appid.isBlank() || secret == null || secret.isBlank()) {
    return AuditResult.passed();
}

// 分支二：拿不到真实 openid（开发登录的 openid 形如 dev-1）→ 跳过微信审核
if (openid == null || openid.isBlank() || openid.startsWith("dev-")) {
    log.warn("WeChat text moderation skipped ...");
    return AuditResult.passed();
}
```

当前 `application-dev.yml` 里 `appid: ''`，所以**两条分支必然命中**，微信审核一次都没真正调用过。

**这意味着**：
- 开发环境测到的拦截效果 = 只有本地词库的效果
- 配了真实 AppID 后，微信那层才会真正生效（但开发登录的 `dev-` openid 仍会跳过，需要真实微信登录）

### 7.3 审核覆盖面（实测代码得出）

| 内容类型 | 文本审核 | 图片审核 |
|---|---|---|
| 帖子 | ✅ | ✅（仅 `post.image` 单图） |
| 评论 | ✅ | — |
| 二手商品 | ✅ | ✅ |
| 兼职 | ✅ | — |
| 私聊消息 | ✅ | ❌ |
| 后台建圈子 | ✅ | — |
| **圈子群聊**（WebSocket） | ❌ 未覆盖 | ❌ |
| **昵称/头像修改** | ❌ | ❌ |
| **AI 聊天输入** | ❌ | — |
| **活动报名材料** | ❌ | ❌ 未覆盖 |

### 7.4 审核结果

| 结果 | 后续 |
|---|---|
| 命中违规词 | **直接拒绝发布**（返回 4001），同时写 `audit_log` |
| 微信判定 risky | 拒绝 |
| 微信判定 review | 入库但不可见（`audit_status=reviewing`），等人工 |
| 通过 | 正常可见 |

### 7.5 已知缺口

| 缺口 | 影响 |
|---|---|
| 被词库拦掉的内容只进 `audit_log`，不进审核列表 | 管理端能看到「拦截 38 条」的数字，但点不开看是什么 |
| 后加的词不回溯 | 已发布内容不会被重新审核 |
| 群聊/昵称/头像/报名材料无审核 | 是真实的盲区，UGC 风险点 |

## 八、支付链路现状

```
下单 → 订单(待支付) → 支付
                        ├─ wxpay.enabled=false → 模拟支付，直接标记已支付
                        └─ wxpay.enabled=true  → 调微信统一下单，返回 prepay 参数
                                                  → 用户支付 → 微信回调 /api/pay/notify
                                                  → 验签 + 校验金额 → 标记已支付
```

**当前状态：模拟支付。** 真实支付需要 5 个前置条件，详见 `docs/真实支付接入指南-五条件.md`。

退款走官方 APIv3 SDK，与支付共用同一套密钥（历史上曾有两套配置导致「能付不能退」，已合并）。

## 九、关键设计约定（改代码前必读）

| 约定 | 说明 |
|---|---|
| 统一响应体 | `{code, msg, data}`，`code=0` 为成功 |
| 身份来源 | 永远用 token，不用客户端传的 userId |
| 兜底规则 | 断网才用本地数据；服务端报错必须抛 |
| 离线写操作 | 不假装成功（报名/支付/发布都不兜底） |
| 状态机 | 订单状态用 `OrderStatus.canTransit` 校验，不要手写判断 |
| 多校 | 新表若有学校维度，必须加 `school_id` |
| 配置文件 | 不往 `application.yml` 写密钥，放 `application-{dev,prod}.yml` |
| 页面样式 | 新页面优先用 `styles/theme.wxss` 的变量，别写死色值 |

## 十、启动与验证

### 启动

```bash
# 1. 数据库（执行一次）
mysql -u root -p campus_life < backend/src/main/resources/db/schema.sql
mysql -u root -p campus_life < backend/src/main/resources/db/module-activity-enroll.sql
# 其他 module-*.sql 按需执行

# 2. 后端
cd backend && mvn spring-boot:run

# 3. 管理端
cd web && pnpm install && pnpm dev

# 4. 小程序
微信开发者工具导入项目根目录，AppID 用 touristappid
```

### 验证是否正常

```bash
# 后端活着
curl -s http://127.0.0.1:8080/api/schools | head -c 100

# 管理端登录
curl -s -X POST http://127.0.0.1:8080/api/admin/login \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | head -c 120
```
